# Qwen3-30B 原文整合优化与本机四卡验证

本轮范围：使用本机 GPU 0–3，优化已有视觉打标的语义整合。模型为 `/private/ckpts/Qwen3-30B-A3B-Instruct-2507`。GPU 4–7 的训练、node17/node8 的全量视觉打标独立运行。本轮没有重新识别音视频，也没有覆盖训练标签或缓存。

[本轮73段有声复核页面](http://localhost:8876/listen_benchmark_review/semantic_qwen30b_20261030/)：主试验65段＋历史回归8段。展示本轮v4结果及未通过提案，未实施后来讨论的“局部整合／失败回退”新流程。

## 输入与规则

对照输入是原生视频 8 fps＋GLARE 高召回点头的既有结果：此前复核的 15 段，以及从 node17 已完成来源中抽取的 50 段。后者每个来源抽一段，seed=20261030，仅读取完成记录和被选中的结果文件，不扫描全量媒体。另用 8 个历史回归样本检查 S1400、重复 yeah/okay 和音频字段保护。

- 直接输入：保留所有观测；CPU 轻量输入：仅折叠时间、内容等条件完全相同的重复观测，仍保存全部来源。
- 15 段 365→359 条，50 段 987→964 条。这是精确去重，不是相近时间或语义合并。
- 模型只能选择已有原文及允许的可见描述前缀。代码取得原文子串，保留主语、时态和句式，仅规范句末标点。
- 同一事件选信息最完整的一条；如果没有任何一条覆盖其他条目的全部动作，则分别保留，允许部分措辞重叠。
- 不生成新时间；最终事件沿用被保留来源的区间。不用长区间把互不重叠的短动作串成一次。
- 点头、头部方向、手、眼、嘴等遗漏报警继续执行。报警是保守的文本检查，不是新增行为分类，也不是视频真值。
- 本轮语义整理只修改视觉指导描述，音频事件及相关字段必须与输入一致。原始观测、冲突、失败提案均保存。

## 代码入口与实验版本

| 版本 | 实现 | 用途 |
| --- | --- | --- |
| 原方案 A | `src/listen_benchmark/semantic_prompt.py` | 保持原有实现，作为基线 |
| 分组 v1 | `semantic_group_prompt.py` | 缩短输出，但自由成员列表容易漏来源；实验保留 |
| 固定归属 v2 | `semantic_fixed_group_prompt.py` | 固定全部来源顺序，独立填写保留列表和归属表；用于 eager/graph 测速 |
| 显式约束 v3 | `semantic_constrained_group_prompt.py` | 将代码允许的目标提前提供给模型；仍存在两张表引用不一致 |
| 单归属表 v4 | `semantic_assignment_prompt.py` | 只输出完整归属表，自指行即保留项，避免重复填写保留列表 |

v4 入口：[`scripts/run_listener_semantic_assignments.py`](../scripts/run_listener_semantic_assignments.py)。每条来源固定输出 `source_id / target_id / quote_index / reason`：指向自己表示保留；指向另一条表示由那条完整原文代表。被指向的条目必须指向自己，链式引用、环、缺失来源、非法合并继续拒绝。代码从该表投影出保留列表，没有修补或改选模型的语义决策。

[`scripts/audit_listener_semantic_prompt.py`](../scripts/audit_listener_semantic_prompt.py) 按白名单选择对应实现，复算提案、最终原文、时间、音频字段和来源。每次运行冻结实际代码、模型元信息、prompt 和输入指纹；旧响应不能冒用为新协议结果。

## 加速配置与适用范围

单卡一份 BF16 模型，TP=1，batch/max_num_seqs=64，`max_num_batched_tokens=32768`，`max_model_len=32768`，显存比例 0.8，prefix caching＋chunked prefill。保留原来的动态提案预算（8192～24000 token）、审核预算 3072 token、最多三次尝试，temperature=0。

新增可选 `--decode-graph`：`FULL_DECODE_ONLY`、编译 mode=0、capture sizes=1/2/4/8/16/32/64。不通过减少输出预算换速度，不截断长输入。CUDA Graph 的额外显存必须看实际启动日志，本轮多数进程约 0.12 GiB，也出现一个进程报告 22.65 GiB，不能把前者当成稳定上限。

本轮是并行对照实验，四卡分别跑不同试验，并非已经验收的全量四卡调度器。后续多卡可各放一份模型、按 token 负载分片；仍须保持样本和来源互斥。这里没有 T5 编码器，不能直接复用视频生成训练的 T5 缓存。

## 结果与使用边界

最终数字见 [四卡实验报告](../experiments/listen_qwen30b_assignments_20261030/README.md) 和可复算的 `comparison.json`。通过数是“代码校验＋模型自检”的结果，不是人工准确率；失败样本保留输入，不把它们计为删除掉的重复事件。必须仅在通过样本上统计输入输出事件的减少量。

**尚未达到全量自动替换条件。** 抽查已通过结果仍发现 `showing continued engagement` 和 `as if beginning to speak` 等表述残留；当前原方案的前缀校验并没有穷举所有推演表达，模型自检也会漏检。S1400 在 v4 中继续因将不相交来源归入同一长事件被拒绝。不能把“通过现有校验”解释为“推演全部去净、所有动作都准确”。本轮保留原方案规则用于公平比较，没有放宽门槛或强制放行这些样本。

v2 的同输入单次 eager/graph 对照：15 段 515.4→168.9 秒，50 段 622.6→349.7 秒，包含加载和重试。前者均通过 1 段；后者通过 20/19 段。输出 token 数接近，但结果有差异，且共享主机上存在其他任务，所以这是实测吞吐证据，不能当成保证的纯计算加速倍数或质量提升。

## 运行和验收

从项目根目录运行；每次改协议或输入必须换输出目录。下面命令只占指定的一张空卡，不会停止已有进程：

```bash
CUDA_VISIBLE_DEVICES=0 \
LD_PRELOAD=/private/software/conda/envs/vllm/lib/libstdc++.so.6 \
OMP_NUM_THREADS=4 OPENBLAS_NUM_THREADS=1 TOKENIZERS_PARALLELISM=false \
/private/software/conda/envs/vllm/bin/python scripts/run_listener_semantic_assignments.py \
  --inputs experiments/listen_qwen30b_assignments_20261030/all65.jsonl \
  --output experiments/listen_qwen30b_assignments_followup/runs/all65 \
  --model /private/ckpts/Qwen3-30B-A3B-Instruct-2507 \
  --batch 64 --memory 0.8 --max-batched-tokens 32768 --attempts 3 --decode-graph

CUDA_VISIBLE_DEVICES='' \
/private/software/conda/envs/vllm/bin/python scripts/audit_listener_semantic_prompt.py \
  --inputs experiments/listen_qwen30b_assignments_20261030/all65.jsonl \
  --run experiments/listen_qwen30b_assignments_followup/runs/all65
```

`results/` 为通过项，`prompts/` 为对应指导文本，`attempts/` 保存每轮模型原响应，`summary.json` 保留所有失败原因。`audit.json` 的 `partial` 表示仅部分样本发布，不能当成全量通过；`COMPLETE.json` 只在全部通过时生成。

CPU 测试使用项目可用的 Python＋pytest；vLLM 环境本身没有安装 pytest：

```bash
PYTHONPATH=src python -m pytest -q \
  tests/test_semantic_prompt.py tests/test_semantic_prompt_cache.py \
  tests/test_native8_semantic_inputs.py tests/test_semantic_group_prompt.py \
  tests/test_semantic_fixed_group_prompt.py tests/test_semantic_constrained_group_prompt.py \
  tests/test_semantic_assignment_prompt.py
```

本轮 59 项通过，涵盖来源完整性、原文截取、禁止跨独立事件合并、动作遗漏、错误引用、缓存身份和实验协议分支。测试通过不代表所有模型提案都正确，实际发布仍逐条执行校验。
