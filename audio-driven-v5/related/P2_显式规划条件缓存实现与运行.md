# 显式规划条件缓存：实现与运行

2026-10-27。本入口准备A1/A2所需的冻结条件：逐样本Gemma embedding与“原输入＋同一逐样本指导”的Qwen hidden。不启动训练，不训练Qwen，不改写已验收数据或旧缓存。

入口：[scripts/p2_plan_cache.py](../scripts/p2_plan_cache.py)。实现：[src/p2_plan_cache](../src/p2_plan_cache/)。方案：[首版实验约束](P2_显式回应规划双通路实验方案草案.md)。

## 输入与格式

使用`experiments/p2_train50h_postprocessed_reselected_20261027/config.json`，29,975段，512×512。计划从该目录`integrated_labels.jsonl`流式读取，保留后处理后的有效区间。准备时核对验收文件、成员、split、几何、标签和静音配方，不读取listener目标音视频进行条件提取。

由`p2_plan_cache.formatting.render_verbatim`沿用此前格式，固定Gemma前言、INTRO、时间表示、事件顺序、空行、Visual response / Audio response / vocal content均与此前英文指导评测一致。Qwen第二遍追加的完整文本与Gemma实际文本逐字一致，保存同一prompt哈希。用户最新确认保留原始打标内容，包括单字中文；模板保持英文，原描述/发声词不翻译、不补静音、不额外去重。原本全英文的样本文本与此前 formatter 逐字一致。

## 两种缓存

| part | 内容 | 消费方 |
|---|---|---|
| text | 正向video/audio文本embedding、有效mask、实际prompt、token计数 | A1/A2共享 |
| input_plan | 第8/18/28/35层全序列hidden、hidden有效mask、计划token范围/ID、位置、原输出layout | A2 |

Qwen使用现有listening多模态prefix，随后追加完整指导文本和原生`im_end`。只处理单条无padding的prefix；计划正文不含模型控制token；文本位置从prefix最大多模态位置继续。重新forward整段，不把旧输入hidden当作计划hidden；Connector读取输入及所有计划token。计划mask标记正文，终止token单独计数。

Qwen必须为eval且所有参数冻结。超过Gemma的1024/2048/4096/8192档位上限，或超过Qwen配置/模型上下文上限时显式失败，不截断。输出检查形状、mask、有限数值及文本身份。Gemma输入token mask与LTX文本Connector输出mask分开理解：原生learned registers可使输出位置全部有效，不能要求其有效数等于原始文本token数。

negative CFG文本不在每条新缓存里重复保存，读取时复用原固定文本缓存的negative，避免复制29,975份。原视频、后处理音频、事件与teacher均不会被缓存命令重建；teacher不读取。

三机联合入口现已补齐：[节点映射、统一启动与状态汇总](P2_显式规划缓存三机联合运行.md)。

## 命令

在项目根目录，使用现有依赖环境。以下命令是运行说明；本次新50h三机共享缓存已完成，实时状态见[本次运行](../experiments/p2_plan_cache_train50h_verbatim_20261027/README.md)。

```bash
P2_PYTHON=/private/liqi_workspace/project_code/Omni-LTX-stage2/.venv/bin/python
P2_DATA=experiments/p2_train50h_postprocessed_reselected_20261027/config.json
P2_WORK=experiments/p2_plan_conditions_train50h_verbatim_20261027

# CPU准备：仅选定29,975段新50h，原文保留。
"$P2_PYTHON" scripts/p2_plan_cache.py prepare \
  --config "$P2_DATA" --work "$P2_WORK"

# Gemma；每个进程只加载一个冻结编码器。
"$P2_PYTHON" scripts/p2_plan_cache.py cache-text \
  --work "$P2_WORK" --device cuda:0

# Qwen第二遍条件编码；与Gemma分开运行，分别管理GPU。
"$P2_PYTHON" scripts/p2_plan_cache.py cache-input-plan \
  --work "$P2_WORK" --device cuda:0

# 检查所有已准备样本的两类载荷及文本配对，不加载预训练模型。
"$P2_PYTHON" scripts/p2_plan_cache.py verify --work "$P2_WORK"
```

小规模检查可在`prepare`传入重复的`--sample-id`，生成明确的工程子集协议；不会修改原训练集名单。正式训练必须使用全量协议，不能将工程子集当作完整验收。

两个cache命令和verify支持`--shards N --shard-index I`，按排序后的ID确定性分片。三机24进程可使用同一共享work目录和互不重复的0–23索引；各进程选择自己的本地GPU。CLI不自动占卡或启动远端进程。空分片明确报告`samples=0`，不是全量完成标记。

每个part/sample有文件锁，保存payload后原子写完成标记。中断后的未完成条目可以重做；已经完成的条目核验后复用，不重新加载模型。身份冲突、损坏、超长和占用锁记为失败，命令返回非零，不能把失败当成跳过成功。重跑不会自动覆盖损坏或另一版本的缓存，应检查后使用新的work版本。

## 目录与身份

- `prepare_identity.json`：准备参数及源文件身份；部分准备失败时也保留。
- `protocol.json`：只有所有选定样本通过准备才发布。
- `samples/<id>.json`：输入索引、实际指导文本、原文及逐事件来源。
- `cache/text/<id>/`、`cache/input_plan/<id>/`：payload与完成标记。
- `preparation_errors.json`：标注格式/控制token约束失败明细。
- `errors/<part>/<id>.json`：缓存失败诊断；历史诊断保留，以当前完成标记及本次report判断重跑结果。
- `reports/`：按part、分片和样本选择分别保存执行/核验结果。

身份覆盖实际文本、输入媒体hash、模型资产、tokenizer及模板、相关代码、层配置、上下文上限和软件版本。模型大权重沿用原项目size/mtime身份，小配置及tokenizer文件使用SHA256；这不宣称每次重算大权重全文件hash。每个任务入口检查源文件，逐样本不重复扫描1GB标注；Qwen实际提取前再校验对应speaker音频和首帧的媒体hash。
