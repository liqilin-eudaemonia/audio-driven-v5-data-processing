## 实际读取与监督

1. SQLite记录定位JSONL字节范围，每个数据worker独立打开只读连接和文件；不把69万条完整JSON载入每个进程，不在32个rank重复读取2GB清单做哈希。
2. 复用`listen_response_sft.load_example`验证统计行、caption、pair、人物角色、时间窗和裁框来源。
3. speaker音频取该pair原始时间窗，真实重采样到16kHz；**不应用listener的静音门控**。
4. listener首帧取最接近pair开始时刻的源PTS，按最终修正版裁框输出512×512 RGB；processor再按`max_pixels=50176`缩放。历史caption使用不同标注框时，继续保留`annotation_crop_differs`追溯字段。
5. 原文描述只放在assistant目标；已记录的开头`Assistant:`清理规则沿用。不输入listener音频、未来视频、speaker转写或目标描述作为user条件。
6. 沿用现有system/user规划prompt，见[data.py](../src/p2_planning_sft/data.py)。只监督assistant描述和`<|im_end|>`；前缀、多模态条件和padding均为`-100`。超长、空目标、嵌入聊天特殊token直接报错，不静默截断或丢样本。

这是文本SFT，不计算AV/Event loss，也不需要重新生成LTX/Gemma latent缓存。

## 当前默认参数

沿用已有3B LoRA设置：Thinker语言层q/k/v/o及gate/up/down投影，rank32、alpha64、dropout0；感知编码器、原语言模型和lm_head冻结。BF16、SDPA、TF32、fused AdamW，LR1e-4，warmup3%、cosine、weight decay0.01。

四机32卡，每卡batch8、累积1，global batch256；1 epoch约2,697步。每卡4个持久数据worker，CPU线程受限；沿用时长分组、动态音频padding、仅监督位置FP32 loss及跨卡有效token归一化。关闭梯度重算的设置来自旧数据训练，新数据已通过32卡首批训练；完整周期吞吐以运行日志为准。

每500步保存权重，训练结束另存最终adapter。按用户最新要求，`training.evaluate=false`：关闭周期、暂停退出及训练结束后的所有dev评估，不创建dev评估DataLoader。dev清单及固定诊断子集记录仍保留用于划分隔离与未来独立评测，不读取其媒体参与本次训练。完成记录写入`validation_enabled=false`、`validation=null`，不伪造验证分数。输出目录：`experiments/p2_planning_sft_filtered_3b_32gpu_20261102/`。正式run已创建，首批LoRA梯度有限且非零、冻结参数无梯度；周期权重按500步保存。运行记录见[训练目录](../experiments/p2_planning_sft_filtered_3b_32gpu_20261102/README.md)。

```bash

  --config configs/p2_planning_sft_filtered_3b_32gpu_20261102.json \

```

先在一张实际空闲GPU做有界试训，使用独立输出目录（8条train，不执行dev评估；不构成正式训练）：

```bash
CUDA_VISIBLE_DEVICES=<空闲卡号> OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=1 TOKENIZERS_PARALLELISM=false \
/private/liqi_workspace/project_code/Omni-LTX-stage2/.venv/bin/python scripts/p2_planning_sft.py \
  --config configs/p2_planning_sft_filtered_3b_32gpu_20261102.json \
  --smoke --stop-after 1 \
  --output experiments/p2_planning_sft_filtered_20261102_gpu_smoke
```

完成梯度、保存和adapter重载检查后，再进行四机训练：在上面的集群命令末尾加`--launch`。节点地址沿用配置，应先核对可用资源；启动器只检查空闲显存，不会停止现有作业，不应将“显存足够”当作四机空闲。每个节点须能访问同一数据／代码／模型路径。

本次新训练开始后，才可用该输出目录自身的`checkpoint-*`加`--resume`续跑；训练配置、数据、代码和world size必须一致。

源清单发生变化时必须重新生成封存记录并改配置，不能覆盖旧记录：

```bash
/private/liqi_workspace/project_code/Omni-LTX-stage2/.venv/bin/python scripts/prepare_planning_reference_data.py \
  --data experiments/listen_j_train_dev_response_prefixfix_20261102/current \
  --output <新的封存记录路径.json>
```

准备脚本默认要求本次确认的690337／5238条；数据范围改变时，应同步修改并复核预期计数，不能为了通过检查直接绕过限制。
