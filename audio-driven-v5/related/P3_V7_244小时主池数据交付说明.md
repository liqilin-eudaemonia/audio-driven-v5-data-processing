## 1. 数据用途与当前交付状态

这份数据用于倾听阶段音视频生成：以当前 speaker 的语音为条件，生成当前 listener 的面部视频及其自身声音，包括沉默、简短附和和笑声。

本次交付范围为训练集自动筛选通过的主池：**126,748 个片段，合计 244.1156 小时**。时长按筛选保留的源时间区间统计，包含区间内停顿；不包含开发集、测试集、开头反馈备用池及待复核数据。它不是原始数据集的全部时长。

**当前产物是“筛选后的片段清单 + 已归一化的参与者整轨音频 + 原始视频引用”，尚未导出逐片段裁剪视频，也尚未全部导出逐片段 WAV。只拿到 JSONL 文件不能直接播放或训练。**

| 项目 | 状态 |
|---|---|
| 原始来源配对、角色判断与时间切分 | 已完成 |
| 每段 listener 固定裁剪框计算与质量筛选 | 已完成 |
| speaker/listener 整轨音量归一化 | 已生成实际 WAV 文件 |
| 音频事件、串音和噪声筛查 | 已完成自动分流，并应用已记录的人工反馈 |
| 按片段裁剪视频并缩放到 512×512 | 尚未批量导出 |
| 按片段截取归一化音频 | 尚未全部导出 |
| 模型帧数适配、特征缓存、正式训练 | 尚未完成 |

`keep` 表示通过当前筛选规则的候选，不代表每段均经人工试听，也不代表已经得到无噪声的成品。清单中的 `training_admitted: false` 和 `frame_adaptation_required: true` 保留了这一阶段状态。

## 3. 已采用的处理标准

### 话轮与角色

speaker/listener 按话轮动态分配，不固定对应参与者 A/B 或左右声道。同一片段内角色固定；listener 接管发言后，下一个话轮交换条件音频与生成目标。简短附和、笑声等 backchannel 通常不视为接管。

候选片段长度为 **2–10 秒**。长话轮优先在句末、停顿或词间隙切分，避免切断有时间标注的词。词间隙是允许的回退位置，因此不能把每段都理解为完整语法句。最终主池是经过几何和音质筛选的子集，不保证连续覆盖原会话。

主池排除片段开头 0.5 秒内检测到的 listener 活动；该类候选另列 `onset_reserve`，不包含在本次 244.12h 中。speaker 结尾范围内的简短反馈可保留；实质插话按规则排除。判断依赖原始转写、VAD 与自动规则，可能存在误判。

### 画面

每个片段记录一个固定的 listener 方形裁剪框；原始像素边长至少 **448**，预期输出尺寸 **512×512**。方向异常（包括原视频 90° 旋转）、方向不确定以及不符合画面质量规则的数据被过滤。

这一步已经完成的是裁框计算和筛选。清单里的 `width: 512`、`height: 512`、`fps: 25` 是预期导出规格，不表示已经存在相应 MP4。

### 音频

对每位参与者的整条原始音轨测量响度，施加固定增益与峰值限制，执行输出响度、峰值和长度检查。归一化目标为 **−18 LUFS**，峰值限制目标为 **−1 dB**；静音或语音不足的音轨按策略处理，不保证每个短片段都恰好达到同一响度。

输出 WAV 为 **48 kHz、单声道**；speaker 与 listener 是两个独立文件。整轨内保留自然强弱变化，避免逐个微弱回应分别强行拉高音量。没有额外执行复杂降噪或声源分离。

音质筛查使用 AST（`MIT/ast-finetuned-audioset-10-10-0.4593`）、PANNs Cnn14，以及双轨相关性、频谱和瞬态等声学规则。目标是排除明显噪声和串音，同时保留正常倾听回应；不能保证彻底消除漏检。

## 4. 如何读取一条清单记录

JSONL 每行一个 JSON 对象。关键字段如下：

| 字段 | 含义 |
|---|---|
| `sample_id` | 片段唯一标识，建议用作导出文件名 |
| `pair`、`group_id`、`split` | 来源会话、隔离分组与数据划分 |
| `start`、`end`、`duration_s` | 源会话时间轴上的起止秒数及区间长度 |
| `speaker_id`、`listener_id` | 该片段的角色对应参与者 |
| `listener_crop.x/y/size` | 原始视频像素坐标：左上角与方形边长 |
| `sources.<role>.archive/member` | TAR 路径及视频成员名 |
| `normalized_audio.<role>.path` | 对应参与者的整轨归一化 WAV |
| `normalized_audio.<role>.sha256` | WAV 文件的 SHA256，迁移后可用于核验 |
| `normalized_audio.<role>.gain_db` | 归一化处理记录的增益 |
| `text` | 区间内 speaker 的转写内容，不是 listener 回复或动作描述 |
| `effective_decision`、`admission_pool` | 本次清单为 `keep`、`primary` |

**`start/end` 不是已经截取后的局部时间，也不是整段文件都应使用的标志。** 视频及两条归一化 WAV 都需截取同一个 `[start, end)` 区间。音频取样时按实际采样率换算起止样本；视频边界需处理帧量化并检查音画同步。

读取示例（只展示索引，不执行媒体导出）：

```python
import json

manifest = "/private/liqi_workspace/project_code/audio-driven-v5/data_corpora/seamless_listen_v7_full/manifests/train_keep_primary.jsonl"
with open(manifest, encoding="utf-8") as f:
    sample = json.loads(next(f))

print(sample["sample_id"], sample["start"], sample["end"])
print("listener 视频来源：", sample["sources"]["listener"])
print("原像素裁框：", sample["listener_crop"])
for role in ("speaker", "listener"):
    print(role, sample["normalized_audio"][role]["path"])
```

读取 TAR 时可按 `archive` 和 `member` 提取指定视频。`offset/byte_size` 是原 TAR 布局对应的定位信息；重新打包 TAR 后不能沿用旧偏移。

## 5. 在其他机器使用与后续导出

本清单目前使用本机绝对路径。在同一共享文件系统上使用时，可直接读取这些路径；迁移到其他机器时，需要按清单收集依赖，并重写 `sources.*.archive`、`normalized_audio.*.path` 及需要保留的证据路径。无需拷贝无关的待复核、淘汰数据或完整原始数据集。

若希望交付一份无需访问原始 TAR、拿到即可使用的逐片段数据集，还需要执行：

1. 按 `sources.listener` 读取原始视频，截取 `start/end`，应用 `listener_crop`，缩放到 512×512。
2. 从两条归一化 WAV 截取相同时间区间，分别保存 speaker 条件音频和 listener 目标音频。
3. 检查视频方向、尺寸、帧率、音画同步、两条音轨长度及解码完整性；不要重新逐片段做响度拉齐。
4. 写出引用导出文件的相对路径清单与校验值，保留 `sample_id`、来源信息和现有 split。

建议成品目录结构如下；**这是后续导出约定，不是当前已存在的文件结构**：

```text
dataset/
  README.md
  manifest.jsonl
  checksums.sha256
  samples/
    <sample_id>/
      listener.mp4
      speaker.wav
      listener.wav
```

若给 listener 视频封装音轨，应使用对应的 listener 归一化音频；speaker 条件音频仍单独提供。模型需要 `8k+1` 等帧数约束时，应另行适配并记录有效区间，不能直接截掉结尾正在说话的部分。当前清单没有为满足该约束再次裁短片段。
