## 2. 每份数据集内应读哪些文件

对新50h、300h七类、300h原文，以下位置均相对于各自数据集目录：

| 位置 | 内容／用途 |
|---|---|
| `manifests/observations.json` | 输入：配对speaker音频、listener首帧、时长、split、身份与媒体校验值 |
| `manifests/targets.json` | 目标：listener裁剪视频、原始listener音轨引用、时长与媒体校验值 |
| `sample_ids.txt` | 本子集冻结成员；缓存目录下还有其他样本，不能遍历缓存来决定训练成员 |
| `samples.csv`、`selection.json` | 原始人脸尺寸、事件统计、评分、来源和入选原因 |
| `integrated_labels.jsonl` | 当前整合原文及事件时间；300h原文版额外保留七类之外的原始视觉观察 |
| `labels/canonical/<sample_id>.json` | 七类弱标签；原文版中仅用于既有媒体缓存合同验证／对照，不代替开放标签 |
| `audio_postprocess/recipes/<sample_id>.json` | 虚拟静音配方、原音轨位置和哈希；包含官方时间支持与已确认的过滤处理 |
| `dataset.jsonl` | 逐样本标签／配方校验值、实际缓存路径和身份 |
| `dataset_contract.json`、`selection_policy.json` | 数据使用范围和筛选政策 |
| `validation.json`、`COMPLETE.json` | 验收结论与交付文件哈希；`export_complete.json`仅表示导出完成 |

300h原文版另有 `open_label_index.sqlite`，按sample_id定位原文；其 `prepared/` 是候选中间产物，不是训练成员清单。

全量版本的对应位置不同：输入／目标清单、canonical标签、配方位于 `view/` 下；后处理原文在 `integrated/*.jsonl`，逐样本处理记录在 `records/<sample_id>.json`，源索引在 `scope.sqlite`、`source_shards.json`。全量验收为 `audit.json`＋`COMPLETE.json`，不必寻找单个 `integrated_labels.jsonl`。

test48/test24使用各自manifest、`integrated_labels.jsonl`、`audio_postprocess/recipes/`、`media_references.json`及`media/`。其 `config.json` 是媒体导出配置，**不是训练配置**，不存在本次交付的训练latent／事件缓存。

## 3. 缓存实际保存在哪里

新50h和两份300h没有各复制一套音视频缓存。以下两个目录是实际存储根：

```text
原媒体与基础特征缓存 B：
/private/liqi_workspace/project_code/audio-driven-v5/experiments/p2_features_full_crop384_20261025/

全量后处理视图 F：
/private/liqi_workspace/project_code/audio-driven-v5/experiments/p2_full_audio_postprocess_crop384_20261026/view/
```

下表中的B和F指上面两个确切目录：

| 数据／缓存 | 实际位置 | 现在的用途 |
|---|---|---|
| 配对媒体裁片 | `B/media/<sample_id>/` | `speaker.wav`、`listener.wav`、`video.mp4`、`first_frame.png`；listener视频已按训练裁框导出 |
| 输入条件缓存 | `B/cache/input/<sample_id>/` | 沿用原输入条件；speaker音频没有被listener静音规则替换 |
| 文本缓存 | `B/cache/text/` | 沿用配置对应的原文本缓存；不是所有开放描述的新文本编码 |
| 原视频／原音频VAE缓存 | `B/cache/vae/<sample_id>/` | 保存基础AV缓存；视频继续复用，音频由下述overlay决定更新或复用 |
| **后处理音频缓存** | **`F/cache/audio_postprocess/<sample_id>/`** | 新音频latent及支持信息，或`reuse_base_audio=true`的复用记录 |
| **后处理七类事件缓存** | **`F/cache/events/<sample_id>/`** | 新50h与300h七类版使用；与过滤后的canonical标签匹配 |
| 后处理配方 | `F/audio_postprocess/recipes/<sample_id>.json` | 不保存清洗后WAV，用原音轨＋配方在内存恢复波形 |
| 后处理canonical | `F/labels/canonical/<sample_id>.json` | 全量七类弱标签，子集各自复制选中条目 |
| 旧事件缓存 | `B/cache/events/` | 静音前历史缓存，不能替代F中的更新事件缓存 |
| 旧Feature teacher | `B/cache/teacher/` | 历史缓存；静音后音频teacher未重算，当前后处理读取配置关闭Feature loss |

按样本保存的缓存条目通常包含 `payload.pt` 和 `complete.json`；身份与载荷校验由读取器执行。

新50h、300h七类目录中的链接实际为：

```text
cache/input             -> B/cache/input
cache/text              -> B/cache/text
cache/audio_postprocess -> F/cache/audio_postprocess
cache/events            -> F/cache/events
```

视频VAE通过配置 `data.audio_postprocess.base_output=B` 定位，不要求子集下有 `cache/vae` 链接。300h原文版只有前三个缓存链接，**没有把七类events作为本版开放监督目标**；七类引用在 `dataset.jsonl` 的 `seven_class_reference_cache` 中单独保存。

## 4. 音频物理文件与读取规则

全量693,997段音频发生更新，28,709段音频保持不变。两者都通过同一套后处理读取入口；读取器根据overlay决定替换音频latent或复用基础音频。不要根据是否有发声标签手动猜测使用哪套缓存。

没有新增处理后WAV，也没有复制视频缓存。`targets.json.target_audio`、`B/media/<id>/listener.wav`和test目录的`listener.wav`均是配方绑定的原音轨裁片；直接读它们得到的是原音频，不是按新规则静音后的波形。

读取清洗后波形：

```python
from p2_listen.contracts import read
from listen_audio_postprocess.recipes import read_listener_audio

recipe = read(dataset_root / "audio_postprocess/recipes" / f"{sample_id}.json")
waveform, sample_rate, metadata = read_listener_audio(recipe)
```

全量场景的`dataset_root`取F；训练子集和test场景取各自数据集根目录。运行Python示例时将项目`src`加入`PYTHONPATH`。

新50h／300h七类读取配置后，使用 [training_data.load_training_sample](../src/p2_listen/training_data.py)，自动转入 [overlay.load_training_sample](../src/listen_audio_postprocess/overlay.py)，组合基础视频、后处理音频和更新后的七类事件缓存。

300h原文版使用 [open_subset_reader.py](../src/listen_benchmark/open_subset_reader.py)：

```python
from listen_benchmark.open_subset_reader import load_open_label, load_open_training_sample

label = load_open_label(dataset_root, sample_id)  # 只读原文和时间
x, layout, _, av_target, label = load_open_training_sample(
    dataset_root, observation, target, device="cpu"
)  # 最后一个返回值是开放事件字典
```

原文版的数据准备和读取已完成；现有固定七类监督头尚未改造为消费全部原文的训练目标，不能把其七类引用缓存当作开放标签训练结果。
