# 固定 J v1：四机 CPU 分片、续跑与训练共存试验

用户已授权按 node8/node4 各 1 worker、2 CPU 线程、CPU 音质、缓存优先的方案试跑 5～10 分钟；稳定后加入 node17/node12，持续慢约 5% 时降载；同时要求接入四机分片与断点续跑。本设计记录实施选择，不改变已确认的规则，也不另加用户审批步骤。

## 实施选择

采用独立 Python CPU 运行层、共享 WekaFS 上的 JSON 队列与跨主机 flock。固定 pair 哈希分片，先领取本分片，允许接管其他待处理分片。每节点 slot lock 防止重复 worker；每 pair 锁覆盖整个处理期间；全局队列锁只用于短事务。固定规则归档和原生产结果只读。

没有沿用旧 GPU 全量调度器：它仍使用 V1、默认多 GPU worker，和本次资源目标不同。也没有引入数据库服务：现有共享文件系统足以承载 4 个低并发 worker，跨主机互斥将在实机验证。

## 队列和恢复

工作目录由显式 --work 指定；初始化冻结选中源、四节点与规则/运行代码/反馈指纹。默认有限选样，--all 必须显式指定。本轮冻结 32 条新来源，不按结果挑选；有原全量结果、归一化音频描述及前版证据才能纳入，跳过原因记录。

队列 JSON 原子提交四分片 cursor 和 in-flight 表。领取时在队列锁内获取 pair 锁并登记 inflight；进程消失释放 flock，其他 worker 可重新领取，不能仅按过期心跳抢活跃任务。完成时原子写 result、完成校验记录，再更新队列；崩溃在这几步之间仍可恢复，完成数只计一次。失败最多 3 次后单独登记，不能静默计为完成。

每一条 QC / fallback / 局部恢复决策之后保存 pending、seen、父子候选、诊断和计数。恢复从该状态继续；若在本段计算中被打断则仅重做本段，已落盘精确 QC 缓存可复用。checkpoint、result、快照绑定运行合同；输入或代码不一致应拒绝恢复。完成源的结果可校验后跳过。结果保持样本 runner 的语义字段与 J 的原始 revision；新运行层另有 revision。

## 原计算流程

准备源时使用已有十二条快照做回归；新源沿用基础 SourceContext(..., shot_times=[[],[]]) 生成转写/VAD/RMS/源元数据快照，再按已验证 runner 构造无视觉裁剪门槛的 J 上下文。先 propose([]) 切完整候选，再执行不变的音质路由、短回应失败回退和有完整性检查的局部恢复。旧全量/v8/当前运行的精确区间 QC 优先复用，验证归一化音频摘要。新 AST/PANNs 仅 CPU，batch=4，不生成视频或训练缓存。

## 资源和生命周期

每节点只有一个 worker，Torch 2 线程、interop/BLAS 1 线程、CUDA_VISIBLE_DEVICES 为空。worker 及子进程限制在当前允许的两个逻辑 CPU 上，nice=10，关闭本进程 THP，记录实际 affinity 和资源环境。模型在 worker 内持久复用。每段之间检查共享 control；SIGTERM 设置停止标志，保存最近完整检查点后退出。独立进程组与身份记录只用于停止本轮 worker，绝不改动训练和既有 rg 进程。

controller 是唯一带 controller lock 的训练监测器。worker 必须要求新鲜 controller lease；监测器失联或 deadline 到期不再开新段，避免无人看管持续运行。远端启动使用已经验证的 SSH 配置和共享代码；启动失败、退出、未获得工作量必须报告，不能据此宣称共存稳定。

## 共存试验

控制器先读取当前 node17 TRAIN_PROGRESS 尾部非 warmup 的 100 步作为基线并绑定日志 inode 与步号。近期日志不新鲜或不足样本则不启动。稳定运行的训练单步耗时包含 batch 与批间等待；验证/存盘的显式阶段和日志重启/step 回退应区分，无法可靠判断时暂停切分，不宣称无影响。

启动 node8/node4 后观察至少 300 秒、最多 600 秒，期间每约 15 秒读取新日志并记录实际 worker 进度。非重叠 40 步窗口的 median 或 P95 连续两窗超过基线 1.05 时降载；≥300 秒后近 80 步 median 和 P95 均≤1.05、训练健康且两 worker 确实处理数据，才允许加入另外两台。四节点再观察同样 300～600 秒。本次有界试跑遇到持续退化直接将切分负载降至零、停止本轮 worker；保留结果和待完成队列。这比继续占用一部分资源更保守，后续可从断点恢复。日志超过 60 秒不更新则保守停止切分，此项记录为无法判定而非切分导致退化。最终停止本轮 worker，出具实际吞吐、缓存复用、训练 median/P95、降载事件和剩余任务报告。不声称无回归，不用 GPU 余显存当空闲算力。

## 验证

单元/多进程测试覆盖：分片确定性、并发互斥、领取后崩溃回收、完成提交中断、检查点合同不匹配、重复完成不重计、最大重试、训练窗口与无活动/陈旧日志门槛。实机跨节点锁探针确认 WekaFS flock；金标准十二条中的代表样本与当前 J 输出比较（起止、角色、原文、终端音质状态与恢复树），不重新跑媒体。另用真实未完成 pair 主动停止/恢复验证已有 QC 和 checkpoint 复用。最后运行授权的双机→四机时间窗口，采集实际 PID/线程/CPU/GPU占用证据。

本次不更改 2～11.95 秒或 5 秒阈值，不修改被冻结规则，不恢复 8875 HTML 服务，不启动正式全量或训练数据替换。writing-plans 技能未安装；实施计划在同一项目中保存，按已授权方案推进。

Builder check 已落实：领取 pair 锁在 queue 锁内一律 nonblocking；稳定判定要求比较窗口中每个节点至少 80% 采样点确实在准备/筛选、心跳新鲜且有工作进度。有限队列提前耗尽算证据不足，不自动扩容。
