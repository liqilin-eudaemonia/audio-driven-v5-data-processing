# 整段事件类别评价接入方案（用户已确认）

## 目标与已确认范围

接入evaluation/README.md所指的现有评测框架，交付类别检测、整段评分、报告和小规模真实媒体验证。对应writing/事件级评测框架_当前确认版.md及中文初稿第六部分；本次主实现为整段类别一致性，语境适当性和生成内部视听协调性继续单列，不能用本指标代替。

用户已确认：

- 视觉四类：点头nodding、摇头head_shaking、微笑／笑态smiling、皱眉frowning。
- 音频三类：可听笑声audible_laughter、简短词语回应brief_verbal_response、非词汇回应nonlexical_response（排除笑声）。
- 完整接入检测、评分、报告及小规模实际验证。
- 使用现有数据标注pipeline检测，入口沿项目README。
- 主宏平均仅纳入冻结参考标签中存在正例的类别；无参考正例类另报误报，不因双空获得满分。

## 方法与取舍

1. 用户选择复用标注pipeline：MediaPipe／反应／ASR线索和Qwen3-Omni-30B。复用本地权重、媒体处理及模型推理方式，保留原始检测证据；需要把训练数据特有的官方时间门控改为每侧独立媒体流程，并增加明确的七类状态输出。
2. 独立关键点规则＋音频模型：可解释，但要引入额外语义音频判别器和阈值，用户希望先复用现成标注链路，因此不作为首选。
3. 全人工七类标注：可作为核验和标签输入，不能代替本轮要求的自动检测接入。

复用的源：scripts/run_listen_native_caption_vocal_pilot.py（v4观察式提示、发声线索规范化、Qwen3-Omni多模态推理），experiments/listen_j_reaction_vocal_omni_20261103/config.json及related/P2_四机32卡检测打标重叠运行_20261103.md（最终反应补充与8fps输入），已有MediaPipe／GLARE单类候选代码。绝不修改历史打标产物或在运行评分队列。

## 检测适配（本设计的提案，尚未视为用户已确认）

- GT与生成各自重新读取最终媒体；不读旧caption、规划描述、训练Event head或另一侧检测结果。使用不含方法名和GT/generated角色的匿名媒体ID送模型，避免提示泄漏。
- GT保留现有封存listener波形配方作为参考输入。生成使用自己的完整音轨，不套GT事件门控、不从GT转写补生成词句、不只截参考有声时段。两侧ASR均从各自波形重做；ASR只是候选，最终须按实际可听内容判断。
- 视觉候选从该侧25fps媒体计算；保留各类独立候选，不使用GLARE六类互斥argmax的输出作为完整多标签真值。点头、摇头、笑态、皱眉可以同时存在。Qwen视觉视图采用原pipeline的8fps视频，不含可听音频；音频视图只给该侧音轨和自身候选，不给视觉，避免以张嘴推断发声或以笑声推断微笑。
- 使用同一冻结Qwen3-Omni权重和版本化观察式提示，分别完成视觉／音频显式类别判别。沿用原pipeline的可观察事实原则，但新增严格结构化输出；因此命名为独立评测适配版本，不宣称原prompt逐字未变。
- 每类必须输出present、absent或unknown，并提供简短可核验描述；技术失败另存error。未提及默认unknown，禁止从稀疏描述推导负例。无需把模型自报置信度当成校准概率；不新造0.5之类语义分数阈值。
- 能量/VAD、点头等原线索的阈值、代码和来源都写入contract。它们仅辅助检测，不把VAD=speech自动等同短词或backchannel。复用现行冻结规则，任何新阈值先作为pilot配置，不在测试集上调参。
- 拟定且待用户确认的类别边界：独立短词／短语yeah、okay、right、no、wow为短词回应；mhm、uh-huh、hmm、uh、ah、oh作为非词汇拟声音节回应（不因ASR拼成英文词而变成短词类）。笑声仅归笑声；普通呼吸、噪声及咳嗽不算非词汇回应。混合片段可多标签，但不能把同一个uh-huh同时算短词与非词汇。持续的完整长句单列long_speech辅助标记，不凭它自动判短词类为present；其中确实另有独立短回应才计入。短词／长句边界无法确认时为unknown，不凭空设秒数或词数界限。
- 生成文件明确有全零音轨时是有效无声；声明不支持音频生成的方法在音频组记N/A；声称支持音频但文件缺失／损坏是执行失败，不伪造静音。

## 数据契约与集成

新增独立src/p2_event_presence包和scripts/p2_event_presence.py入口，复用现有绑定pair清单与OmniResponse媒体读取，不改变现有video/reaction/audio默认阶段的含义或已冻结评分源码。

提供prepare/detect/score/compare/review等子命令（具体拆分由实施者决定）。prepare接受当前metric_manifests／prepared references及独立生成音视频映射，记录样本ID、数据集、来源、原始媒体/参考配方身份、模型、draw_id和支持模态。各数据集分开汇总，不跨Seamless/ResponseNet/ViCo混合。

标签结构每侧每类包含状态、证据、检测输入哈希和版本身份；允许独立人工标签导入，明确来源manual/detector、是否复核以及unknown。类别表版本、模型权重／处理器／提示／候选规则、媒体与标签摘要组成contract；身份变化拒绝复用缓存。逐条原始模型响应、解析错误和重试理由保留。

新检测/报告独立输出目录，只在用户指定的新运行中启用；不会让已有worker自动改指标，也不会把旧summary标成已算新事件指标。README给出可执行入口、配置、实际验证证据和未完成的人工核验／校准范围。

## 指标和边界细则

1. 每个clip、每个draw、每个类别只记录一次存在性。同类多次或不同时间发生都不增加TP；无GT时间IoU匹配，不按事件个数或持续时长加权。
2. 按类别跨全评测集合累加TP/FP/FN，再计算P、R和F1。视觉、音频分别给Macro-P、Macro-R、Macro-F1和逐类结果；可附Micro，命名明确，不以Micro替代Macro-F1。主P/R采用与F1相同类别集合，这是实现提案。
3. 主宏平均类别集合由冻结参考标签的正例支持确定，独立于生成输出。每类报告参考正/负/unknown、预测正例、TP/FP/FN、可评样本、失败/未知数；无参考正例类保留FP及误报率。对参考支持类，无任何正预测时P/F1记0；完全不可评时记N/A。
4. 双空不产生TP，不增加F1。全部参考都无事件时本组主Macro为N/A，同时报告生成额外类别、误报和参考全空样本数，不能填1。
5. unknown与检测失败不作负例。完整集合存在未决单元时不输出伪完整headline；另给明确标注的可评子集/逐类统计和缺项清单。多系统compare按每个类别分别取所有系统共同可评的ID交集，保存每类集合身份；不要求同一clip七类全可评才使用该clip其余可评类。主宏平均类别集合仍保持原冻结参考的正例支持类不变；若交集让某个主类别完全不可评或没有参考正例，主宏平均记N/A并明确列缺失类，不能静默删除该类来抬高均值。不得直接排名不同有效子集的条件均值。
6. 多次生成按相同draw策略分别计算全测试集类别计数，再对draw指标等权报告均值/离散度，保留每draw值；不跨draw取并集、不按GT挑best。缺draw明确partial。
7. 缺样本、重复ID/draw、错配参考、非法类别、输入标签契约不完整、NaN、伪状态都拒绝或以可追溯失败记入覆盖，不能静默丢弃。事件时间若作为证据保留，只检验它属于该侧片段，不参与类别匹配。

## 核验与小规模实际验证

- 具有辨识力的单元检查：时间整体平移/重复同类不改分；逐类全集计数而非平均逐clip F1；七类分模态；双空不加分；无GT正例宏集合不随生成变化；已知负例误报；unknown/error不当负例；共同子集；多draw不可GT择优；缓存/模型/媒体变更。
- 实际pilot从已有冻结pair清单中按有声、安静、短片段/可见人脸等事先规则选小批，保留选择及媒体身份。至少涵盖GT自对照和真实生成与GT对照；不将样本用于阈值调优或正式模型选择。测试执行样本数及耗时由实施者根据媒体可用性决定并明确报告，不能据少量pilot声称检测可靠性已建立。
- 输出逐条原始七类判别、来源线索、失败原因、逐类计数及有效覆盖。生成可以无任何事件；不得强迫检测输出正例制造分数。
- 提供盲化人工核验包和可导入的七类人工标签文件，用独立人工标注检查检测错误；未获得人工标签时明确pending，不把模型自评或自对照当成人工可靠性结果。语境及协调性量表尚未确认，本轮不捏造人工分数。
- 真实执行证明媒体读取、检测和聚合端到端可用；首版仍标detector_based/pilot_only。正式benchmark分数需要独立人工核验/阈值校准与测试隔离证据后才发布。
