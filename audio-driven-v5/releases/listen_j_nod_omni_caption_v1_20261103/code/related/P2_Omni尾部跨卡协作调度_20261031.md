# Omni 尾部跨卡协作调度（2026-10-31）

用户已确认实施：临近队列尾部降低每卡来源预领量，并让空闲卡分担其他卡尚未开始的片段。仅优化当前 J/Omni 打标的执行调度，不改输入、prompt、模型、采样、重试、裁框、音频净化、点头与画质规则，不启动下游全量统计任务。

## 设计与边界

原有来源级共享队列继续负责分配、恢复和最终完成回执；新增片段级 flock，所有新工作进程在准备输入前领取，输出持久化后才释放。取消或异常时先停止并排空准备任务，再释放锁。存活锁不因心跳超时而被强抢。

常态仍每卡最多预领4个来源。已入队未领取来源少于 `worker_count × ready_sources_per_worker` 时，新的预领上限变为1；已持有的来源继续处理，不抢占正在准备或推理的片段。上游后续又补足队列时恢复上限4。默认32卡阈值为64来源，统计最多向后读64行，不扫描全量结果目录。

来源拥有者通过既有 worker 心跳发布最多64个尚未提交准备的片段 ID。空闲卡每次从一个来源独占领取最多8条，复用原来源记录、画质决定、音频配方和点头输入。来源拥有者遇到被辅助卡锁定的片段会跳过；辅助卡退出时锁释放，原卡或后续接续者可以继续处理。已保存结果不会重复生成。

辅助卡不提交来源完成回执、不增加来源完成数；来源拥有者仍逐片段核对 `caption/held/visual_excluded/visual_review` 的终端结果，收齐后仅提交一次。辅助失败单独留痕，后续由拥有者按原重试机制处理，不提前把整个来源判失败。

这不是对活跃推理任务的迁移。CPU已预取、GPU正在生成的片段不能分走；若全部剩余片段都已开始，或上游暂时没有可用输入，仍可能短暂空卡。此变更不承诺整体吞吐增幅，需以实际尾部协作记录与最终耗时评估。

生产 `config.json` 新增配置：

```json
"tail_sharing": {
  "enabled": true,
  "worker_count": 32,
  "packet_size": 8,
  "ready_sources_per_worker": 2,
  "poll_seconds": 5
}
```

`enabled=true` 先让新工作进程加入片段独占协议。只有工作目录 `tail_sharing/ENABLED.json` 存在时，才开启尾部缩减与跨卡辅助。发布时先关闭这个开关、分批升级并验证32卡，再打开；避免与不遵守片段锁的旧进程混用。

worker 心跳新增 `tail_protocol`、`tail_mode`、`effective_max_active_sources`、`tail_offers`、`assisted_packets`、`assisted_clips_claimed`、`last_assisted_packet`。领取数不等于完成数。新caption的 `scheduling` 记录 owner/helper、原来源拥有者及来源ID；来源字段和自然语言正文不变。

片段锁文件位于 `tail_sharing/clip_locks/results/<hash2>/`，是小型锁元数据，不产生新WAV/视频缓存。运行中不可删除锁文件；取消协作只关闭开关并等待在途任务结束。

## 部署、验证与回退

部署证据和修改前快照：[tail_sharing_20261031](../experiments/listen_j_omni_20261030/tail_sharing_20261031/)。最终实测状态以该目录验收文件为准。

CPU回归覆盖同时领取不重复、多个辅助卡互斥、辅助卡退出恢复、来源拥有者退出后恢复、原来源保留、仅拥有者提交来源回执、准备排空后解锁、辅助失败不误判整个来源及尾部阈值切换。生产分批更新仅对本流水线进程发SIGTERM，在途推理保存后退出，由已有supervisor接续。

另外固定两个并发约束：准备流结束时不自行释放来源／片段锁，必须等推理消费者保存完成后显式关闭；辅助包未结束时不能领取新的整来源任务，避免原拥有者退出且队列回补时覆盖在途包。

CPU验收为63项测试、2项子测试通过；32路worker线程模拟512条，零重复、零遗漏，来源完成回执只有1份。四台实际主机的共享flock排他与释放检查通过。CPU模拟耗时不作为GPU提速指标。

回退优先删除 `tail_sharing/ENABLED.json`，停止发放新辅助包；已领取包继续完成。保持新代码和片段锁协议至任务结束最稳妥。若确需退回旧代码，必须先排空所有新协议工作进程及其准备任务，再重启旧版；不能在仍有辅助包运行时混用旧代码。已保存结果、来源回执和原始标注不删除。
