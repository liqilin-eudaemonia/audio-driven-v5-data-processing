# 全量开放行为提取、统计与32卡接续（2026-10-31）

## 任务边界与数据范围

本轮根据用户授权，先准备代码，再临时暂停四机32卡 Omni 打标做实际测速，随后恢复原打标；打标结束后自动转入全量文本提取、CPU统计。CPU画质、点头及上游生产不因测速停止。完整范围为当前 J 切分的60,869个来源、1,151,805个候选片段，不是历史722,706段。

只读取已有 Omni 段落，不重新看视频、不重新ASR、不改写原caption或训练缓存。缺caption、画质排除、画质待核、held和输入错误分别计入覆盖表；只有有caption且输入证据可核对的记录交给文本模型。质量状态、裁框来源、train/dev/test、来源会话及人脸尺寸原样保留。本轮不自动选取或混合训练集。

## 已确认的提取与统计规则

沿用用户接受的v3提取及50段CPU统计，模型为 `/private/ckpts/Qwen3-30B-A3B-Instruct-2507`。输入原始caption和原句编号，模型提取开放行为、正／负／不确定、持续状态／变化／基线、原句引用、明确次数及重复依据；`relations=[]`。temperature=0，输出上限8192，输入加输出上限12288，不静默截断。

完整prompt位于 `src/listen_richness/extraction.py::SYSTEM_V3`，由 `production.messages` 显式选用；通用旧入口默认v4，与本轮无关。固定prompt摘要为 `a6eeeef764e602e1c4258ef32e3d905b88c5564401ec3f6febf33a81f1b0473c`，工作目录config保存模型、prompt、源码指纹。

统计仍调用 `scripts/analyze_listen_richness_pilot.py::aggregate`（richness-type-quantity-tables-v2），区分原文明示次数、不同提及推得次数、未知次数、持续状态组，不以描述长度计数。点头候选与官方词／句／VAD并集是独立证据，不与文本数量重复相加。类别覆盖秒数表示包含该类的片段总时长，**不是动作精确持续时长**；跨重叠片段计数也不等于原视频唯一事件总数。

严格校验失败最多重试一次，完整保留所有原响应。仍有局部问题时保留可用项及待核证据；无法解析的记录计为unknown，不伪装为0或丢弃。原50段及3个历史校验失败案例全部保留，CPU回放统计与原版本一致。覆盖全量的含义是所有片段都有结果或明确分流记录，不代表模型没有漏检或统计已成为人工真值。

## 加速实现

- 四机每卡常驻一个TP=1模型，独立GPU UUID校验；避免跨机器模型通信。
- CPU按已完成来源的追加索引增量准备，不递归扫结果目录；当前16个轻量读／编码线程，SQLite分批事务提交。
- 在准备线程中提前编号原句、计算prompt token IDs及长度，GPU不重复做输入tokenization；按长度打包512条chunk，单卡预领两个chunk组成1024条请求池。
- vLLM连续调度、prefix cache、chunked prefill、decode CUDA Graph；显存预算0.92，固定BF16与输出质量参数。
- 共享动态chunk队列＋文件锁。空闲卡直接领取下一chunk；异常可重领，已持久化回执校验后复用，避免重复计数。
- 原响应、逐段统计按chunk写JSONL，不新增百万个小文件；CPU最终SQLite汇总，时间重叠检查为排序＋堆，避免旧小样本报告的两两比较。

CPU时间校验允许至多一个音频采样点的浮点／微秒舍入差，并核对音频样本数；原始时间不修改，真实时间错配仍拒绝。

## 运行与恢复

在项目根目录运行，GPU worker由控制器远程启动：

```bash
python scripts/listen_richness_cluster_control.py chain \
  --work experiments/listen_richness_full_j_20261031
```

chain等待上游 `producer_complete.json`、caption队列无在途／延后／失败、读取到追加索引末尾，再确认32卡显存释放，启动统计；模型阶段结束后CPU汇总。链路状态见 `chain.json`，后台日志见 `chain.log`。单卡失败由控制器按上限重启；重复失败会明确报错，不把不完整数据当完成。控制器异常退出可用上面同一命令续跑，排他锁阻止重复控制器。

测速命令会暂停当前Omni，请只在明确维护窗口使用：

```bash
python scripts/listen_richness_cluster_control.py benchmark \
  --work experiments/listen_richness_full_j_20261031
```

暂停只对已记录PID＋启动时间＋完整命令身份校验通过的Omni GPU worker及其监管进程生效。已有CPU上游继续工作。停止标记带本工作目录归属，恢复时只移除自己的标记。普通异常及SIGTERM走finally恢复；`kill -9`或机器掉线不能依赖finally，应检查 `maintenance/` 和停止标记后人工恢复。所有实际测速生产输出后续复用。
