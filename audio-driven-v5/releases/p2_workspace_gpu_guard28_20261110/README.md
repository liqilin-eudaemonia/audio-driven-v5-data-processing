# 训练28卡：工作区外GPU计算任务自动清理

用户于2026-11-10明确授权：不是本工作区的任务终止，不得影响训练速度。工作区按当前环境根目录 `/private/liqi_workspace` 判定，包含其下各项目及被引用的工作区代码；不把单独使用本工作区Python环境或模型文件当作任务归属证据。

已部署并运行：node12、node8、node4各GPU0–7；node11仅GPU0–3。node11 GPU4–7继续预留，程序不扫描清理只占用这些卡的任务。跨训练卡和预留卡的同一进程会标为需复核，避免连带停止预留任务。当前训练完成或本目录创建STOP后结束清理；常规小时观察另行继续。

每15秒并行读取四节点NVML及进程归属。工作目录、实际脚本路径、最多16层父进程链用于归属判断；当前28个训练worker的PID＋start_ticks单独保护。当前工作目录或实际工作区脚本／父启动任务能确认属于本工作区，允许保留。仅Python解释器／第三方site-packages／模型路径位于工作区不能单独建立归属。来源不完整、权限不足、PID已变化等情况记录为unknown，不误杀；NVIDIA/MPS等基础服务保护。记录不包含完整命令行或环境变量，避免记录API密钥。

确认工作区外的GPU进程，间隔2秒后由节点端重新查询NVML和归属，再核对PID起始时间、GPU范围。先SIGTERM，最多等5秒；仍存活时再次核对归属和GPU范围，才SIGKILL。身份或归属变化则跳过。各节点终止操作串行，不对不明确的SSH失败盲重试。

`supervisor.py`每5秒确认检测程序存活，已确认退出才按固定源码指纹恢复；观察失败不会推断训练已停止。`guard.lock`／`supervisor.lock`避免重复部署。程序不改变训练代码、数据、loss、batch或checkpoint；不占用GPU显存。
