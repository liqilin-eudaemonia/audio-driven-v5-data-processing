## 1. Seamless处理经历了哪些阶段？发现什么问题，如何改进？

| 阶段 | 发现的问题 | 改进与产物 |
|---|---|---|
| 对话切分与音质筛查 | 完整句、静音切口、凑帧等条件过严；旧父话轮候选遗漏可用区间；声学规则误删轻声、笑声 | 沿完整源会话扫描角色，优先自然边界、允许长句内切分，局部问题局部避让后重新质检；音质采用保留／复核／排除分流 |
| 裁剪与规模确定 | 大裁框不等于大脸；完整候选规模较大 | 先统计再筛选，确认使用原图crop_proposals.listener，裁剪缩放到512×512；原预裁框≥384的722,706段进入全量打标 |
| 多模型开放打标 | 点头漏检、整段概述、粗时间、联合视听不稳定；长prompt有时减少输出 | 对照后采用Qwen3-VL视觉＋Omni纯音频＋ASR词级对齐，整段与短窗结合，保留开放描述及原始响应 |
| 原文去重整合 | 同次事件跨窗重复；相接同词合并可能吞掉真实“yeah, yeah” | 保守去重、保留词序与独立发生、选择已有边界，保存全部来源；取消嘿→笑声、Ed→Yeah等内容改写 |
| 音频与标注联合后处理 | 官方独立音轨仍有残留串音；通用降噪可能削弱真实回应 | 经100条复核后采用官方listener词／句／VAD区间并集保留声音，范围外静音，同步调整事件 |
| 增量缓存 | 音轨与标签变了，旧缓存可能不再匹配 | 保存虚拟静音配方，更新音频latent和事件缓存，复用原视频，不全量另存处理后WAV；音频teacher需与新目标一致 |
| 子集筛选 | 仅按事件数容易选入重复微笑，类别不均，裁框无法代表人脸清晰度 | 真实人脸短边p10＋类别覆盖＋封顶事件密度，主体集与稀有类别补充，严格划分隔离 |
| 生成指导语义精简 | 原文仍有重复意义、心理推演；自由改写可能漏动作或主语 | 30B模型选择最全面原文，代码检查引用、时间、动作遗漏；后续按事件组安全整合，失败保留原文，完整样本不删除 |

音质早期规则还修复了“整句ASR包络覆盖无词空档”造成的误拦。无转写、窄带、瞬态或孤立模型噪声提示不再单独作为硬删依据。

来源：[切分淘汰诊断](P3_QC3_淘汰归因与裁框分布.md)、[切分与全量流程](../scripts/README_listen_v8.md)、[全量音频后处理](../experiments/p2_full_audio_postprocess_crop384_20261026/README.md)。

### 可直接用于PPT的凝练版

> 对话切分与音质筛查 → 原图裁剪与规模确定 → 多模型开放打标 → 原文去重整合 → 官方时间约束下的音频与标签后处理 → 增量缓存 → 大脸与丰富回应子集筛选 → 面向生成指导的语义精简。

> 原始证据可追溯，音频与标签一致；去重不吞掉真实重复，语义整理不补写动作，局部处理失败不轻易丢掉整段数据。

## 2. 长视频切分HTML里的旧版、新版有什么区别？最后多少小时？

旧版先提名父话轮，再在其内部切分；新版`local-listening-recovery-1`扫描完整源会话逐词时间线。短附和不抢占主发言角色，双方实质性发言重叠只局部断开。切分优先句末，其次停顿／标点，再其次完整词之间；长句允许产生2–11.95秒片段，组合失败尝试更早终点。

局部音质问题必须能定位，增加150ms保护区后避开；回收子片段重新跑QC3/QC4，不继承父片段的通过或失败结论。持续底噪、未知全局问题、人工拒绝不会自动放行。页面展示完整时间覆盖及未提取原因，不表示整条源视频都能转为合格数据。

## 4. Qwen3-ASR＋ForcedAligner具体是什么意思？

- ASR输入listener音频，回答“说了什么”。
- ForcedAligner输入同一音频和ASR文字，回答“各个词位于什么时候”。
- 实际调用为`Qwen3ASRModel.transcribe`，再将非空转写送入`Qwen3ForcedAligner.align`。

例如“Okay. Yeah, yeah.”可对应三个词区间。强制对齐不保证文字真实或边界准确；错词也可能被分配时间，重复词会错位。它不负责完整识别笑声、叹气，也不负责判断发声是否属于listener。故只是时间证据，需与其他来源和官方时间一起整理。

## 5. indicating／suggesting等心理推演是prompt要求的吗？换prompt能解决吗？

全量视觉实际prompt是：

```text
Watch this {duration}-second listener clip. List all visible backchannel behaviors you recognize. Give each occurrence its own start time, end time (seconds from clip start), and a brief description.
Return JSON with an events array. Each event has start, end, modality ("visual"), and behavior (description).
```

没有要求心理推演，但也没有明确禁止。原始响应已出现“The listener covers her face with her hand, likely to suppress laughter or tears, indicating strong emotional reaction.”，不是整合代码添加的。

对原因的判断：backchannel带有交流功能含义，brief description又未限定纯观察，模型容易把动作和意义解释一起输出。建议源头增加简短要求：只写可见动作、表情及变化，保留主语及同时动作，不解释心理、意图、原因或交流意义。

这是讨论中的改进建议，不是本文已执行的新全量prompt。应先同50段配对重测，确认推演减少且动作不遗漏、边界不退化。换prompt可能改善描述，但不会自动解决感知漏检、时间定位或跨窗重复；无须因此重跑音频静音流程。

来源：[生产冻结prompt](../experiments/listen_raw_crop384_20261024T131300Z/code/src/listen_benchmark/prompts.py)。

## 6. “50段原文整合”具体怎么做？为什么相同文字还会出现？

该页对应`listen-existing-result-fusion-verbatim-v2`，仅CPU处理已有结果，不重看视频、不重新听音频、不调用LLM。输入为682条观测、上游类别／语义关联及307份整段／滑窗ASR记录。

1. 保留全部原始观测。
2. 使用已有内容键、类别／语义标识、窗口来源与时间去重；要求跨窗、不共享来源窗口、区间重叠、两边界差均≤0.2秒，组内两两满足；有歧义不强并。
3. 选择已有代表区间，不均分、不插值、不取所有区间外包作为持续事件。
4. ASR优先整段词序，无整段则选词记录最多的窗口；按单调词序选已有正时长候选，同次转写中的重复词不合并，无法定位单列。
5. 视觉／非语言音频保留全部原文版本，**按输入遍历顺序收集的第一条**作为主显示；不是自动选择最全面句子。
6. 其他发声描述可关联为证据／分歧，不额外断言一次新发声。视觉与音频各保留时间，回应组只表示可能同时发生，不表示组内一直发声。

不把嘿改笑声，不把Ed改Yeah，不新增Says模板，心理推演也仍保留。七类来自上游语义归类，此步骤不重新硬映射。人工反馈用于规则及回归，不直接读取人工填写的词／时间替代输出。

50段最终175候选（134视觉＋41音频），2个无法定位词单列，15段无候选不视作负例。原文保留不等于识别正确，也不等于彻底语义去重。

### S0699例子

`naturalistic_V00_S0699_I00000500_local_3491a3549642`保留两次Okay：1.76–2.08秒、4.08–4.40秒，没有合成一声。页面还存在两条0.4–0.5秒、显示文字相同的视觉候选，说明旧规则不保证所有语义重复都消失。

### S5193为什么两条Affirmative vocalization时间不同？

`naturalistic_V02_S5193_I00000190_local_60bde84ffa78`：

| 原始观测 | 时间 | 整合去向 |
|---|---|---|
| event-0039 | 7.000–7.200秒 | 原始证据保留，无独立事件关联 |

## 7. 音频与标注联合后处理具体做了什么？

用户对随机100条复核后确认，以官方listener词／句／VAD区间并集作为声音支持，前后各保护0.1秒，边缘10ms淡变，其余静音。多字中文ASR内容对应区间移除并静音，单字嗯／哈／呵等暂保留。这是确认后的工作规则，不证明保留区间内毫无串音。

标签：无交集移出派生音频事件；唯一匹配官方词则用词时间；满足条件的独立非语言发声可用单次VAD；否则用模型区间与音频保留范围交集。原词与官方转写不同时保留我们的原词。多个有效子区间通过`intervals`保存，不能把外包范围当作连续发声。视觉字段不变，官方区间没有原模型事件时不自动补写。

722,706段全量后处理已验收，693,997段更新音频、28,709段复用。保存配方、新音频latent及事件缓存，不另存全量WAV、不复制视频缓存；有无发声标签不等于音频是否全静音。

来源：[静音规则](P2_官方音频时间并集静音规则.md)、[标签对齐](P2_官方时间对齐与原文保留规则.md)、[多字中文规则](P2_多字中文ASR移除与静音规则.md)。

## 8. 快速验证训练集具体怎么选？

以静音后重新筛选的新50h为准，不混用旧30,415段50h。

- 仅train；人脸检测有效帧≥98%；原始／语义标注无记录错误；至少一个非微笑事件。
- 依据后处理实际保留事件计数，同一事件的多个支持片段只计一次。
- 先取约45h主体：原始真实人脸短边p10≥224像素。一般稀有类补充允许≥192，摇头允许≥160。
- p10是逐帧短边第10百分位，不是裁框大小或resize后尺寸。
- 排序：`0.5*min(face_p10/384,1)+0.3*class_count/7+0.2*min(capped_density/12,1)`。
- `capped_density=10*封顶事件总数/max(duration_s,5)`；每类最多计3条，微笑最多1条。封顶只影响排序，不删除标签。
- 优先补稀有类，目标每类覆盖2,000段；候选不足不强凑。实际摇头352段，其他六类超过2,000。
- 同一源pair最多8段，源时间不重叠，反向角色也检查；与dev/test会话、参与者、连通组隔离；完整片段不截断凑时长。

结果29,975段、50小时零0.532秒；99.17%人脸p10≥224，249段低于主体门槛均来自摇头补充。

来源：[筛选策略](../experiments/p2_train50h_postprocessed_reselected_20261027/selection_policy.json)、[新50h说明](../experiments/p2_train50h_postprocessed_reselected_20261027/README.md)。

## 9. 16种pipeline有什么区别？fixed里有真实标注指导吗？

矩阵为2种文本×4种损失×2个阶段，统一设计使用新50h、512×512。“16份已准备配置”不等于16组均完成训练；历史旧50h实验不自动构成同数据消融。

| 维度 | 选项及含义 |
|---|---|
| fixed | Qwen输入speaker音频、listener首帧、固定任务提示；Gemma固定场景文字；没有真实回应词、动作或时间表输入 |
| guided | 同一份逐样本标注计划进入Gemma和Qwen输入＋计划条件；属于目标标注指导，不证明自主规划 |
| AV | 原生音视频flow-matching生成损失 |
| AV＋Event | 增加七类事件时间监督，权重0.05 |
| AV＋Feature | 增加目标视频／音频teacher特征监督，各0.1 |
| AV＋Event＋Feature | 两类辅助监督都开启 |
| S1 | Qwen冻结，可以用hidden缓存；训练Connector、LTX text-attention LoRA及相应辅助头 |
| S2 | 从同文本同损失S1初始化，新增Qwen注意力q/k/v/o LoRA，在线forward；不做规划文本SFT |

Gemma、音视频感知塔、基础模型原参数冻结。LTX text-attention LoRA所有组开启，Qwen LoRA仅S2开启。Event／Feature直接更新Connector及S2 Qwen LoRA，不直接更新LTX LoRA；AV更新生成链路。无Event时仍可训练detach(U)的诊断probe，不影响生成。无Feature时不构建decoder、不读teacher。

**fixed可以有标签监督，但没有标签输入指导。** 真实listener后续视频／音频是目标；Event与Feature用于损失，不输入fixed Qwen。guided才直接输入逐样本计划。“只改Gemma”的A1是额外消融，不在16组guided定义内。

S2多训练一个阶段，优于S1不能只归因于LoRA；严格归因需要相同额外步数的继续冻结对照。阶段切换新优化器，不能冒充阶段内严格续训。

来源：[矩阵设计](P2_十六组文本条件与QwenLoRA训练设计.md)、[实现与梯度](P2_十六组训练实现与运行.md)。

## 10. system prompt分别是什么？

项目显式任务文本放在Qwen的user消息，与图像／音频一起输入，不是另写的system消息。底层使用原生chat template。fixed和guided共用以下Qwen固定任务：

```text
The reference image shows the listener. The input audio belongs to
the other participant, who holds the conversational floor.

Generate the listener's synchronized facial video and own audio
throughout this listening interval. Model the listener's expressions,
head movements, and vocal feedback in relation to the incoming speech.
Preserve periods without vocal feedback and maintain the listener's
identity. The listener remains in the listening role throughout.
```

Gemma固定描述：

```text
A continuous close-up video of the person in the reference image
listening to another person speaking off-camera. The camera remains
fixed, and the person's identity and background remain consistent.
Facial expressions, head movements, and brief vocal feedback, when
appropriate, form a natural listening response. The person remains
in the listening role throughout. The soundtrack contains the
listener's own vocalizations and periods without vocalization.
```

guided在场景文本之后添加逐样本计划。语义精简版模板为：

```text
The response schedule below uses seconds relative to the start of the clip. Generate the described visual and audio responses. Quoted text specifies the vocal content. Multiple intervals listed together belong to the same response, not repeated utterances.

[开始时间–结束时间 seconds]
Visual response: 原始或安全整合后的描述

[开始时间–结束时间 seconds]
Audio response: "具体发声内容"
```

相同完整指导文本交给Gemma，也接到Qwen原生assistant生成前缀后，第二次forward提取全部输入＋计划token的hidden。不是重新写system消息，也不意味着模型自主生成了计划。开启Event／Feature或LoRA不另换提示词；历史英文翻译版和原文保留版须按实际run区分。

来源：[固定原文](../src/p3_listen/prompts.py)、[追加计划](../src/p2_plan_cache/encoding.py)、[语义版模板](../src/listen_benchmark/semantic_prompt.py)。

## 11. Event组件具体结构是什么？BCEWithLogitsLoss怎么算？

Event是条件U上的两个独立小MLP，不直接生成音视频：

```text
U_video → 同时间有效空间token平均 → LayerNorm → Linear(D_video,128)
        → GELU → Linear(128,6) → 六类视觉logits
U_audio → 按时间聚合             → LayerNorm → Linear(D_audio,128)
        → GELU → Linear(128,1) → 音频发声logit
```

视觉六类为点头、摇头、微笑、大笑、皱眉、惊讶；音频只有listener_vocalization，不预测Yeah／Okay词义。视觉布局4Hz（输入8FPS、两帧一组），每格0.25秒；音频8Hz，每格0.125秒。多标签独立预测，不是七类softmax；可同时点头和微笑。头内无额外Transformer或时序卷积，依赖上游上下文。聚合与MLP用FP32。

事件区间转占用比例y：完全覆盖为1，部分覆盖为0～1；可用背景为0，不确定区域known=false排除。例如0.25秒格中覆盖0.10秒，y=0.4，表示时间占用，不是人工给出40%置信度。

令z为logit、p=sigmoid(z)，普通二元交叉熵为：

`L = -[y log(p) + (1-y) log(1-p)]`

BCEWithLogitsLoss将sigmoid和交叉熵合并为稳定计算，无需先手动sigmoid。y=1、p=0.9时损失约0.105，p=0.1时约2.303；y=0则反过来。

实际实现带类别正例权重w：

`L(t,c) = -[w(c)*y(t,c)*log(p(t,c)) + (1-y(t,c))*log(1-p(t,c))]`

仅known格参与；每类除以其全局known格数，再对有有效监督的类别等权平均。正例权重后概率不能直接解释为校准占用比例。开启Event时总损失加`0.05*L_Event`；Feature若开启再加两路各0.1。

probe_only先detach(U)，只更新头；joint_event将梯度传回Connector，S2再到Qwen LoRA。Event不直接更新LTX LoRA，不是推理时必需输入，也不是GLARE独立检测器。

来源：[Event实现](../src/p2_listen/events.py)、[时间布局](../src/p2_listen/layout.py)、[矩阵模型](../src/p2_matrix16/model.py)。

## 12. 现在有哪些评测指标和方式？独立检测器是什么？

### 当前比较方式与边界

2026-10-28本批正式范围为原独立test24，每条seed137／251，每组48输出。旧4组最终1268步＋新版guided AV／AV＋Event最终1249步共288输出；新版AV＋Feature最终权重待补48。此前更宽范围、train或test48产物不混入正式比较。**10月29日总索引已记录本批6组288输出上线，前次问答“5组指标完成、1组运行”仅是当时快照。**

各组保持相同test成员与GT、speaker音频、首帧、长度。旧组仅换Gemma指导文本，新版Qwen与Gemma使用同一指导；因此跨版本不是只改变单一损失的纯消融。该批是目标标注指导诊断，不代表source-only自主规划。总索引另列自主规划试验，应分开看。

### 默认指标

| 指标 | 方向 | 实际含义与限制 |
|---|---|---|
| FVD-32 | ↓ | I3D时空特征分布距离；25FPS连续32帧约1.28秒，各模型与GT相同固定窗口；集合级、小样本敏感，不代表全片逐帧正确 |
| UTMOSv2 | ↑ | 模型预测音频主观质量，非人工MOS；仅listener，不评回应词是否正确、时机是否合适；静音不适用 |
| SyncNet LSE-D | ↓ | listener口型与其自身声音的特征距离，不是与speaker节奏的互动一致性 |
| SyncNet LSE-C | ↑ | 最佳同步匹配的突出程度，非概率；短轨迹／近静音须看支持范围 |
| R-F1 | ↑ | 六类视觉反应事件宏平均F1；同视频同类tIoU≥0.5一对一贪心匹配，缺席类计0 |
| R-tIoU | ↑ | 已匹配事件的时间交并比均值；需结合漏检误报，不能单看 |
| R-ATD | ↓ | 起点／终点／时长相对GT时长的归一化偏差，负偏差权重2、正偏差0.5；报告×100，不是毫秒误差，无匹配为null |
| R-FID | ↓ | 两侧各自全部反应帧的Inception特征分布距离，含未匹配反应帧；不是FVD或逐帧像素误差 |

可选FD需指定特征；METEOR／ROUGE-L／BERTScore需生成和参考文本；Distinct-1/2统计表达多样性。这些是可选接口，不意味着默认均已计算。训练loss下降不能替代生成评测。

### “独立检测器”指什么？

GT和生成视频都经同一套GLARE参考视觉反应流程：MediaPipe Face Landmarker提取关键点／头姿；FER＋MTCNN提供表情／人脸信息；规则及合并器产生微笑、大笑、皱眉、惊讶、点头、摇头序列。不是打标Qwen，也不是我们训练的Event head。

独立是指与生成模型训练分支独立，不是人工真值。GT侧也是自动检测参考；六项不评价音频回应，也不能直接证明反应适合speaker内容。

### 为什么有严格版和去门槛版？

严格版要求逐帧关键特征完整、唯一FER脸及框IoU≥0.1等；去门槛版取消整段严格准入，沿用既定缺失值、插值、平滑处理并保留漏检诊断。后者不是官方标准全量评测的等价物。

旧英文指导批次test共同支持严格版7/24、去门槛24/24，只是旧批次覆盖数字。最新单条件评分按该条件两个seed共同支持汇总，严格子集可能跨pipeline不同，横向比较应另取共同支持集合。音频指标也须同时报告覆盖率；无脸、静音、短轨迹不能硬排分数。历史生成近静音，使UTMOS／SyncNet不宜直接解释成有效回应质量。

来源：[当前正式评测](../experiments/p2_reintegrated_final_eval_20261028/README.md)、[GLARE](P2_GLARE四项反应评测实现与运行.md)、[音视频指标](P2_OmniResponse评测实现与运行.md)、[两套GLARE口径](../experiments/p2_guided_en_full_eval_20261027/README.md)。
