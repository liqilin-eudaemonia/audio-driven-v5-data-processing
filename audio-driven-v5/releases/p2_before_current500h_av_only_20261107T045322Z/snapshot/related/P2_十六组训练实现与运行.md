# 十六组文本条件 × 损失 × Qwen 阶段：实现与运行

2026-10-27。用户已确认第二阶段让 AV／Event／Feature 损失按配置回传到 Qwen LoRA，不另做规划文本 SFT。设计见[设计记录](P2_十六组文本条件与QwenLoRA训练设计.md)。

入口：[训练脚本](../scripts/p2_matrix16.py)、[实现包](../src/p2_matrix16/)、[16 份配置及索引](../configs/p2_matrix16/matrix.json)。本入口独立于历史四组训练代码；没有启动16组正式训练。

## 配置矩阵

每个单元格均有 `s1` 和 `s2` 配置，合计16份。

| 生成链路损失 | fixed 配置前缀 | guided 配置前缀 |
|---|---|---|
| AV | `fixed_av` | `guided_av` |
| AV＋Event | `fixed_av_event` | `guided_av_event` |
| AV＋Feature | `fixed_av_feature` | `guided_av_feature` |
| AV＋Event＋Feature | `fixed_av_event_feature` | `guided_av_event_feature` |

- fixed：原固定 Gemma prompt，Qwen 只编码 speaker 音频和 listener 首帧的原输入前缀。
- guided：每条样本的完整时间段标注指导，同时交给 Gemma 和 Qwen；两处文本必须完全一致。沿用此前英文指导模板，按最新确认保留原描述/发声词，包括单字中文。
- s1：Qwen 冻结；fixed 读取既有 input，guided 读取新增 input_plan，逐样本读取对应文本 embedding。
- s2：从**同文本、同损失 s1** 检查点初始化，再新增 Qwen LoRA；条件 forward 在线重算，不读取 input/input_plan hidden。规划文本本身不做 SFT。

guided 属于此前 A2。A1（只替换 Gemma、Qwen 不加入计划）不在这16组中。训练计划来自标注；自主规划文本生成器、盲测规划效果不是这16份配置已经完成的验证。

## 数据与缓存

统一使用[重新后处理并筛选的新50h](../experiments/p2_train50h_postprocessed_reselected_20261027/README.md)：29,975段、50小时零0.532秒、train、512×512。读取该目录 config.json，组合原视频 latent、静音后音频 latent／reuse_base_audio 和更新后的七类事件。未重做旧视频 VAE、未保存新 WAV。

新增文本/计划缓存位于 `experiments/p2_plan_conditions_train50h_verbatim_20261027`，三机提取与校验已经完成（各29,975条），验收及日志见[缓存作业](../experiments/p2_plan_cache_train50h_verbatim_20261027/README.md)。只处理新50h，不处理722,706段全量。

Feature 组使用独立 `experiments/p2_matrix16_teacher50h_20261027`。teacher 由冻结的原始 Qwen 生成：listener 目标视频特征，以及**静音配方处理后的音频**先合并为单声道、重采样到16kHz再提取的音频特征。身份绑定源媒体、配方、模型和代码。静音是有效目标，mask 只处理时间支持不足／padding。不能将旧音频 teacher 接到新音频 AV 目标上。已通过真实GPU单条提取，完整50h teacher 已完成29,975条，48份分片报告全部成功，验收文件为该目录COMPLETE.json。本次由三机各一张5号卡逐步扩为三机24卡、每卡2进程。

无Feature组不构建 decoder、不读取 teacher、不设置其优化器组；不修改后处理数据视图原来的 feature-disabled 防误用检查。

## 优化与梯度

共同设置：AV权重1；有Event时0.05；两路Feature各0.1；LTX两路text-attention LoRA各组均开启，rank8、alpha8、lr1e-5。Connector／Feature lr3e-5，事件头lr1e-4。Gemma和两个基础模型的原参数冻结。

Qwen LoRA 位于文本self-attention q/k/v/o，rank8、alpha8、lr1e-5。当前使用隐藏层索引8/18/28/35，因此只改其上游0–34号block的140处投影，不给未参与所选hidden的最后block添加无梯度参数。音频塔、视觉塔和输入embedding冻结；文本Transformer开启非重入gradient checkpointing。去掉了在线提取及LayerMemory中的hidden detach。

| 损失 | Connector | Qwen LoRA（s2） | LTX text LoRA | 其他 |
|---|---|---|---|---|
| AV | 更新 | 更新 | 更新 | — |
| Event，开启时 | 更新 | 更新 | 不更新 | 更新事件头 |
| Event，关闭时的诊断probe | 不更新 | 不更新 | 不更新 | 仅更新事件头 |
| Feature，开启时 | 更新 | 更新 | 不更新 | 更新两个decoder |

无Event组的probe使用detach(U)，所以“AV组”指生成链路只由AV优化。TensorBoard会同时展示诊断probe损失，不代表它回传到了生成链路。Feature目标由独立冻结teacher提供，不能来自在线LoRA模型。

每个microbatch是一条完整样本，支持不同时间长度和文本长度；跨卡按global batch归一化。Event按全局已知bin数量归一化，unknown不作负例。FP64桶累积／SUM归约覆盖所有优化器参数；生成链路统一clip，事件头单独clip，延续之前的裁剪口径。

## 运行

训练步数故意为null，需显式指定，避免继承旧数据配置的1000步。若另行决定每阶段遍历一轮，global batch24时为1,249步／29,976个样本位置；这只是换算，不是已批准的正式预算。

```bash
P2_PYTHON=/private/liqi_workspace/project_code/Omni-LTX-stage2/.venv/bin/python
P2_CONFIG=configs/p2_matrix16/guided_av_event_s1.json

# 一次准入／事件统计；不遍历加载全部AV、hidden，也不重新hash所有源视频。
"$P2_PYTHON" scripts/p2_matrix16.py preflight --config "$P2_CONFIG"

# 必须由操作者明确填写本次预算、资源和节点参数。
"$P2_PYTHON" -m torch.distributed.run \
  --nnodes=3 --nproc_per_node=8 --node_rank="$P2_NODE_RANK" \
  --master_addr=172.29.15.91 --master_port=29988 \
  scripts/p2_matrix16.py train --config "$P2_CONFIG" \
  --steps "$P2_STEPS" --global-batch 24
```

三台分别使用node_rank 0/1/2；本轮缓存已经完成，以上仍为后续正式训练命令，尚未启动。第二阶段换成同前缀`s2.json`，先做对应preflight，再向train传 `--parent /绝对路径/s1/step_XXXXXX.pt`。新阶段新优化器；检查父组、数据、源码、结构和参数形状。严格续跑使用`--resume /当前组/step_XXXXXX.pt`，不得同时传parent。

Feature teacher命令（各组共享一份，不按8个Feature配置重复提取）：

## 保存、恢复与记录

每100步及正常结束／主动STOP保存模型、优化器、step和每rank RNG；完成标记绑定checkpoint SHA。只保存Connector、事件头、可选decoder和两类LoRA，不重复保存基础模型。配置、数据协议、源码、模型资产、父权重、rank数均进入恢复身份。

`output/STOP`会在step边界停机并保存。崩溃恢复到最近完整checkpoint，不把未完成step视为成功。阶段内预算属于严格身份；需要延期预算时应先明确新的实验协议，不能直接改配置冒充原断点恢复。

`metrics.jsonl`、`status.json`、`tensorboard/`记录AV视频/音频、Event、两路Feature、加权总损失、逐类事件loss/known、各参数组梯度、学习率、耗时和峰值显存。恢复清理checkpoint之后的旧曲线，防止重复step误读。

[inference.py](../src/p2_matrix16/inference.py)提供新checkpoint严格恢复与在线条件接口；要求同一计划文本，区分`predicted`和`annotation_oracle`。这是供后续评测调度器调用的接口，不等于16组已完成生成评测。用户尚未提供新验证集。
