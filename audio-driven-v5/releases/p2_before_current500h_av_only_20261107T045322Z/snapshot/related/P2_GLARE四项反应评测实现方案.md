# GLARE 四项反应指标：实现方案

2026-10-26：用户已选择先完成公开四项反应指标及完整视频评测流程；评测数据由用户稍后提供。本次不选择正式评测数据、不启动正式评测。当前 E1 三机训练持续运行。

## 目标与实现选择

接通 P2 检查点生成 → 独立 RGB 视觉反应检测 → CSV/视频一致性检查 → R-F1、R-tIoU、R-ATD、R-FID → 可追溯报告。支持用户已有 GT/生成视频直接评分，也支持已有独立 CSV；不使用训练事件头评分。

采用原仓库指标函数及作者独立视觉标注仓库的规则，增加严格适配、逐类统计和流程管理。重新实现四项公式容易产生口径偏移；改用训练标注 VLM 会改变检测器体系，两者均不作为本轮实现。用户确认的范围是四项指标及完整流程；具体代码组织由实施方选择。

## 固定口径

- 六类视觉、每帧 winner-take-all，输出列顺序使用 GLARE 原定义。七类训练标签与音频训练保持原样。
- 分数严格 >0.5，按类、按视频，tIoU≥0.5 的降序贪心一对一匹配。
- R-F1 汇总全数据集每类 TP/FP/FN，再对六类平均；缺席类为零。
- R-tIoU 是匹配事件均值，无匹配为零。
- R-ATD 保留原实现 alpha=2、beta=0.5、三项相加、报告乘 100；无匹配为 null。
- R-FID 使用 FID 专用 Inception-v3 pool3，分别汇总两侧自己的全部反应帧，含未匹配事件，无帧重采样；不足两帧为 null。
- GT 与生成帧数、FPS、起点与时间轴严格匹配。检测器规则以 25 FPS 固定，不静默改 FPS 或裁掉错位帧。
- 自动检测结果只称 detector-based reference consistency，不称人工真值或 speaker 适当性结论。

## 组件

新增 `src/p2_glare_eval/`、`scripts/p2_glare_eval.py` 及独立测试，不修改 `src/p2_listen/` 或其复用源文件，不改变训练 checkpoint/source identity。

1. 上游加载器：固定两个仓库的源码哈希、commit 与 MediaPipe 模型哈希；复用原指标和六类规则，显式固定点头 v2。FER 采用逐帧公共接口，绕开上游依赖自定义 FER Video 接口的批处理脚本，保留 FER 原模型与 MTCNN。
2. 输入与持久化：成对视频清单或原生 P2 observations/targets，记录全媒体 SHA256、sample ID、生成 seed、模型身份、检测协议；完成标记最后原子写入，重跑校验身份和输出哈希。
3. 检测器：MediaPipe face features + FER emotion + 六类原规则 + 原 winner combiner。保留逐帧原输出和人脸检测覆盖；缺帧、未检测到脸、依赖错误不得伪装成 neutral。默认完整覆盖才进入四项正式汇总；不完整样本/失败按全清单报告。
4. 评分：调用上游公式，增加逐类 TP/FP/FN、匹配事件、匹配覆盖、反应帧数和失败清单。R-FID 模型离线预取且记录权重哈希；支持 CPU/GPU。多生成 seed 分别评分并汇总均值，不重复 GT 帧改变 FID 权重。
5. P2 生成：复用现有 source-only 生成入口；模型只能接触 speaker 音频、listener 首帧、固定文本和时长。GT 只供评分。支持分片、已完成结果复用、失败记录、最终 checkpoint 完整标记检查；可显式等待训练完成后执行，但需要用户提供清单后才建立作业。
6. 环境：独立评测虚拟环境，不改训练虚拟环境；GPU 测试不得抢占当前 24 卡。通过 CPU 的真实视频检测、FID 权重及端到端样例验证主要评测链路。

## 验证与交付

测试阈值边界、缺席类、无匹配、ATD 非对称/缩放、贪心匹配、reaction-frame selection、尺寸/帧数/时间轴不一致、缺失样本、缓存身份失配、失败不被静默丢弃、多 seed 分开聚合、生成 GT 隔离。加入对上游四项公式的金标准重放；CPU 实际人脸视频与 FID 模型用于工程验收，不冒充正式评测结果。

用户提供数据后，固定协议、运行生成及检测、导出 JSON/Markdown 与事件明细。任何不可评分项必须有明确原因，不能填 0 或把不完整子集冒充完整评测。
