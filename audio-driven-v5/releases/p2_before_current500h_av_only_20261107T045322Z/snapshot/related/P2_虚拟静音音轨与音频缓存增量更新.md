# 虚拟静音音轨与音频缓存增量更新

2026-10-26。用户确认：全量保留原音频与处理规则，读取时在内存中静音；只更新音频缓存，抽样试听可保存WAV。本轮已完整运行固定100条并通过逐条验收，未启动全量处理或训练。

## 当前实现

不再给每条数据额外写一个处理后的WAV，也不重新编码或复制视频latent。每条数据保存一个JSON配方，读取时验证原WAV哈希，依次应用已经复核的两级处理：

1. 官方listener词／句／VAD区间并集、各侧0.1秒保护区、10毫秒内部淡变。
2. 多字中文ASR对应区间静音及其外侧10毫秒淡变，单字中文保留。

操作顺序、采样点取整及float32运算与已有试听文件一致。**先在原采样率下处理，再按原VAE路径重采样与补齐**；不在latent上简单置零。全静音波形也正常经过音频VAE。

相比“保存所有处理后WAV”，此方案不增加整套波形文件；相比“重算整包视频＋音频VAE缓存”，此方案单独保存音频更新，并在训练读取时组合旧视频。原始WAV、原缓存和旧marker均不改写。

## 文件职责

| 文件 | 职责 |
| --- | --- |
| `src/listen_audio_postprocess/recipes.py` | 配方、来源校验、内存波形读取及数值哈希；不写WAV |
| `src/listen_audio_postprocess/prepare.py` | 建立独立数据视图、配方和新canonical标签，复用input/text目录 |
| `src/listen_audio_postprocess/encoder.py` | 常驻原生LTX音频VAE；不加载视频VAE、Omni、Gemma |
| `src/listen_audio_postprocess/overlay.py` | 音频独立缓存身份、单样本写锁、原子完成、断点复用、训练时组合 |
| `scripts/p2_audio_postprocess.py` | `prepare`、`verify-waveforms`、`cache`入口 |
| `src/p2_listen/training_data.py` | 只有配置显式包含`data.audio_postprocess`时读取新音频缓存；普通配置沿用原逻辑 |

目前针对现用的 **AV＋Event、`feature_loss_enabled=false`** 路径。若开启teacher特征损失会明确报错，避免把新音频与旧音频teacher混用。后续需要teacher时应另行接入音频teacher增量重建。

## 目录与身份

```text
<new_output>/
  config.json
  manifests/observations.json          # speaker、参考图、时长、split不变
  manifests/targets.json               # 仍引用真实原媒体；不伪造新WAV路径或文件哈希
  audio_postprocess/policy_manifest.json
  audio_postprocess/index.json
  audio_postprocess/recipes/<sample_id>.json
  labels/canonical/<sample_id>.json
  cache/input -> <base_output>/cache/input
  cache/text  -> <base_output>/cache/text
  cache/events/<sample_id>/...
  cache/audio_postprocess/<sample_id>/{payload.pt,complete.json}
```

原完整视频／音频VAE包仍在`base_output/cache/vae`；新目录不复制它。新音频payload只包含音频latent、音频支持mask、几何信息与处理波形哈希。训练时读取原包，复用其中的视频tensor，替换音频字段。原始波形实际未变化时，新payload仅保存“复用原音频”记录，不加载编码器。

新身份绑定：原音频SHA256、完整处理配方、处理代码版本、原VAE身份和载荷SHA256，以及原模型资产契约。标签同时绑定配方摘要。修改规则会导致旧音频增量缓存身份不匹配，要求新版本；不会修改旧`complete.json`绕过检查。

原`features.py`、`layout.py`、`p3_listen/features.py`、`runtime.py`均未修改，现有input/text/视频缓存身份不因这次功能新增而整体失效。新版训练入口有少量代码改动，旧训练的严格checkpoint续跑仍应使用其固定源码版本；本轮保留了修改前文件到验证目录`source_before/`。新数据应使用独立实验目录。

## 标签衔接

只更新音频事件，视觉事件、已有弱覆盖和unknown策略保留。根据原canonical事件的`source.event_id`关联整理后的事件；原文不同或缺少对应源事件会报错，不静默补写。

多个不连续有效区间拆成训练支持片段，保留同一个原事件ID关联，标明`count_new_utterance=false`；不把外包区间里的静音间隙标成连续发声。此次仅为缓存准备，不启动训练，也不把弱标签升级为人工真值。

## 已验证的100条入口

```bash
cd /private/liqi_workspace/project_code/audio-driven-v5
P2_PY=/private/liqi_workspace/project_code/Omni-LTX-stage2/.venv/bin/python
P2_VIEW=experiments/listen_audio_virtual_validation_20261026/view100

# 本轮已建立；相同输入可以复用，身份不同会报错。
"$P2_PY" scripts/p2_audio_postprocess.py prepare \
  --base-config experiments/p2_e1_train50h_lora_tb_20261026/config.json \
  --review experiments/listen_official_chinese100_20261026/results.json \
  --output "$P2_VIEW"

# 不加载预训练模型、不写WAV；与之前试听文件逐采样点比较。
"$P2_PY" scripts/p2_audio_postprocess.py verify-waveforms \
  --config "$P2_VIEW/config.json" \
  --review experiments/listen_official_chinese100_20261026/results.json

# 事件缓存使用CPU；本轮100条已完成。
"$P2_PY" scripts/p2_audio_postprocess.py cache \
  --config "$P2_VIEW/config.json" --part events
```

本轮100条已经用CPU完整运行（`--part all --device cpu --cpu-threads 2`）。以后有分配的空闲GPU时，可使用以下命令；**本轮未执行GPU命令**：

```bash
"$P2_PY" scripts/p2_audio_postprocess.py cache \
  --config "$P2_VIEW/config.json" --part audio --device cuda:0 \
  --shards 1 --shard-index 0
```

普通`p2_listen.py cache --part vae/teacher/all`遇到此类新配置会拒绝执行，防止错误地从未处理的原音频生成目标缓存。使用上面的专用入口；训练仍通过原`p2_listen.py train`入口读取新配置。

## 扩展全量的输入契约

除了100条review入口，也支持 `prepare --records <JSONL> --base-config <原配置> --output <新目录>`。每行包含：

```json
{
  "sample_id": "实际样本ID",
  "source_audio_sha256": "与原targets清单一致的listener WAV哈希",
  "official_listener": {"words": [], "sentences": [], "vad": []},
  "extra_mute_intervals": [],
  "audio_events": [],
  "provenance": {"reference": "本次规则处理记录"}
}
```

官方区间必须已转换到片段内秒数，空数组明确表示没有标注，不能用缺文件冒充空数组。`extra_mute_intervals`为明确移除的多字中文事件区间。`audio_events`为已整理后的保留事件，包含原`event_id/description/text`及有效`intervals`。上面的空数组只是格式说明，不能直接当作真实全静音数据输入。

全量流程还需先产出这些官方时间与最终标签记录；本轮没有遍历全量官方metadata、没有把100条结果推广成其他样本的配方。多机可使用固定`--shards N --shard-index i`分片，每个进程常驻一个音频编码器，样本写入有文件锁和完成标记，重跑跳过已完成缓存。各机必须能访问相同的原媒体、base缓存和新输出路径。

## 验证结果与范围

- 100/100条音频缓存及事件缓存就绪，实际训练读取、断点复用全部通过。
- 100条内存处理波形与上一轮已试听WAV逐采样点一致，未产生新WAV。
- 98条更新音频缓存，新latent与实体处理WAV经同一CPU编码器产生的结果逐位一致。2条波形未变化，精确复用原音频缓存；另行确认虚拟与实体波形的同设备编码结果一致。原缓存可能由不同设备生成，不要求跨设备重编码逐位相等。
- 保留63个音频事件，38条有发声标注、62条无发声标注，53条音频全静音。描述原文与有效区间和已复核版本完全一致；六类视觉事件、事件目标及视频latent不变。
- 26项单元／原AV路径／推理隔离检查通过。
- 本批新增音频payload共4,133,972字节（约3.94 MiB），没有新视频缓存；未据此外推全量空间或吞吐。
- 本轮未初始化CUDA，没有启动训练或全量转换。这里只验证缓存与训练数据读取，未运行训练前向、反向或生成评估。
