## 启动前提

- 已用`p2_plan_cache.py prepare`发布完整`protocol.json`，配置中的`work`指向该目录，且对应指定的新50h数据配置。
- 单字中文按用户最新确认原样保留；不翻译、不删除样本。
- 三机代码、Python、模型及tokenizer依赖身份相同，工作目录双向共享。
- 默认独占配置要求GPU没有计算进程、显存≤1024MiB、利用率≤5%。共享配置显式允许其他任务，启动和每个GPU阶段前检查空闲显存；本次要求至少80GiB空闲、缓存进程限额64GiB。资源不足时等待，超时报告失败；不kill其他任务。

`prepare`在一个协调进程执行一次；不能由24个GPU进程同时准备同一协议。旧视频/后处理音频latent继续复用，三机任务只提取新文本及计划hidden。

## 使用命令

项目根目录下：

```bash
P2_PYTHON=/private/liqi_workspace/project_code/Omni-LTX-stage2/.venv/bin/python
P2_CLUSTER=configs/p2_plan_cache_3nodes.json
P2_JOB=experiments/p2_plan_conditions_train50h_cluster_run01

# 查看24分片规划，不启动进程。
"$P2_PYTHON" scripts/p2_plan_cache_cluster.py plan --cluster "$P2_CLUSTER"

# 检查SSH、双向共享目录、代码、依赖和GPU占用；不提取特征。
"$P2_PYTHON" scripts/p2_plan_cache_cluster.py probe \
  --cluster "$P2_CLUSTER" --output experiments/p2_plan_cache_cluster_probes

# 数据准备完成且卡空闲后启动。start再次执行核验。
"$P2_PYTHON" scripts/p2_plan_cache_cluster.py start \
  --cluster "$P2_CLUSTER" --job "$P2_JOB"

# 汇总每个分片当前阶段、日志、返回码和节点心跳。
"$P2_PYTHON" scripts/p2_plan_cache_cluster.py status --job "$P2_JOB"

# 显式停止本作业的子进程，不影响其他GPU任务。
"$P2_PYTHON" scripts/p2_plan_cache_cluster.py stop --job "$P2_JOB"
```

三台机器分别运行脱离SSH会话的监督进程，启动终端退出不会终止它们。每个监督进程管理本机8个分片。各阶段失败最多重试一次，已经成功的样本由原缓存完整性逻辑复用；持续失败的分片不进入下一阶段，也不会计为完成。其他分片可以继续。

每个节点有进程锁，每个缓存part/sample另有原有文件锁。代码和协议身份在运行中检查；改源码或混用另一个协议会失败。普通中断后按同一配置重跑可复用完成缓存。运行中的监督进程不可重复启动；完成的作业再次start返回already_completed。主动stop留下STOP标记，重启须使用新job目录，同一work缓存仍可复用。

极端断电/SIGKILL不承诺自动重启监督进程；心跳过期会标为stale。先确认旧进程状态再重启，GPU占用及缓存锁阻止重复占卡。不要把“有限阶段重试”误解为无限守护或数据问题自动修复。

## 日志与完成条件

- `job.json`：冻结的节点、GPU、分片、缓存协议及源码身份。
- `launch.json`：三机启动结果。
- `nodes/<node>.json`：节点心跳与状态。
- `workers/<rank>.json`：分片阶段、尝试次数、PID、日志路径与退出码。
- `logs/<rank>.<stage>.attempt-<n>.log`：每次尝试日志；同一job重跑追加，不覆盖旧记录。
- `status.json`：调用status时生成的汇总快照。
- work目录`reports/`：原缓存写入及逐载荷校验明细。

只有24个分片都完成两阶段提取和verify、三个节点也全部成功，整体才标为succeeded。SSH启动失败、GPU占用、样本失败、载荷损坏或缺失都不能得到整体成功。
