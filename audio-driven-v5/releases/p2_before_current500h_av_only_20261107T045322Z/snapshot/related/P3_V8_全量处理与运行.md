## 并发安排

- 本机 GPU 0–7，默认 8 个模型工作进程，每卡 1 个，各自持有 AST/PANNs。
- `--prep` 默认 2，总计 16 路 CPU 准备；本次小批显式指定 `--prep 1`，总计 8 路。模型和 BLAS 每进程限 1 个 CPU 线程，减少嵌套线程争用。
- 共享任务领取队列，CPU 先完成的来源优先送入质检，结果按 pair 原子写入。每卡多模型进程用于覆盖 CPU 特征处理/存储等待。
- 模型 batch 保持验收时的 16。PANNs 批内 padding 会随上下文长度改变；不能仅为占显存而直接改 batch 并假定结果等价。后续调大须先做结果一致性验证。
- 每 15 秒记录 CPU、I/O 等待、8 卡利用率、显存和完成量；约每 120 秒更新完整时长报告。是否提高并发以吞吐与错误率为依据，不把占满显存当作产量。
- 全量获得验收授权后，媒体导出并发由 `--render-workers` 控制，默认 16。H.264 使用 CPU、每个 FFmpeg 单线程，保持 CRF 17、512×512、25fps；该阶段 GPU 空闲不意味着裁剪停工。本次 `--limit 128 --no-render` 小批完成后不会自动导出全量媒体。

## 实际导出内容

对音质 `keep` / `review` 的片段导出，分类存放；`exclude` 和无完整候选的片段只保留审计。review 的导出供复核，不自动加入训练。

每个样本目录包含：

- `listener.mp4`：裁剪后的 listener 视频与其自身 AAC 音轨。
- `speaker.wav`、`listener.wav`：原归一化整轨按同一区间裁出的 48kHz 单声道 PCM_24。
- `reference.jpg`：listener 视频第一帧。
- `export.json`：区间、音频精确样本数、视频时长、质量状态及文件 SHA256。

视频做完整解码检查；音频验证精确样本数。视频帧边界允许不超过约 81ms 的容差、AAC 时长不超过 25ms；不再以 8k+1 帧或 201 帧上限截掉句子。训练帧数适配另行实现。

从项目父目录运行：

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  Omni-LTX-stage2/.venv/bin/python audio-driven-v5/scripts/run_listen_v8_full.py init

OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  Omni-LTX-stage2/.venv/bin/python audio-driven-v5/scripts/run_listen_v8_full.py detach \
  --workers 8 --prep 1 --render-workers 16 --limit 128 --no-render
```

`detach` 持续执行筛查并在结束后导出媒体，不启动训练。完成记录可以复用；进程异常恢复前需核对 `runtime.json` 中的工作进程均已结束，再重建队列，不能让孤儿工作进程与新一轮并行处理相同来源。错误来源不计入已成功处理或合格数据。

`report` 子命令可生成报告及区间清单；不能与监督进程的报告写入并发运行。当前全量结果与用时须根据实际运行统计，24 组小样本不能估计最终可用小时数。
