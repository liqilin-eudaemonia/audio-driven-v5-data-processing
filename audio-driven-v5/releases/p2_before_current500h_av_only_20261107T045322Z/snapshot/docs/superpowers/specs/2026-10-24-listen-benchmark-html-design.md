# 打标模型 HTML 对比页设计

状态：用户已确认设计，并追加要求先分析结果、提出方案建议，再完成 HTML。

独立实施审阅已完成：没有必须补充的重要问题。人脸关键点原始结果约 187 MiB，页面仅加载必要摘要，完整原文按需查看，避免拖慢首页。

## 目标与数据

让用户先找出值得复核的打标方案，再对照同一段真实音视频判断模型事件是否正确。使用 `listen_benchmark_cluster_20261024T014809Z` 最终纳入的 16 配置、50 条样本和 1450 次请求；读取已有结果，不重新运行模型。初版没有人工真值，不能展示准确率或宣称某模型最优。

## 方案选择

- **总览＋同样本并排复核：用户已选择。** 统计方便筛选，媒体与时间轴提供判断依据。
- 仅统计总览：制作更快，但无法判断事件是否标对。
- 人工盲评优先：有助于减少品牌偏好，但不适合作为本次快速了解结果的默认入口。保留可选隐藏模型名称开关。

## 页面布局

顶部显示本次数据范围和“尚无人工准确率”的状态，提供“方案总览／逐样本对照／运行记录”三个页签。

**方案总览**：默认展示完整方案（Joy＋Omni、Qwen3-VL＋Omni、Qwen3-Omni 视觉＋音频分路、Qwen 原生视听、MiniCPM 分路与原生视听）。可以切换到视觉、音频、联合和输入控制组。表格可排序，显示阶段结构通过数、各目标有效检查时长比例、失败样本数。有效覆盖单独显示，不能把“至少检查过一小段”当作全片覆盖。模型自报事件数仅用于发现差异，不当作召回率。Captioner、ASR 和人脸轨迹放在辅助证据区，不加入事件模型排名。

**逐样本对照**：左侧为全部 50 条样本列表，可搜索并按失败、覆盖不足、模型事件差异筛选；默认保留完整样本集合，不只展示精选案例。右侧顶部共用 listener 视频与独立 WAV 播放器，显示 512×512 裁剪预览、播放速度和当前时间。下方可选择 2–4 个方案并排展示，所有事件共用相同的时间轴和播放游标。点击事件定位到该区间，支持重复播放。默认展示 audit 的点头／倾听者发声；discovery 另设切换，不混入固定目标事件。

各栏分别展示事件、有效检查区间、unknown 和未检查区间。无事件但未检查的片段不能呈现为可靠负例。失败栏保留错误原因与原始回答，不能显示成空事件。可展开完整原文、提示词和运行版本。不同模型的帧率、原生/拼接输入方式明确标注；共用视频只是复核媒体，不声称所有模型实际编码方式相同。

**人工比较**：支持对当前样本选择“更好／相当／都不好／无法判断”及备注，可选隐藏模型名后再揭示。判断保存在当前浏览器，可导出 JSON；这是主观复核记录，不自动转成 GT 或模型准确率，不修改原始实验文件。

**运行记录**：显示引擎与输入版本、失败类型和 CPU/GPU/显存实测曲线。明确监测时间范围，保留加载和空闲收尾；不以不同并发部署的耗时直接排名模型速度。原始记录可查看或下载。

## 实现选择（由助手提出）

复用项目现有静态 HTML 和媒体预览方式，不引入前端框架或外部 CDN。导出独立 HTML、必要数据和媒体预览包，提供项目内预览入口；不上传数据到外部服务。首页统计内嵌，避免双击 HTML 后完全空白；完整媒体复核通过本地 HTTP 预览，并给出可访问地址。使用浅色背景、清晰表格和蓝色操作元素；颜色同时配合文字与图例，不依赖红绿辨识。

默认并排方案为 Joy＋Omni、Qwen3-VL＋Omni、Qwen 原生视听，用户可替换。人工评审仅在本地保存，页面提示导出备份。

## 验收

核对 16 个最终配置及组合统计与原始报告一致；核对全部 50 条媒体映射及裁剪；检查事件点击、音视频同步、未知/未检查区间和失败展示；检查筛选、模型切换、本地记录与 JSON 导出；检查桌面和窄屏显示。页面不得将结构通过率标成准确率，也不得因缺失输出而展示零事件。
