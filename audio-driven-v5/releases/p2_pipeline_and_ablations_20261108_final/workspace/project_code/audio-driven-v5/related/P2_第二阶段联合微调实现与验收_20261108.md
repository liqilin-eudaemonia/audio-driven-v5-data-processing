## 初始化、目标和梯度

`prepare`必须显式指定第一阶段配置、完整检查点和规划SFT adapter，不自动替用户选择最终模型。候选目录为[完整模型6000＋SFT2752](../experiments/p2_stage2_joint_candidate_full6000_20261108/config.json)，仅用于接入验收，尚未作为最终模型选择结论。

Qwen从最新规划SFT2752初始化，保留并继续更新原rank32／alpha64语言层LoRA，基础语言、音频及视觉权重冻结。Connector、LTX LoRA和已启用的Whisper／Feature Decoder／LTX Event头从同一个第一阶段完整检查点加载；不加载旧Adam或旧RNG。AV-only等历史状态中保存的冻结闲置Event头可显式忽略，任何活动参数缺失／新增／形状或dtype不符均拒绝。

生成目标保持所选第一阶段组件和系数；完整模型为AV＋0.025视觉Feature＋0.025音频Feature＋0.05 LTX整段Event。另加候选0.1规划SFT交叉熵，仅监督回答token及原生EOS。规划损失按全局有效回答token数归一化，AV／Feature按样本平均，Event沿用全局known计数与原class mask，匹配原FP64 SUM梯度归约。

Qwen每次在线前向，hidden不detach；生成损失可经LTX和Connector到达原规划LoRA。只注册adapter参数，不把冻结3B／22B基础模型写入新检查点。检查点保存全部可训练模块、完整Adam、rank RNG、来源、配置、数据、Qwen参数名称顺序及世界大小，严格拒绝跨实验恢复。

Qwen输入仍仅为speaker音频、listener首帧及相应文本；listener后续视频、音频和teacher仅进入生成目标或辅助损失。训练guidance为最新完整标注；评测时重新由当前Qwen生成计划、hidden和对应Gemma条件。

## 0／100／300执行约定

| 阶段 | 行为 |
|---|---|
| 首次`launch` | 在线加载Qwen和LTX；最长实际片段及最长规划有效片段做两次完整真实更新，测试Adam与显存，分别记录生成／规划对Qwen的梯度；恢复初始参数／Adam／Torch RNG；保存step0并退出 |
| step0评测 | 固定64条，由当前Qwen自主规划；所有来源和评分证据绑定检查点及配置 |
| `--resume step_000000.pt` | 基线评测完成后训练至100，完整保存退出 |
| step100评测及`decide` | 比较规划CE、LPIPS、声音误报和格式错误等安全项；结果为continue_to_300才可接续 |
| `--resume step_000100.pt` | 训练至300，完整保存退出 |
| step300评测及`decide` | 要求安全项不明显退步、有效反应类别F1有改善；只输出是否值得1000步验证，不自动扩大训练 |

中间因STOP退出保存的检查点恢复时，也要核对该窗口之前的评测门槛，不能通过恢复57／137步绕过0／100步检查。启动前先进行CPU来源／门槛预检，避免缺少评测时占用GPU加载22B。

候选参数：有效batch31、Qwen LR1e-6、其余组原LR约1/3、预热20步、全重计算、CPU预取2批、512MiB FP64归约、134GiB进程上限。四机8＋8＋8＋7，node11 GPU7预留。单rank可用累积维持batch31；显存和吞吐最终以真实GPU短测为准。

候选[policy.json](../experiments/p2_stage2_joint_candidate_full6000_20261108/policy.json)是**可审阅的工程筛查值**：规划CE相对增幅最多10%、LPIPS绝对增幅最多0.01、声音误报／格式错误率绝对增幅最多0.02；300步反应F1改善至少0.02。它们不是已实证的最优阈值或统计显著性。参数和策略在step0前确定并重新preflight；开始后修改需要新实验和新基线。

## 分阶段评测

评测显式运行在node11预留GPU7，命令环境为`CUDA_VISIBLE_DEVICES=7`、逻辑设备`cuda:0`。代码校验物理UUID和空闲显存，不终止其他任务。

各阶段使用独立子进程：Qwen规划／hidden／参考计划CE → Gemma → Whisper（若启用）→ LTX生成 → VAE解码 → 独立GT导出 → 原生像素／音频评分 → 原事件检测 → 独立计划证据提取。固定seed137、30步、video CFG3／audio CFG7，不跨检查点复用Qwen或文本条件。

短测视频指标只计算PSNR／SSIM／LPIPS，节省FID／FVD网络开销。音频复用既有声音活动与UTMOS流程，短回应不满足UTMOS支持时保留N/A。反应类别复用现有七类pilot检测器，视觉／音频各按参考正例支持类别取宏F1，再对两模态等权平均；step0参考事件标签封存，后续先核对参考媒体内容和检测协议，再用相同标签重算生成结果分数，保留原始重新检测记录。报告的是参考类别一致性；它不是语境正确率，且人工校准仍未完成。

另由冻结标注模型读取每条计划，只有明确计划发生／明确排除的事件才标present／absent，未提及保持unknown，并要求原文证据。它与生成媒体检测分开，输出计划执行召回及显式违背率；不把“未提到点头”解释为“禁止点头”。此项为诊断，不冒充人工真值。

未知、检测失败或指标缺失不会填0。100步以可完整取得的安全指标判定；300步若反应指标不可评，则hold，不宣称有改善。报告核对输入身份、证据SHA，并从原评分产物重算摘要后才用于门槛判断。生成失败或输出截断保留原始记录，不能用GT或安静模板替代。

## 命令

以下命令为用户明确分配资源后的手动操作，不存在自动队列。候选路径仅作示例。

```bash
PY=/private/liqi_workspace/project_code/Omni-LTX-stage2/.venv/bin/python
CFG=/private/liqi_workspace/project_code/audio-driven-v5/experiments/p2_stage2_joint_candidate_full6000_20261108/config.json
OUT=/private/liqi_workspace/project_code/audio-driven-v5/experiments/p2_stage2_joint_candidate_full6000_20261108

# 新的模型选择应prepare到新目录，显式提供parent-config/checkpoint/adapter/validation。
"$PY" scripts/p2_stage2_joint_train.py --help
"$PY" scripts/p2_stage2_joint_train.py preflight --config "$CFG"
"$PY" scripts/p2_stage2_joint_train.py commands --config "$CFG"

# 首次只检查GPU能力、保存step0，不进入正式更新。
"$PY" scripts/p2_stage2_joint_train.py launch --config "$CFG" --logs "$OUT/launch_step0"

# 在node11运行；其余评测同样改step为100或300。
CUDA_VISIBLE_DEVICES=7 "$PY" scripts/p2_stage2_joint_train.py evaluate --config "$CFG" --step 0

"$PY" scripts/p2_stage2_joint_train.py launch --config "$CFG" --resume "$OUT/step_000000.pt" --logs "$OUT/launch_to100"
CUDA_VISIBLE_DEVICES=7 "$PY" scripts/p2_stage2_joint_train.py evaluate --config "$CFG" --step 100
"$PY" scripts/p2_stage2_joint_train.py decide --config "$CFG" --step 100

# 仅当DECISION_000100.json的decision为continue_to_300：
"$PY" scripts/p2_stage2_joint_train.py launch --config "$CFG" --resume "$OUT/step_000100.pt" --logs "$OUT/launch_to300"
CUDA_VISIBLE_DEVICES=7 "$PY" scripts/p2_stage2_joint_train.py evaluate --config "$CFG" --step 300
"$PY" scripts/p2_stage2_joint_train.py decide --config "$CFG" --step 300
```

本组输出目录的`STOP`保留当前更新并完整保存退出；它不会停止其他实验。恢复只允许本组完整检查点。候选目录已有三个阶段的命令清单，但没有run.json或联合训练权重。

## 验证边界

27项测试通过：原生小型Qwen文本模型＋真实PEFT＋原生小型LTX，覆盖AV／Feature／LTX Event分别反传到原规划LoRA、冻结基础权重、逐token CE／EOS、完整联合Adam下一步逐值恢复、两进程实际Gloo SUM与单进程累积逐值一致、归一化、原检查点加载、禁用缓存和门槛合同。32条真实混合缓存回读通过，另将冻结H reader的load设为直接报错后读取真实样本成功，证明训练组装不读取旧H payload。

全量验证区间排除、190,987条SFT交集caption SHA以及64条参考媒体已实际检查。尚未执行本组完整规模GPU反传、31卡NCCL、显存／步速或64条真实模型生成评分；这些由启动检查和显式评测命令完成，不能把CPU验收当作已经测得收益。
