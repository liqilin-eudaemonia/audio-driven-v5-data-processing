# Speaker Whisper 缓存：预取、编码、写盘重叠

2026-11-04，`speaker-whisper-prefetch-v2`。已更新代码及后台接续配置；当前仍等待打标完成。只处理原500h训练集285,638条的speaker音频，不启动训练。

## 已应用的历史经验

参考v4总索引指向的 [Whisper全量缓存方案](../../audio-driven-v4-p3-whisper-offload-20261017/docs/P3_WHISPER_FULL_AUTOPILOT_20261017.md)，复用每卡常驻Encoder、窗口合批、跨批次音频预取、FP32且关闭TF32、启动前短／跨窗一致性检查与逐条原子发布。旧方案是三机24卡、窗口batch8、4读取线程，本次四机32卡，窗口batch16、4读取线程。

当前配置：

| 项目 | 实际配置 |
|---|---|
| 模型 | 冻结Whisper-large-v3 Encoder，每卡一个常驻实例 |
| 窗口batch | 16；尚未声称是GPU实测最优值 |
| 音频准备 | 每卡4读取线程，当前批＋下一批双缓冲 |
| 写盘 | 每卡1个后台线程，最多1批待写结果 |
| 计算线程 | 每卡2个CPU计算线程，OpenBLAS=1 |
| 数值 | FP32，关闭autocast，最高FP32矩阵精度，显式关闭matmul／cuDNN TF32 |
| GPU启动检查 | 每卡实际Encoder对比逐条与合批，短音频23056点、跨窗音频432123点；填满配置batch |
| 一致性标准 | hidden：atol=1e-4、rtol=2e-4；时间和valid掩码逐值相等 |
| 全量终检 | GPU提取结束后，由CPU16读取线程校验，分256条有界提交 |

流程是：GPU编码当前批时，CPU准备下一批；GPU编码下一批时，后台保存和校验上一批。两处重叠均有事件同步测试证明，输入和待写结果数量有界。没有把全部音频一次性读进内存。

每个worker先用实际模型做合批／逐条检查。失败时写 `validation/rankNNN.json`，且不发布该worker的新生产特征；CPU读取异常和后台写盘异常都会向主进程传播，不会报告 `finished=true`。已有完整缓存仍按原契约和payload SHA验证后复用。

长音频继续采用30秒编码窗、26秒保留核心、两侧最多2秒上下文；不改变50Hz／1280维输出，不去掉前导静音，不使用listener目标音轨，不新增WAV。每条的来源、采样点数和20ms时间网格继续校验。

## 验证和性能边界

- **80项CPU回归通过**，含新增8项提速测试、原架构、原仅AV及矩阵训练、接续门控和专用CLI；[JUnit记录](../experiments/p2_j_qwen_whisper_av_codecheck_20261104/prefetch_v2_tests.xml)。
- 真实Whisper-large-v3与真实3.115秒speaker样本，对照保留的原CPU缓存：`[1,156,1280]`，hidden最大误差0、时间和掩码逐值一致；[原始记录](../experiments/p2_j_qwen_whisper_av_codecheck_20261104/prefetch_v2_real_sample_regression.json)。这是CPU数值回归，不是GPU测速。
- 每张卡的实际GPU检查在资源释放后、正式特征写入前自动执行，结果保存到新缓存目录 `validation/`。本次没有为了提前测速占用正在打标的卡。
- 吞吐尚无本轮GPU实测，不能宣称提速倍数或batch16最优。worker进度新增 `prefetch_wait_s / encode_s / write_wait_s / elapsed_s`，用于运行后定位等待。`encode_s`包含预处理、编码及结果回传，不能直接当作纯GPU核时间。
