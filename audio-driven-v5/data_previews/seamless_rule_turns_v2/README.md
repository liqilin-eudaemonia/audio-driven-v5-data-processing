# 规则话轮 V2：按主话轮切分的倾听音视频

本版遵照用户“先不用别的模型，按规则裁剪”的要求。**没有运行 Qwen、其他语言/音频模型、新 ASR 或新 VAD。** 仅使用同一批 50 个 Seamless interaction 的现有转写、词级时间戳、VAD、关键点和情绪特征。

## 查看

Cursor 已转发的端口仍为 8875。新版位于 `http://127.0.0.1:8875/rule_turns/`。第一版文件仍保留，便于对照。

- 每人 512×512，带独立音轨；双人对照 1024×512、25 FPS。
- 页面显示完整主话轮范围，以及当前导出的是完整话轮还是排除 listener 事件后的连续子区间。
- “完整会话与切点上下文”含双方混音，可以播放切点前后各 5 秒、整个主话轮或自由浏览。
- 完整会话左右人物位置固定；页面标明他们在当前导出片段中的 speaker/listener 身份。脸部对照始终是 speaker 左、listener 右。
- 显示父话轮内全部 listener 事件、保留/排除状态，点击事件可试听前后上下文。
- 反馈保存在独立的 V2 浏览器存储中，可导出 JSON；不会把第一版同序号片段的备注套用到新片段。

## 核心区别

**主话轮不因 speaker 停顿而结束。** 对方没有满足接管规则时，当前主话轮持有者保持不变。VAD 与词时间用于估计双方发声证据，不直接作为话轮分割点。

本次对 50 个会话全部进行规则标注，得到 314 个候选主话轮、457 个已成功导出的连续倾听区间，合计 7038.172 秒。最终成功导出数量和失败原因见 `manifest.json`、`validation.json`；原始全部边界见 `annotations/`。这是规则产生的标签，不是已由语义模型或人工确认的真实话轮。

## 主话轮状态与接管规则

1. 根据现有 ASR 句段读取发言事件，不再按 0.55 秒词间停顿生成话轮。
2. 最早出现的非反馈短语、至少 4 词的句段建立初始主话轮。
3. 对另一人的非反馈发言，从其起点查看之后 8 秒的双方证据。计数和发声时长只统计不属于反馈短语句段的词；词时间区间取并集，避免重叠重复累计。
4. 满足下列任一条件，才产生接管候选；距上一话轮起点至少 2.5 秒，抑制短时间反复切换：
   - **原持有者基本让出：** 对方至少 4 个内容词、词区间覆盖至少 0.65 秒；原持有者最多 1 个内容词、覆盖不超过 0.3 秒。
   - **持续接管：** 对方至少 8 个内容词、覆盖至少 1.6 秒；原持有者最多 3 个内容词、覆盖不超过 1 秒。
   - **重叠中占优：** 对方至少 8 个内容词、覆盖至少 1.6 秒，覆盖时间至少是原持有者的 1.5 倍，且内容词数至少多 4 个。
5. 接管边界落在触发接管的句段实际起点，**不会等 8 秒观察窗结束才切**。8 秒是离线确认窗口，不是固定话轮长度。
6. 对于短问句，如果问句不超过 4.5 秒、10 词，原 speaker 在问句结束后 6 秒内继续至少 5 个内容词，则优先标为澄清问句候选，不自动交换主话轮。
7. 最后一个主话轮结束于最后的已标注发声/转写之后 0.2 秒，并限制在原始会话长度内。

这些词数、时间和优势阈值用于**比较双方是否发生接管**，不是“停顿超过阈值就结束话轮”。由于没有语义判断，接管起点仍可能偏早或偏晚，页面保留对应量化证据与上下文。

## Listener 事件

| 标签 | 规则与处理 |
|---|---|
| `feedback_candidate` | 不超过 3 秒、7 词，且完整文本匹配保守反馈短语/词集合；保留。包括 Yeah、Uh-huh、I see、I love that 等。前缀匹配不算，例如“Yeah, but I have another idea”不被当成反馈 |
| `clarification_candidate` | 满足上述短问句与原 speaker 继续发言条件；排除 |
| `interruption_candidate` | 不匹配反馈且未触发接管，同时与 speaker VAD 重叠或 speaker 在其后继续；排除 |
| `uncertain_speech` | 其余无法由规则解释的 listener 转写；保守排除 |
| `overlap_from_previous_turn` | 新话轮开始后，上一位主讲者仍延续此前句段；排除该重叠部分 |
| `untranscribed_vocalization` | VAD 与现有转写覆盖交集不超过其时长 20%；不超过 3 秒时保留为待复核发声，超过 3 秒则排除。不能据此断言是笑声或 backchannel |

反馈短语只是可复现的规则候选。反问、简短回答、讽刺或其他表达可能误入；未列入短语表的真实反馈也可能被误排除。`VAD only` 不代表已确认是非语言声音。

## 从话轮到连续倾听区间

- 给排除事件前后各留 0.15 秒余量，从父话轮中减去这些区间。
- 每个剩余区间独立导出，**不把插话前后拼接**，保留原时间。
- 小于 4 秒或 speaker 少于 4 个词的剩余区间只记入标注，不导出预览。
- 不再以固定 10–12 秒窗口或 speaker VAD 占比 50% 筛选；话轮内正常停顿保留。
- 所有合格的连续区间都尝试导出，不再每会话只抽 1–2 段。

## 裁剪与音轨

使用原始视频与独立逐人 WAV，源文件不修改。每个连续区间使用固定面部窗口，按已有关键点的稳健范围计算，保留头部运动。至少 80% 的帧需有足够有效面部点，否则记录失败。

因为整段话轮可能很长，本版不因裁剪窗口超过典型面部大小的 3.2 倍而重新缩短时间；改为标记 `wide_crop` 并在页面提示。这样不会为了裁脸好看而改变话轮边界。大幅位移会导致固定窗口更宽，是后续可讨论的裁剪优化点。

完整会话对照为 640×360、10 FPS；当前片段原画面对照为 640×360、15 FPS；它们用于检查时间和人物关系，脸部目标视频保持 512×512、25 FPS。单人音轨不做独立响度归一化，混音为双方各乘 0.5 后相加。

## 文件与复现

- `annotations/<pair>.json`：全部主话轮、逐事件标签、排除区间和待导出区间。
- `manifest.json`：成功渲染的片段、源定位、边界证据、完整会话地址、裁剪参数和失败原因。
- `annotation_summary.json`：渲染前的规则统计。
- `media/<pair>/conversation.mp4`：完整会话及双方混音。
- `media/<pair>/clip_XXX/`：脸部双人对照、双方单独 512×512 MP4、各自试听音轨、原画面对照和元数据。
- `rules` 字段：本批使用的阈值；所有结果都带 `segmentation_revision=2`。

```bash
python scripts/test_rule_turns.py
python scripts/build_seamless_rule_turns.py --render --workers 12
python scripts/publish_rule_turns_preview.py
```

如修改规则，需要使用新输出目录或清理本批生成缓存，避免复用旧边界对应的媒体。该脚本的断点续跑仅适用于规则未变化的同一次构建。
