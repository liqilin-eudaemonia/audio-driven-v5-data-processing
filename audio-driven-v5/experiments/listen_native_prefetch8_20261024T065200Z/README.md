# 原生视听 CPU 媒体预准备吞吐对照

用户指出 8 卡利用率低后进行的独立性能检查，不替换简短 prompt 的 50 段结果。

8 个副本各运行相同 8 段，共 64 次请求。GPU 0–3 使用 1 个 CPU 准备客户端，GPU 4–7 使用 4 个客户端提前准备媒体。所有副本保持单请求 GPU batch、原生视听对齐参数、模型、51 词 prompt、生成参数一致。`plan.json` 的 8 请求是每副本计划，总计划见 `performance_plan.json`，实际完成数见 `status.json`。

从模型 ready 到完成的平均时间：45.01 秒 → 30.72 秒，减少 31.74%，速度比 1.465。此时间不含模型加载；4 对 4 副本同时运行，属于小规模同机对照，不能直接外推全量吞吐。

8 个副本对每个样本的原始输出完全一致。64 次中 48 次通过时间等校验，16 次为同两个样本在各副本上重复出现的时间无效；性能优化没有修复或隐藏这些标注问题。

`performance_result.json` 保存每卡实测时间与 GPU 观测值，`resources.jsonl` 保存每 5 秒资源及 worker 状态；GPU 仍未持续满载。全部 worker 正常退出，结束后显存释放见 `resources_after.json`。

后续工作代码允许每卡最多 4 个 CPU 准备客户端，GPU batch 仍为 1；单卡启动器默认采用 4。推理快照保持本次实测版本，未修改历史实验。
