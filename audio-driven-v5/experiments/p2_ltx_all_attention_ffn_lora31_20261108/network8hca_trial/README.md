## 实际结果

生产训练完整保存并停于step811。冷入口、当前284218段清单、采样计划、282源码身份和启动wrapper预检通过。首先用31卡做八网卡通信预检；NCCL日志确认识别mlx5_0–7八张RoCE网卡，但第一个集合通信在90000ms超时。没有进入完整模型ABBA测速，因此没有可报告的端到端提速或降速数据。

NCCL日志见smoke8/rank00.log；原始启动参数见smoke8/COMMANDS.json。网卡ACTIVE／NCCL能枚举设备，不等于当前四机的多网卡互联已通过验证。

## 资源干扰与恢复

测试期间node11 GPU7启动了独立的p2_vico_dim_best10.py评测（约59GB），启动时间1794147745.8，处于通信测试尚未结束的时段。恢复31卡训练被空卡检查拦截。用户明确选择暂停此评测、立即恢复31卡训练后，仅停止其控制器1278570和工作进程1356555，既有结果保留；node11 GPU0评测保持。

按用户最新优先级结束进一步测试，恢复原单网卡配置，从step811完整模型／Adam／31份RNG接续。RESUMED_ACCEPTED.json生成后表示已确认继续真实更新。正式训练配置、网络和核心源码未改；未采用八网卡，也未触发其他训练队列。

本轮结论为：尚无八网卡提速证据，通信兼容性预检未通过，且测试后段存在资源干扰；不能把这次结果表述为已完成干净的单／八网卡吞吐对照。历史八网卡方案需要在当前四机独占资源条件下重新验证，不能直接照搬。
