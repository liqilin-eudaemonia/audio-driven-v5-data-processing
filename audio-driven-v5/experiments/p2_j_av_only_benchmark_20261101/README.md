2026-11-01，测试完成，正式仅AV训练尚未启动。当前AV＋Event训练已正常停在4,201步；第4,200步及退出时第4,201步权重均完整保留、SHA256校验通过，见 [ORIGINAL_SAVED.json](ORIGINAL_SAVED.json)。

## 实测结果

四机各8张H200，保持global batch=32、相同初始参数、样本顺序、随机数和优化器。只改变LTX梯度重算策略。

| 测试 | 更新步数 | 平均步时 | rank0 PyTorch峰值保留显存 |
| --- | ---: | ---: | ---: |
| 隔层重算，包含最长11.95秒样本 | 16 | 6.387秒 | 127.81GiB |
| 全层重算，同一组时长对齐批次 | 32 | 4.027秒 | 50.25GiB |
| 隔层重算，同一组时长对齐批次 | 32 | 3.642秒 | 127.75GiB |
| 隔层重算，16步保存退出＋恢复16步 | 32 | 3.754秒 | 127.94GiB |

32步配对结果：隔层重算使步时降低 **9.6%**，吞吐提高 **10.6%**；去掉两步预热后，步时降低9.8%。表中不包含模型冷启动及最后保存的时间；恢复组的步时也不包含重启加载时间。不同长度批次不能直接比较，因此第一行仅用于最长样本压力验证。

四机GPU遥测峰值显存约127.3—129.5GiB，各节点采样到100%GPU利用率。峰值不是全程均值，不能据此认定所有时刻均无等待。[GPU采样汇总](gpu_summary.json)

首选已设置为 `gradient_checkpointing=alternating`，保留BF16、512窗口时长分组、32MiB梯度通信桶、NCCL/IB配置和128GiB PyTorch显存上限。这是当前保持同数据、同batch、同数值策略下，通过最长样本验证的实测更快配置，不宣称覆盖所有可能组合的全局最优。

完全关闭重算未作为全量默认候选：此前真实实验仅7.872秒样本已占约136GiB，不能覆盖本轮最长11.95秒的数据。依据见 [既有24卡加速记录](../../related/P2_24卡联合训练GPU验证与提速.md)。
