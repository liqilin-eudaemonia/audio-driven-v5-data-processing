# P2 倾听事件监督：代码准备与运行说明

日期：2026-10-23。当前状态：**独立代码、配置、数据接口及 CPU 验证已准备；等待用户提供真实数据，未运行真实 Omni/LTX 缓存、GPU S0 或正式训练。**

设计依据：[实验计划](P2_倾听事件监督实验计划.md)、[代码修改要求](P2_倾听事件监督代码修改要求.md)。总入口：[README](../README.md)。本次没有修改旧 v4 P2、v5 P3 或生产 QC4 筛查逻辑，没有挑选用户尚未提供的数据替代正式实验输入。

## 1. 已实现内容

| 部分 | 入口 | 当前实现 |
|---|---|---|
| 独立命令行 | [scripts/p2_listen.py](../scripts/p2_listen.py) | prepare、import-labels、cache、audit、train、generate、evaluate、report |

| 标签/时间轴 | [annotations.py](../src/p2_listen/annotations.py)、[layout.py](../src/p2_listen/layout.py) | 两类独立事件、coverage/unknown、soft occupancy、边界截断屏蔽、实际秒数聚合 |

| 无数据检查 | [CPU 测试入口](../scripts/check_p2_listen_code.py)、[CPU DDP 检查](../scripts/check_p2_listen_cpu_ddp.py) | 合成张量和临时生成媒体，不加载预训练权重，不使用正式数据 |

当前接口与原设计的具体化：

- 导入清单使用 JSON 数组或 JSONL；内部保存 `manifests/observations.json`、`targets.json`、`admission.json`，不是设计草案中的固定 JSONL 后缀。
- 新增必填 `grouping_ids`，记录双方参与者/session，用来检查跨 split 身份重复；不输入模型。
- 事件来源通过 `provenance.media_hashes` 绑定目标音视频，而非单一不明确的 `media_sha256`。
- `audit` 当前提供 `config/data/cpu` 三种 suite；细项隔离/时间/梯度/恢复由测试覆盖，真实单卡 S0 另记录梯度路径。未把设计中的每个细项都暴露成独立命令。
- 外部标注模型调用已有独立的 [Joy + 音频模型打标客户端及 Omni 对照入口](P2_倾听事件自动标注实现与运行.md)，支持人工修订后导入；目前只通过模拟 HTTP 与合成媒体验证，真实模型/数据联调待完成。QC4 自动挑样和自然度盲评仍由后续数据/评测工作完成，不把自己的事件头当裁判。
- 正式 checkpoint 的 dev32 生成矩阵和后续第二个训练 seed 由明确命令运行；不在训练结束后自动占用 GPU。训练代码已有确定数据顺序与恢复，不承担全量自动实验调度。

## 2. 当前验证证据与限制

- [unit_tests.json](../experiments/p2_listen_code_validation/unit_tests.json)：P2 专项 CPU 测试、实际 Python 版本、文件 SHA256。覆盖输入隔离、时间/unknown、缓存、梯度、恢复、CFG、临时媒体导入和事件评测。
- [cpu_audit.json](../experiments/p2_listen_code_validation/cpu_audit.json)：真实旧 P2 模块的小尺寸实例运行 5 步合成更新；E0 的事件到 U 梯度为 0，E1 的两个模态梯度非零；保存恢复后的下一步参数完全一致。
- [cpu_ddp.json](../experiments/p2_listen_code_validation/cpu_ddp.json)：2 个 Gloo CPU 进程，含梯度累积和不均标签覆盖；对照单进程有效 batch 的参数误差小于 `2e-5`。
- 预定真实运行环境中的 PyAV、SoundFile、P2/LTX 模块与 `i2av_only` 配置已完成导入检查，没有加载预训练权重。

这些检查**不是实际 Omni/LTX 的 S0**。真实数据到位后仍需验证：感知塔输出与网格的实际形状、VAE/音频端点支持、全尺寸显存、冻结 DiT 的真实梯度、一次完整生成与音视频质量。这些未知不以“测试通过”代替。

视频向上对齐 `8k+1`，不截掉真实句尾；尾部不参与有效监督。音频 centered STFT + causal 下采样可能多出一个端点 latent：只允许删去该一个超出 renderer 预算的端点，并记录 `audio_endpoint_tokens_removed`；其他 shape 不匹配直接报错。音频 mask 另屏蔽 STFT 右侧支持余量。真实 S0 必须核对具体基座的该契约。

## 3. 数据如何接入

示例目录：[examples/p2_listen](../examples/p2_listen/README.md)。文件是占位格式，不是可训练数据。用户可先提供其现有清单/路径，后续由代码适配，不要求手工填写示例。

每段需要：speaker 音轨、listener 首帧、listener 目标视频及自身音轨、片段时长、双方参与者/session 来源、数据质量准入状态；事件起止与 unknown/coverage 可随后补充，但训练前必须有合法标签。

当前 `prepare` 导入**已经切好且对齐的片段**：默认 25 FPS、512×512，时长完整，不超过对齐后的 201 帧 pilot 预算。它不会从原始长视频自动切窗或改 QC4 的生产规则。路径相对输入 JSON 所在目录解析；目标 `admitted=false` 会拒绝导入，防止占位样本进入实验。

推理仅需 observation，包含明确的外部时长/几何；目标和标签只在训练、缓存目标或独立评测时打开。修改事件标注不会要求重新提取 H，但需要使用新的标签/实验版本，不允许绕过缓存身份检查继续训练。

## 5. 数据到位后的首个 S0 命令顺序

以下 `/path/to/...` 是待替换路径，本次没有执行。先使用 8–16 个 train 和约 8 个 dev 样本；建议复制基础配置并设置独立 `output`，完整 pilot 将使用另一份清单/输出目录，避免小集与全量身份冲突。

```bash
cd /private/liqi_workspace/project_code/audio-driven-v5
# 1. 导入并校验已经准入的对齐片段；只做数据工作。
/private/liqi_workspace/project_code/Omni-LTX-stage2/.venv/bin/python scripts/p2_listen.py prepare --config /path/to/s0_config.json --observations /path/to/observations.json --targets /path/to/targets.json
# 2. 导入人工核验的小集标签。
/private/liqi_workspace/project_code/Omni-LTX-stage2/.venv/bin/python scripts/p2_listen.py import-labels --config /path/to/s0_config.json --labels /path/to/events.json
# 3. 对已分配的空闲 GPU 准备缓存；device 示例由实际资源替换。
/private/liqi_workspace/project_code/Omni-LTX-stage2/.venv/bin/python scripts/p2_listen.py cache --config /path/to/s0_config.json --part all --split train --device cuda:0
/private/liqi_workspace/project_code/Omni-LTX-stage2/.venv/bin/python scripts/p2_listen.py cache --config /path/to/s0_config.json --part all --split dev --device cuda:0
# 4. 两组从相同 seed/初始化分别做 5 步真实检查。
CUDA_VISIBLE_DEVICES=0 /private/liqi_workspace/project_code/Omni-LTX-stage2/.venv/bin/python scripts/p2_listen.py train --config /path/to/s0_config.json --arm E0 --train-seed 20261023 --s0 --steps 5
CUDA_VISIBLE_DEVICES=0 /private/liqi_workspace/project_code/Omni-LTX-stage2/.venv/bin/python scripts/p2_listen.py train --config /path/to/s0_config.json --arm E1 --train-seed 20261023 --s0 --steps 5
```

基线 `E0` 对应 `probe_only`，实验组 `E1` 对应 `joint_event`。单卡实际 S0 会检查事件路径及 AV 到两个 U 的梯度，所有真实步检查冻结 renderer 未改变。`--s0` 不会自动只挑前 16 段，样本范围由这份独立清单明确决定。

需要时再用 torchrun 启动匹配 global batch 的多卡任务，例如：

```bash
CUDA_VISIBLE_DEVICES=0,1 /private/liqi_workspace/project_code/Omni-LTX-stage2/.venv/bin/python -m torch.distributed.run --standalone --nproc-per-node=2 scripts/train_p2_listen_distributed.py --config /path/to/s0_config.json --arm E0 --train-seed 20261023 --s0 --steps 5
```

不同 world size 或预算不能冒充同一 run 的严格恢复；多卡检查使用独立输出配置。已有 run 要使用其检查点 `--resume`，不接受回退旧 checkpoint 后向较新日志继续追加。`STOP` 文件放在具体 arm 的运行目录，下一次 optimizer step 前检查并保存当前状态。

## 6. 生成与事件评测

单个 observation JSON 是数组清单中的一条对象，不包含 target/label 字段。正常生成命令示例：

```bash
/private/liqi_workspace/project_code/Omni-LTX-stage2/.venv/bin/python scripts/p2_listen.py generate --config /path/to/s0_config.json --observation /path/to/one_observation.json --checkpoint /path/to/step_000005.pt --output /path/to/new_generation --seed 137 --device cuda:0
```

输出包括 `generated.mp4`、独立 `listener.wav`、原始解码音频、probe logits 和成功/失败记录。保留原始 `padded.mp4` 供核对几何，正式展示/评价使用真实支持范围。`text_only` 不需要 checkpoint；`remove_u` 从两分支同时移除 U；`audio_swap` 需要同长度替换音轨并重新计算 H。

test 生成必须提供 `--release` JSON，至少含 `config_sha256`、允许的 `checkpoint_sha256` 数组、`sample_ids`、`seeds`；锁定后才生成，不自动释放 test。S0 使用 train/dev。

独立人工/检测器得到的生成事件结果格式为 JSON 数组或 JSONL，每条至少包含：

```json
{
  "sample_id": "example_0001", "train_seed": 20261023,
  "arm": "E0", "sample_seed": 137,
  "status": "success", "independent_verified": true,
  "events": [{"type": "head_nod", "start": 1.2, "end": 1.7}]
}
```

成功输出必须有独立核验；失败输出写 `status=failed`、`events=[]`。缺少预定生成记录会报错，不能悄悄按成功子集计分。时间为片段内秒数。

```bash
/private/liqi_workspace/project_code/Omni-LTX-stage2/.venv/bin/python scripts/p2_listen.py evaluate --protocol /path/to/locked_protocol.json --observations /path/to/observations.json --references /path/to/reference_events.json --predictions /path/to/generated_events.jsonl --output /path/to/results.json
/private/liqi_workspace/project_code/Omni-LTX-stage2/.venv/bin/python scripts/p2_listen.py report --results /path/to/results.json --output /path/to/report.md
```

`evaluate` 不用训练头打分。报告按参考一致性给出事件结果，`quality_assessed=false` 明确提醒自然度/音质/角色保持仍需盲评。当前没有任何真实模型效果结果。
