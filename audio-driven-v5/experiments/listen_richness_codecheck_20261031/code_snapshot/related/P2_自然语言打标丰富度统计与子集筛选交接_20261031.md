# 自然语言打标丰富度统计与子集筛选交接

2026-10-31。**代码准备与 CPU 验证完成；尚未运行真实30B行为提取或全量筛选，未替换训练数据。**

## 1. 用途与边界

对现有J切分Omni整段描述建立独立筛选信息：时间证据统计＋文本模型提取开放行为＋原始人脸测量，再选取“主体集＋稀有行为补充”。不重新打时间戳、重新ASR、写WAV或修改caption、净化配方和缓存。训练描述仍是原文。

统计对象是描述中的行为与检测候选，**不是人工真值或精确动作次数**。原记录 `training_admitted=false` 不直接等于没有使用价值；本工具独立判断筛选资格，但不自动授予训练准入。

适配 `experiments/listen_j_omni_20261030/`，不把旧722,706段七类事件结构混入新J结果。

## 3. 数据读取和统计

`prepare --work` 从 `ready.jsonl → jobs/<job_id>.json` 读取清单，再按sample ID哈希定位caption，**不递归扫描结果目录，不读取媒体内容**。当前未生成caption的片段计为 `not_yet_captioned`，不是无回应或打标失败。

- 核对source的sample、listener/speaker、原视频成员、split/group、源起止时间及音轨身份。
- 保留历史旧框来源；存在 `crop_provenance` 时校验原框、实际框、测量与source哈希。
- 核对 `visual_quality` 的measurement SHA256和质量合同。旧caption未内嵌验收时，`--work` 自动读取同pair的 `visual_quality/measure/completed/` 回执；`--manifest` 模式需显式提供 `quality_decision`。缺失、冲突写入DB errors，不默认放行。
- 画质未通过、生成截断或review_flags不为空的样本退出自动提取。
- 点头核对同一sample、25fps、recall和合法片段相对时间。分别保存原始条数、相同边界去重后的候选区间数、区间并集时长；`exact_nod_count=null`。
- 官方词／句／VAD先裁到当前片段，再按生产代码相同的样本取整、并集、padding和fade计算。**配方时间已是片段相对时间，不再减源起点。** 不额外跨越空隙；支持区间数不等于词数。
- 分别记录 `official_core_s`、`nominal_keep_s`、`mask_positive_s`，不把它们当作实测发声时长。`waveform_full_silence`沿用生产波形检查。配方SHA256、采样率、时间原点、音频样本范围均检查。
- 本版仅接受当前J的官方并集政策；发现其他净化政策或额外静音规则时拒绝近似套用。
- 人脸p10/p50来自原图真实人脸宽高，不是512裁框。无检测是未知；`face_sample_detection_fraction`是**采样测量覆盖率**，当前测量5fps，不能宣传成原视频所有帧的有效率。清晰度沿用已有验收。

## 4. 文本模型与原文保障

默认 `/private/ckpts/Qwen3-30B-A3B-Instruct-2507`，连接已有OpenAI-compatible `/v1/chat/completions` 服务。模型名可显式指定为服务名称。temperature=0，max_tokens=8192，默认并发2、最多尝试2次；不会自行启动服务或抢占生产显卡。

模型只接收caption，不接收检测器区间数和官方发声区间，避免把候选证据误当原文事实。输出格式示例：

```json
{
  "behaviors": [{
    "id": "b1", "behavior": "head nodding",
    "modality": "visual", "polarity": "positive", "form": "change",
    "quote": "The listener nods twice.", "attributes": [],
    "repeat": {"kind": "explicit", "count": 2, "quote": "twice"}
  }],
  "relations": []
}
```

该quote必须实际出现在原文。行为名开放，不限定七类；不从投入／思考／同意推断动作，不把下视当点头、张嘴当发声。一句多个可见动作分别保留；持续状态只提一次。未明示次数时count为null；不输出起止时间。顺序和同时关系必须有原文明示依据。

代码检查完整JSON、固定字段、唯一ID、原文子串、修饰语／次数依据属于引用、明确次数有字面数字支持、关系ID与无循环顺序。失败保存原始回复，带校验错误重试；仍失败记为failed，不伪造空动作成功。

**结构和引用校验不能证明语义归类、否定理解或动作覆盖完全正确。** 上线前仍需真实30B小批复核。原始caption、提取结构和每次原始响应均保存。

统计时，同类持续表述只计一个类型。点头在caption和检测器都有时，只挂两份证据，不增加一倍动作数。仅检测器有时保留独立候选，不伪装成原文正例。明确否认点头却存在候选、全零波形却有正向音频描述，均标记一致性冲突并退出自动筛选。

### 同义表达

prompt要求稳定的简短普通动作名；不做模糊字符串合并。统计别名可用 `--aliases` 提供：

```json
{"schema":"listen-richness-aliases-v1","reviewed":true,"aliases":[
  {"modality":"visual","alias":"smile","canonical":"smiling"}
]}
```

仅改变统计分组，不改变caption、quote和提取原始行为名。拒绝循环、多跳别名。**默认不假定开放词表已完全消歧**；pilot需检查catalog里的同义重复和伪稀有类别，再冻结别名版本。更新别名后重导出统计即可，无需重跑提取。类型始终注明 `caption_extracted_candidate`。

## 5. 初版筛选参数

下列参数是代码的明确初版建议，尚未在新J数据上验证为最优：

- 50h，约90%主体、余下补充稀有行为和主体补足；保留完整片段，最后一段可小幅超过目标。
- 主体人脸p10≥224，补充最低160，同pair最多8段。没有自动使用300h的放宽规则。
- 人脸采样检测覆盖≥98%，清晰度测量覆盖≥80%，仍须上游画质判定通过。
- 按2秒时长区间分组，文字类型数和封顶变化密度做组内分位；密度分母至少5秒。
- 初版分数：45%人脸大小＋30%行为多样性分位＋20%变化密度分位＋5%点头检测支持。末项是证据支持，不增加动作计数。恒定／零维度不制造分位奖励。
- 每类变化得分最多3，smiling/blinking最多1；“多次但次数不明”只给封顶得分，不回写成两次。持续状态不增加变化得分。
- 主体内先尝试预留总时长5%的安静／持续状态候选：波形全静音、无点头候选、文字变化得分0。不是人工确认无动作；不足会报告。该比例可调，并非此前已确认的固定政策。
- 稀有行为按候选pair数排序，初版目标每类尽可能覆盖3个不同pair；优先同时补多个缺口，再按大脸和丰富度。未覆盖写入 `coverage_gaps`。
- 不自动降低门槛；主体不足或总时长不足返回退出码2并报告缺口。

必须提供完整权威catalog，检查全体train/dev/test的group/session/person跨划分冲突。只取train，选中样本pair、split、group、双方ID与catalog一致；同pair源时间不能重叠，即使listener方向相反也检查。catalog未覆盖的来源退出候选，不根据文件名猜划分。

## 6. 命令与续跑

项目根目录执行。以下为后续运行示例，**本次未执行全量或真实模型步骤**。

```bash
# CPU统计默认最多200个已有caption；--limit 0才表示不限量。
python scripts/listen_richness.py prepare \
  --work experiments/listen_j_omni_20261030 \
  --db experiments/listen_richness_pilot/stats.sqlite --limit 200

# 从已准备的pending记录分层抽样。
# DB若只有前200条，这仍是局部验证，不能称全量随机抽样。
python scripts/listen_richness.py pilot \
  --db experiments/listen_richness_pilot/stats.sqlite --count 200 --seed 20261031 \
  --output experiments/listen_richness_pilot/pilot_ids.json

# 导出请求，仅准备输入，不调用模型。
python scripts/listen_richness.py requests \
  --db experiments/listen_richness_pilot/stats.sqlite \
  --ids experiments/listen_richness_pilot/pilot_ids.json \
  --output experiments/listen_richness_pilot/requests.jsonl

# 有明确分配的文本模型服务后才执行；8000为示例端口。
python scripts/listen_richness.py extract \
  --db experiments/listen_richness_pilot/stats.sqlite \
  --ids experiments/listen_richness_pilot/pilot_ids.json \
  --endpoint http://127.0.0.1:8000/v1 --workers 2 --limit 200

python scripts/listen_richness.py export \
  --db experiments/listen_richness_pilot/stats.sqlite \
  --output experiments/listen_richness_pilot/export_v1 --parquet

# 200条不足50h时预期报告缺口；实际选集需要足量已提取候选。
python scripts/listen_richness.py select \
  --db experiments/listen_richness_pilot/stats.sqlite \
  --catalog data_corpora/seamless_listen_local_full/catalog.json \
  --policy configs/listen_richness_selection_v1.json \
  --output experiments/listen_richness_pilot/selection_v1
```

示例catalog沿用既有格式，全量选新J数据前应核对覆盖范围；未纳入权威catalog的pair计入 `missing_catalog_pair`，不会默认放行。

`extract --retry-failed` 重试失败记录，成功记录不重复提交。最大并发32个在途请求；不可把视觉batch512直接当成文本模型并发设置。

离线 `import-responses --responses responses.jsonl` 每行需：sample_id、snapshot_sha256、完整extraction_contract、finish_reason="stop"、extraction；前三项从requests.jsonl复制。拒绝过期输入、不同模型合同、截断结果和覆盖已有不同的成功提取。

SQLite记录输入、代码文件SHA256、prompt／模型合同、状态和全部响应；代码／模型／已准备输入发生变化需新DB。操作同一DB采用排他锁；本版没有多机自动部署器。输入路径、限量和模型服务都须显式配置。

## 7. 输出及下一步验收

- `sample_stats.jsonl`，可选 `sample_stats.parquet`：逐段人脸、行为、点头和音频统计；Parquet嵌套字段用JSON字符串保存。
- `behavior_evidence.jsonl`：完整caption、原文引用、提取结构、统计分组与冲突。
- `behavior_catalog.json`：开放类型的片段／pair覆盖、原文例证、别名版本。
- `EXPORT_COMPLETE.json`：表示当前导出结束，需同时看pending/failed/errors；不是全量或语义验收完成。
- 选集导出 `selected_manifest.jsonl`、`selection_policy.json`、`selection_report.json`。保留原caption、源媒体变换、caption／配方哈希和入选原因。选中项再次核对原caption文件哈希。

manifest是筛选交付清单，**不是自动生成的新训练缓存配置**。训练仍须通过现有净化配方读取listener音轨，不能绕过配方直接读取原WAV。

真实30B pilot要检查复合动作遗漏、同义拆分、否定误读、无依据的心理类型、排序质量，再冻结参数及别名。默认有未解决记录时拒绝最终筛选；`--allow-partial`只用于显式试筛，报告保留partial状态。
