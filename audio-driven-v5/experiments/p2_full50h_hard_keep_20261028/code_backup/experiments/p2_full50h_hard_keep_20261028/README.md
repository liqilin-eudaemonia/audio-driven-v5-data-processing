# 完整新50h：硬处理结果保留、失败事件回退原文、审核意见仅记录

本入口取代`p2_new50h_guided_chain_20261027`的缩小成员实验。用户已明确确认：训练使用完整新50h，模型二次审核不得剔除样本；能安全整合的事件使用整合结果，其他事件保留原始描述和时间，不删除整段、不补写内容。

## 成员和训练顺序

- 输入仍是重新静音后筛选的29,975段新50h，全部train，resize为512×512；不是旧30,415段数据集。
- 构建必须核对29,975个sample_id全部覆盖、时长约180,000.532秒（50小时零0.532秒）。未完成构建不能宣称已全部恢复。
- 每阶段global batch=24、seed=20261023、**1,249步**（29,976个样本位置，覆盖完整一轮）。
- [串行24卡顺序](training_schedule.json)：先AV、AV＋Event、AV＋Feature、AV＋Event＋Feature四组冻结Qwen；再按同样顺序运行对应Qwen LoRA阶段。
- 每组独占三机24卡，每机8卡、每卡1样本、梯度累积1；每100步保存，保留严格断点恢复和TensorBoard。
- 四组S1从统一初始化重新开始，各S2只继承本轮对应S1最终权重。此前约15h的小子集AV训练保存于原目录第144步并停止，不用于本轮初始化。

## 整理规则

使用已有模型提案，无需再次生成整套整合提案。每条视觉来源必须有明确处理去向：

1. 按引用和冲突关系把原事件组成独立组。
2. 对每组调用交接原`compile_plan`和硬校验；可独立通过的组使用原文截取/安全整合结果。
3. 无法通过的组完整保留该组原始事件，描述、起止时间、有效区间不改。不存在可用提案、超长或无法安全截取也保留原文。
4. uncertain/non_observable来源同样保留原事件。任何来源都不能在没有安全对应关系时消失。
5. 全部音频事件逐字段保留，不从视觉推断声音，不重新ASR或静音。
6. 模型二次审核意见与原提案继续保留，只作记录，绝不控制样本是否进入训练；不伪造accepted=true。

`recovery/<sample_id>.json`记录安全整合来源、原文回退来源、失败原因、所选提案与原审核记录路径及哈希。审核意见针对原提案，不冒充对新拼接结果的审核。

最终`view/rejected.json`为空表示**没有排除训练成员**，不表示所有模型提案均通过硬校验。原来的19,082条拒绝原因仍保留在旧实验，不覆盖。

## 缓存与自动接续

- [恢复进度](RECOVERY_PROGRESS.json)、最终`RECOVERY_COMPLETE.json`。
- [三机单卡任务池](pool/state.json)。CPU用16个进程整理标注，每形成一块可用文本立即投递Gemma和Qwen缓存任务，三机最多24个GPU任务。
- 如果实际指导文本及完整条件身份与上一版相同，直接链接原条件缓存；发生改变的样本生成新缓存，旧缓存不覆盖。
- 原视频VAE、后处理音频VAE、事件缓存及冻结teacher沿用同一50h入口，不重新提取。
- `plans/samples/`为实际逐样本指导文本，格式沿用既有英文模板，原字段不翻译；`plans/cache/text/`和`input_plan/`为实际条件缓存。Qwen读取输入＋同一规划的全部hidden；S2在线重新forward。
- 全员恢复后自动启动原接续导演：缓存齐全 → 8路CPU校验 → 四条配对GPU短测并行 → [24卡串行训练](training_queue/state.json)。不得在最终缓存/GPU校验前将正式训练标为已启动。
- 原生缓存读取器仍检查身份、张量及SHA；没有降低缓存和训练有限值校验。
