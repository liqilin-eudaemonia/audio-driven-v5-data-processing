用户将node11物理GPU7整卡指定给推理，并要求补完此前训练后的工作。本轮只读取旧权重、在validation运行前向验证和进行CPU审计，优化器更新次数为0，没有启动训练或test43。

## 实际状态

第二轮VQ确实跑过20000步，但按验证总loss选中的best仍是第1步：14.636833；末次validation总loss为38.144559。predictor仍未训练。第20000步last权重未保存，无法直接检查末步模型或精确续训。

本轮只读验证未通过学习有效性检查。所存第1步模型的validation重建L1为12.198702，训练均值基线为12.264574，仅低约0.537%；码本使用94个token，没有证据表明是完全码本塌缩。第1步被选中不等于训练没执行，而是后续记录的验证总loss均未更低。

## 已确认偏差与未定原因

- 本地训练在`vico_l2l_retrain.py`里重新创建AdamW/Adam并固定lr1e-4，丢弃了官方setup返回的ScheduledOptim预热。官方默认VQ首步约3.952847e-9；本地首步约为其25298倍，1000步约25.30倍。这是明确的协议偏差，不应称为完整沿用官方训练方案。
- 官方归一化函数确实逐值复现，统计文件没有读错。但其scale是“各窗口时间标准差的跨窗口标准差”，不是全局标准差；在当前训练窗口上，标准化表情的全局标准差约4.20～10.56，需结合量化及重建loss进一步验证适用性，不能直接断言为实现错误。
- 保存标准用重建项＋量化项的总loss，但原日志未分别记录两项；初始化模型可能重建差而量化loss低，无法凭总loss确定各项的变化。
- 原实现只存best，没有保存last模型、optimizer及RNG，导致无法回看第20000步模型的重建效果。这是检查点实现缺陷。

以上是确认的偏差和待验证因素，不是已证明的单一根因。修复训练方案前，不能把这轮权重列为有效基线或直接接predictor/test。
