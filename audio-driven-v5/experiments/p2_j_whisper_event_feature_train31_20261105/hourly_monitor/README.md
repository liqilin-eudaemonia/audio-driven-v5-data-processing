# 每小时训练巡检

用户于2026-11-05授权：每小时检查四机训练状态，失败或持续变慢时诊断处理，直到训练完成。

`../hourly_patrol.py`为独立只读巡检进程，每3600秒核对四机训练PID、GPU状态、控制器实际进程身份、损失、五组梯度、完整检查点收据及近期步时。仅使用CPU，不改任何checkpoint绑定源码或配置；node8 GPU7明确排除，允许用户在其上运行其他任务。

已有train31控制器仍每约20秒检查进度及数值，负责故障隔离与从完整checkpoint恢复，最多5次尝试。本巡检不另起竞争恢复器，不因SSH失败或单次GPU低利用率杀训练。巡检发现问题写入`latest.json`的`alerts`，由当前持续goal检查并诊断；本脚本本身不向聊天发送通知，也不会自动改训练配置。

速度检查：最近128步与早期第100–1000步按batch平均片段时长的0.5秒分桶匹配；至少64步有参考、比值中位数超过1.25时提示诊断。这个阈值不是效果保证，也不是自动重启依据；文本长度、checkpoint保存和其他任务竞争需继续核查。预计剩余时间只按近期计算步时估计，不含额外故障与保存开销。

- `process.json`：实际巡检PID与进程开始ticks。
- `schedule.json`：下次巡检时间。
- `latest.json`、`report-<epoch>.json`：最新及历史报告。
- `controller.log`：运行日志。
- `observation_error.json`：最近一次观察异常，如存在则按时间核对，不能当成训练退出证明。
- `STOP`：只停止这个巡检，不停止训练。

训练报告完成后，巡检会校验最终步checkpoint SHA256再退出。当前goal还需复核最终状态与保存结果后才能结束。

首轮现场核查：四机8＋8＋8＋7个训练进程均存在，已有500／1000／1500步完整收据。第1001–1500步平均6.1603秒，第501–1000步6.0946秒；最近128步按时长匹配比值约1.028，未发现持续显著减速。SSH重试后四机均成功连接。此为首轮证据，不代表后续状态。
