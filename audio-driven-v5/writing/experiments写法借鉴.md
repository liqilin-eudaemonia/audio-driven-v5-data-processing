# Experiments 写法借鉴：OmniPersona 与 GLARE

记录日期：2026-11-11。

本文分析本轮会话提供的 [OmniPersona](OmniPerson.pdf) §4 与 [GLARE](00_GLARE_local.pdf) §6 实验段落及表格，整理其组织方式、结果分析和对本项目的应用。数值案例均为参考论文结果，不是本项目实验结果；文中的实验分工和英文句式用于后续写作，不表示本轮新增或执行实验。

返回 [写作总索引](README.md)。配套阅读：[Method写作借鉴](Method写作借鉴_GLARE与OmniPersona_20261111.md)、[Feature与Event监督详解](Feature与Event监督详解及结构图画法_20261110.md)、[参考论文图表与实验设计分析](参考论文图表与实验设计分析_20261107.md)。早期更广的候选与方案见 [文献实验建议](../experiments/literature_full_experiment_audit_20261107/EXPERIMENT_RECOMMENDATION.md)；其中的五组消融等历史安排不覆盖本轮会话已确定的四组结构。

## 1. 先抓住实验部分的共同逻辑

- **实验设置**交代比较的条件、数据与评价依据。
- **总体比较**回答完整模型表现如何，在哪些能力上有优势。
- **逐类与定性分析**解释平均数背后的具体行为和失败模式。
- **组件消融**检查方法中各项设计的实际作用。
- **参数、人评与补充实验**按实际主张补足证据，范围由任务和已完成工作决定。

两篇论文都在尝试建立这样的关系：

```text
引言中的困难与贡献
  → Method 中的针对性设计
  → 检验该设计的比较／消融
  → 能反映目标能力的指标与案例
  → 有明确范围的结果结论
```

实验正文的职责是指出重要观察、提供关键证据并解释含义。表格保存完整数值，正文不必逐列复述。

## 2. 两篇论文分别如何组织实验

| 论文 | 组织方式 | 可借鉴的重点 |
|---|---|---|
| OmniPersona | 数据与评价设置 → 按 benchmark 组织定量比较 → Seamless 上的组件／参数分析和人评 → 定性比较 | 不同设置检验不同能力；总体生成、条件接口、跨轮稳定性与人工感知分别寻找证据 |
| GLARE | 实验设置 → 总体定量比较 → 逐类反应分析 → 定性比较 → 组件与损失系数消融 | 从总体效果深入到具体反应类别，再回到模型设计的作用 |

章节数量与实验归属服务于叙述，不是必须照搬的格式。OmniPersona 把部分消融和人评放在 Quantitative Comparisons 中，GLARE 单独设置 Ablation Study，二者都可以形成清楚的证据组织。

## 3. OmniPersona：围绕不同能力安排比较

### 3.1 数据与评价设置先说明“为什么在这里测”

其 Training Dataset 段只交代来源、使用范围及输入规格，把读者带到训练设定。Evaluation Setup 随后说明各评测协议覆盖什么，以及作者为什么另外组织 Seamless 上的长片段评价。

它的三个评价入口分别承担不同职责：

| 评价入口 | 在原文中的主要用途 | 可学习的写法 |
|---|---|---|
| SpeakerVid-5M | 比较视听生成及 MLLM 与生成器的连接方式 | 先说明对照方法的关键差异，再解释结果 |
| OmniResponse | 在对应的对话协议下评价文本、音频与视频 | 按输出模态组织指标，并说明方法适用范围 |
| 自行组织的 Seamless 评价 | 检查跨轮生成、身份／声音保持及倾听表情 | 让补充评价直接回应本文的任务要求 |

借鉴到本项目：介绍 Seamless、ResponseNet、ViCo 时，要说明实际评测内容，而不只是列三个名称。当前设想是 Seamless 与 ResponseNet 评价倾听视听反馈，ViCo 补充视觉倾听能力；具体测试数量、筛选和正式协议以最终执行为准。

原文的 60 个约 50 秒片段、三种交互状态及跨轮一致性目标属于 OmniPersona。不能把这些条件套到本项目的当前语音条件下 backchannel 生成，也不能从它对既有 benchmark 的概括推导出“此前没有倾听评价”。

### 3.2 先说比较方法差在哪里，再说谁表现好

在 SpeakerVid-5M 比较中，原文先指出几种系统连接 MLLM 与生成器的方式不同：文本、文本表征、文本与非语言记忆。这让后面的表格围绕一个清楚的问题展开。

可以学习的段落顺序是：

```text
比较什么能力
  → 对照方法在哪个关键环节不同
  → 观察到的主要结果
  → 结果对该设计意味着什么
```

对于我们，比较段落应交代输入与输出范围：纯视觉倾听方法比较共同的视觉能力，能够生成音视频的方法或本模型消融才适合评价自身声音生成。使用不同预训练资源的系统比较，也不自动等于在统一训练条件下孤立检验架构。

### 3.3 固定中间内容，有助于解释生成阶段的变化

原文提到固定相同 response text 的补充比较，目的是减少回应文本差异对下游生成结果的影响。这是有价值的控制思路：完整系统比较衡量端到端表现，固定中间条件的比较帮助理解生成阶段本身。

对本项目，如果比较目标是 Whisper、Feature 或 Event 的生成阶段作用，应保持 Qwen 规划器版本、输入清单和描述生成设置一致；需要更严格控制时，可以复用同一套预测描述。若同时改变规划器、训练数据或预算，结果就包含多种变化，解释范围应相应调整。

这属于控制变量的建议，不是本轮新安排一个级联系统实验。用户此前已确认不把“联合生成优于级联生成”单独作为待证明的主要主张。

### 3.4 消融围绕模块原本负责的能力解释

OmniPersona 的消融没有只说“去掉模块后分数降低”，而是将变化与模块职责连接：

- 去掉 masked fusion 后，原表 FVD 从 11.93 增至 78.74，说明在其设定中这一设计对生成表现影响明显。
- 去掉 memory queries 后，FIDemo 从 0.31 增至 0.62，作者把它与表情建模联系起来，并引用额外表征探针。
- Strided RoPE 的讨论主要对应身份保持，Diffusion Forcing 的讨论主要对应时间稳定性。

可借鉴的是“模块职责—观察到的指标变化—对应可见现象”的关系。消融能够支持组件作用；更具体的内部机制解释应与已有证据相称。表征探针能说明某种信息可被读取，不能单独代替最终生成效果或完整因果论证。

### 3.5 参数分析写出收益与代价

原文将查询容量、上下文长度与性能放在同一图中，讨论增加容量后的收益趋缓，并结合计算量解释选值。

可以学习：参数小节不只宣布“选取某个值”，还说明改变参数后观察到什么趋势，以及选择依据。我们如已有 Event／Feature 权重搜索结果，可以用同样方式分析生成质量与行为指标的取舍；不需要额外复制与任务无关的记忆容量、长上下文实验。

### 3.6 人评与效率交代可复核的条件

人评段落明确人数、片段数、方法、评分范围和判断维度，再概括结果。效率段落明确设备、输出时长、分辨率、步数及计时是否覆盖编码和解码。

对本项目，人工评价维度已经讨论为语境适当性、参与感／自然度、视听协调。正文使用实际完成的人数、样本和评分方式，不继承参考论文的 20 人、20 条或 1–5 分设定。效率如果不是主要贡献，可以在有实际记录时简洁补充，不必为了模仿章节而扩大工作范围。

## 4. GLARE：从总体表现深入到反应行为

### 4.1 设置段落简洁，但比较条件明确

GLARE 的设置包含三块：实现细节、评价指标、比较方法。它明确报告训练规格，并说明对照方法在其数据上训练和测试。

可以借鉴的是信息组织，不是照搬具体条件。我们的正文应如实说明每个对照方法是重训、微调还是使用已有权重；只有实际统一了训练数据和设置，才能作出相应表述。

训练数据量与数据资源总量也应分开，正式生成训练使用哪份选集就报告哪份。具体数字最终从实际配置核对；数据章节已经介绍的构建过程不必在设置段再次展开。

### 4.2 主结果按能力分组解释

GLARE 主结果先概括总体表现，再把指标分成视觉质量、动作／交互及反应事件等组，解释每组结果反映什么。它还区分 RealTalk 与 Seamless 的结果，而不把不同数据集混成一个平均排名。

本项目的结果段也可以分成：

1. 视觉质量是否保持或改善。
2. 视觉与声音反馈类别是否更好地匹配参考回应。
3. 对当前话语的适当性、参与感和视听协调是否有支持证据。

不要用画质指标单独证明互动更自然，也不要用更多动作或更多发声直接证明反馈更合理。

### 4.3 逐类表解释平均分掩盖的差异

GLARE 的逐类表把不同反应的指标与数据量并列，使读者看到某些类别更难、不同数据来源上的表现也不同。

对我们可以借鉴：视觉／音频分别报告逐类 P、R、F1，并给出对应评测集中的参考正例支持数。它能够帮助区分：

- 哪些类别经常遗漏，导致 Recall 偏低。
- 哪些类别容易额外出现，导致 Precision 偏低。
- 平均提升是否主要由少数类别贡献。
- 哪些结论受到类别样本量限制。

当前整段评测不要求参考事件时间重叠，因此不能借用 GLARE 的时序分数解释“时间更准确”。原论文表中的 Data Amount 也不能未经核对直接当作我们的测试支持数口径。

“罕见类别因此更难”“低分说明数据更复杂”可以是解释假设；若没有额外分析，应使用审慎措辞，避免把相关性直接写成已经证明的原因。

### 4.4 定性比较围绕可观察的失败现象

GLARE 在同样的抽帧位置比较方法，讨论静态回应、反应类型和发生时间。OmniPersona 则关注模糊、身份变化、场景切换和跨时间漂移。

两者共同的写法是：先明确要观察什么，再让图像或视频显示具体差异。不是仅放几张效果图，再笼统写“更自然”。

我们的案例应优先展示与任务有关的现象：

- 是否出现与当前话语相符的视觉反馈。
- 是否遗漏短促声音，或在安静场景中出现不恰当发声。
- 面部变化与自身声音是否协调。
- 是否存在僵硬、过强或与语境不适应的反应。

同一比较使用相同输入与统一展示尺度；音频用可播放补充视频和对应时间轴呈现。共同抽帧时刻用于观察，不把与 GT 的动作发生时刻不同直接视为错误。GT 是一个观察到的回应，仍允许其他合理实现。

### 4.5 消融报告混合结果，更能说明模块分工

GLARE 的文字报告：prosody 条件改善部分画质和动作指标，但单独使用时反应指标收益有限，某些时间指标甚至变差；反应损失则对反应建模更直接。最后再讨论二者结合后的整体表现。

值得学习的是，模块的作用由实际结果解释，而不预设每个模块都应让所有指标变好。如果某个条件分支提高动作幅度却同时增加误反应，应同时报告，而不是只选其中上升的一列。

本项目的四组移除消融可以检验每个组件在完整模型中的条件贡献，但没有覆盖全部组件组合。仅凭四组结果，不应额外声称已经证明三组件的可加性或全部协同关系。

### 4.6 损失权重用生成结果解释

GLARE 的权重段落按“小权重—中等权重—较大权重”的趋势展开，并把变化与生成目标和行为监督之间的平衡联系起来。

本项目可以学习这种写法，但实际曲线可能并不单调，应按结果描述：

- Event 权重变化时，类别 Recall、Precision、画质和误发声是否发生取舍。
- Feature 权重变化时，条件适配是否带来最终生成表现的变化。
- 所选配置在目标能力和其他质量维度上有什么依据。

不要根据训练 loss 最小直接认定生成效果最优。参考论文报告的 0.05，以及我们历史配置中的相同数值，都不能代替当前实验的选值证据。用于选参数的数据也应准确披露其用途。

## 5. 学习结果表达时，也核对正文与表格是否一致

参考论文有可学习的结构，但不应把它们的概括自动当作每列结果都支持的结论。本轮提供的表格就有明确的持平与例外：

| 参考表格 | 可直接核对的事实 | 写作启示 |
|---|---|---|
| OmniPersona Table 2 | SIM-o 为 0.65，与 SpeakerVid-5M 持平 | 可以说该项保持竞争力或并列；不能称为严格提升 |
| OmniPersona Table 3 | 相较 OmniResponse，ROUGE-L 同为 0.081；Distinct-2 从 0.882 降至 0.833 | 总体文本表现的概括应区分提升、持平和下降 |
| GLARE Table 2，RealTalk | Ours SSIM 为 0.601，DyStream 为 0.611 | 较好的总体结果不等于每项画质指标均第一 |
| GLARE Table 2，Seamless | Ours DI-Sync 为 0.205，ListenFormer 为 0.212；Var 为 2.447，DyStream 为 2.452 | 应指出不同能力上的实际排名，不能用全称覆盖例外 |
| GLARE Table 3，RealTalk surprised | Ours R-tIoU 为 0.658，DyStream 为 0.679；R-FID 为 16.007 与 15.397 | 平均提升不自动代表所有类别、所有指标都改善 |

OmniPersona 对“LSE-D 低于 GT”的说明也值得注意：自动指标优于参考媒体的分数，不等于生成结果在所有方面优于真实对话。原文对参考媒体同步问题的解释是其报告的观察，我们在自己的论文中只能根据自己的检查和指标适用范围作出解释。

推荐的结果段落顺序：

```text
主要结论
  → 选一至两个关键数字支持
  → 说明它对应哪种能力
  → 交代重要持平项、退化项或适用范围
```

SOTA 主张应限定到实际比较的方法、测试设置和指标范围。没有输出音频的视觉方法无法提供音频生成排名；它们的 N/A 不能作为我们“击败”该方法的数值证据。

## 6. 与本项目当前写作方案对应

### 6.1 三个实验问题

| 问题 | 对应证据 | 正文重点 |
|---|---|---|
| 完整模型能否产生质量较好且有反馈行为的 listener 音视频？ | 主比较、可适用的视觉／声音事件指标、定性与人工评价 | 质量、行为与互动判断分别说明 |
| Whisper、Feature、Event 分别起什么作用？ | 完整模型与逐项移除对照 | 固定其他条件，观察与组件职责有关的变化 |
| 数据与标注为任务提供了什么支持？ | 样本与行为统计、媒体／标注样例、已有质量核验 | 如实展示资源；若主张标注更完整或减少遗漏，需有对应比较证据 |

不把所有可借鉴实验自动转为必做项。优先完成支撑当前主张的主比较与四组消融，逐类、权重和人工分析按已完成材料及论文需要组织。

### 6.2 已确定的比较方法与表格口径

会话中确定的主表方法为 L2L、DIM、ViCo、ListenFormer、DyStream、GLARE、Avatar Forcing 和 Ours。训练来源、输入适配、实际可执行范围以正式结果对应的记录为准。

用户要求合并为一张方法比较表，可以按数据集分块，并在列上组织不同能力：

| 指标组 | 已讨论的指标 | 解释重点 |
|---|---|---|
| 视觉质量 | CPBD、PSNR、SSIM、FID、FVD、LPIPS | 指标反映不同质量属性，参考相似性不覆盖所有合理回应 |
| 视觉反应与行为观察 | Emo-Acc、Emo-Div、ΔResp、MLLM reaction detection rate | 类别一致、类别多样性、动作幅度差距与检出情况分别解释 |
| 视觉事件 | P、R、Macro-F1 | 整段类别一致性，补充逐类支持和结果 |
| 音频事件 | P、R、Macro-F1 | 只对实际生成 listener 音频的方法填写 |

当前约定：UTMOSv2 已从我方主比较表移除，本次引用 OmniPersona 的实验不意味着重新加入。Emo-Div 不默认越大越好；MLLM reaction detection rate 的含义和汇总按最终定义，不能直接代替反应适当性。整段事件已按[2026-11-08确认的协议](../evaluation/event_presence/README.md)，在视觉／音频各自冻结参考中有正例的类别上分别计算Macro-P／Macro-R／Macro-F1；表头P／R应明确对应宏平均，无参考正例类别的误报另报。

表格说明按作者已确定的格式放在表格下方。适用指标内标示最优／次优，避免在不同数据集或不同协议之间混合排名。

### 6.3 四组消融与各自要解释的现象

| 配置 | 保留内容 | 结果分析要回答的问题 |
|---|---|---|
| Ours | AV＋Whisper＋Feature＋Event | 完整模型的综合表现 |
| w/o Whisper | AV＋Feature＋Event | 直接声学路径在原有 Qwen 条件之外带来什么变化？ |
| w/o Feature | AV＋Whisper＋Event | 移除条件适配监督后，生成质量和反馈表现怎样变化？ |
| w/o Event | AV＋Whisper＋Feature | 移除显式类别监督后，事件遗漏、误激活和 P／R 怎样变化？ |

这些配置仍使用 Qwen／Gemma 条件和 AV 目标。`w/o Whisper` 不是完全没有 speaker audio；`w/o Event` 也不等于训练中删除所有反应描述。

组件消融应交代模型初始化、规划器、数据、训练预算和采样条件。版本或预算存在差异时，按实际范围解释，不把它写成只改变一个开关的严格比较。

### 6.4 人评维度对应任务目的

保留三项：

- **Contextual appropriateness**：反馈是否适合当前 speaker 的话语。
- **Engagement / naturalness**：是否体现自然参与，允许合理的安静倾听，避免把活动更多等同于更好。
- **Audiovisual coordination**：生成声音和面部／头部反应是否形成协调回应。

用户已要求人评主表不放 Valid samples 和 Uncertainty 两列。必要的样本规模、评分人数、呈现条件及统计说明可以放正文或补充材料。纯视觉方法只比较可适用维度；为其配上真实 listener 音频会改变评价条件，应明确说明。

### 6.5 章节内容的推荐顺序

```text
Experimental Setup
  ├─ Training data and test settings
  ├─ Implementation details
  └─ Evaluation protocol and compared methods

Comparisons with Existing Methods
  ├─ Quantitative results
  └─ 对应的定性案例／补充视频

Ablation Studies
  ├─ Ours 与三个 w/o 变体
  └─ 已有的逐类／权重分析

Human Evaluation 或其他对应小节
  └─ 按实际完成情况组织
```

这是内容顺序建议，不要求照此新增全部编号小节。数据质量核验、完整逐类表和更多失败案例可结合篇幅放到数据章节或补充材料。整体效果展示、组件分析及人工判断之间应有明确分工，避免同一表格被多次重复解说。

## 7. 可复用的结果段落模板

以下方括号均为待填内容，方向和结论必须由实际结果决定，不能直接删除占位后当作已完成实验。

**总体比较：结论—证据—含义。**

```latex
Table~\ref{tab:overall-comparison} compares the methods on
[dataset] under [evaluation setting]. Our model achieves
[verified result] in [metric group]. In particular,
[metric] changes from [baseline value] to [our value],
indicating [interpretation supported by this metric].
[State any important tie, regression, or limitation.]
```

**组件消融：改动—观察—对应职责。**

```latex
Removing [component] leads to [observed change] in [metric],
with [corresponding qualitative observation]. This result
supports the role of [component] in [specific capability].
[Report relevant effects on the other metric groups.]
```

如果变化不足以支持预期机制，应改为描述实际观察，而不保留上述 `supports` 结论。

**逐类分析：平均收益来自哪里。**

```latex
The per-category results show [observed pattern].
For [category], [precision/recall/F1] changes from [x] to [y],
whereas [another category] shows [different pattern].
[Report the applicable category support and interpretation.]
```

**权重分析：描述趋势，不预设“越大越好”。**

```latex
Varying [loss weight] changes [observed metrics or behaviors].
The selected setting provides [verified balance] between
[generation quality] and [feedback behavior].
[State the selection setting and any relevant trade-off.]
```

**定性分析：让图说明具体行为。**

```latex
Figure~\ref{fig:qualitative} compares responses to the same
speaker input. [Method] exhibits [observable behavior],
while our model produces [observable behavior].
The accompanying video illustrates [vocal feedback or
audiovisual coordination that still frames cannot show].
```

结果正文优先使用清楚的观察动词，例如 `increases`、`decreases`、`remains comparable`、`misses`、`produces`。机制解释与因果措辞应与对照条件和证据强度相称。
