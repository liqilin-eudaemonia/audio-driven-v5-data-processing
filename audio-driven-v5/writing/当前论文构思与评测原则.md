**1．任务范围与应用目标**

输入只有当前一两句 speaker audio 和 listener first frame，**没有历史对话输入**。输出为 listener 在倾听阶段的音视频，包括安静倾听、无声视觉反应，以及简短附和、笑声等有声反馈。“当前语音语境”仅指这段输入提供的内容、语气、韵律等线索，不能写成历史记忆或多轮对话理解。

应用目标是：即使用户只说一句话，数字人也能给出自然、贴切、具有参与感且表达丰富的反馈。用户举出的典型场景是分享开心的事情或讲笑话，真实倾听者可能点头、微笑、共同发笑，平淡的生成反应则削弱交流体验。

这里的“丰富”指有多种有意义的反馈方式，并能根据当前语音适当表达；不等同于每段都更多点头、更多发声。倾听是对话角色，倾听期间可以发声；短发声也需结合语境区分 backchannel、回答、打断和接管话轮。

**2．核心主张与三项贡献**

> 让数字人根据当前说话者语音，生成自然、贴切且具有参与感的倾听视听反馈。为此，我们构建任务数据，提出专门的生成 pipeline，并建立相应的评测协议。

**数据、模型 pipeline 与 benchmark 均为核心贡献方向。** 模型应有独立的方法论证和消融证据，不能在叙事中被弱化为数据集附带的演示。

| 贡献 | 研究问题 | 核心证据 |
|---|---|---|
| 数据资源 | 用什么样的样本与监督学习倾听反馈 | 任务化处理、行为覆盖、标注和音轨质量、独立划分 |
| 模型 pipeline | 如何从 speaker audio 生成 listener 的视听反应 | 设计动机、可比基线、完整模型效果、模块消融与输入控制 |
| Benchmark | 如何判断反馈自然、贴切且有互动作用 | 代表性测试集、评价规则、人工验证、外部基线与可复现协议 |

**3．全文的论证顺序**

1. **真实需求。** 倾听者通过动作、表情和短促声音参与交流，视觉与声音反馈共同构成交互表现。
2. **研究问题。** 仅根据当前 speaker audio 与 listener 首帧，如何生成贴切、协调的视听 backchannel？目标人物的声音本身也是待生成的反应。
3. **数据支撑。** 将对话素材组织为倾听片段，保留真实视听反馈并提供反应监督。
4. **方法回应。** 用直接声学条件与反应相关监督，学习从说话者信息到倾听反应的映射，再通过联合音视频生成表达。
5. **评测验证。** 在考虑多种合理反应的前提下，评价反馈行为、适当性、视听协调与媒体质量，检验模型改善了什么。

引言先讲任务价值，再说明数据与评测需求以及模型设计困难，随后概括三项贡献。方法段落采用“具体问题 → 设计理由 → 实现机制 → 对应实验”的顺序，避免仅罗列组件。

**4．数据需求与相关工作定位**

用户提出的数据需求包括：部分资源分辨率或人脸有效质量不足，部分来源的双方画面或音轨需处理，缺少适合本任务的 backchannel 标注；现有对话评测中，目标倾听反馈的覆盖也可能不足。

这些是待逐项核验的资源差异，不能统一归于 ViCo、SpeakerVid、RealTalk、Seamless 等所有数据集。ViCo 已提供独立 speaker/listener 视频；Seamless 官方也提供高清视频与分开的音频通道。通道分开与残余串音是不同问题，需要分开描述。[ViCo 数据说明](https://project.mhzhou.com/vico/)、[Seamless 官方说明](https://github.com/facebookresearch/seamless_interaction)

数据章节的工作表述为：**已有语料提供了重要对话素材，本工作围绕短语音条件下的视听 backchannel 生成，完成倾听区间组织、反馈保留、音轨质量检查和反应标注等任务化处理。** 每项处理的实际完成情况和效果需有记录支持。

| 要核对的属性 | 应记录的内容 |
|---|---|
| 输入输出支持 | 是否有配对的 speaker 输入、listener 视频与自身音频 |
| 角色与事件 | 是否区分倾听反馈、完整回答和话轮接管；标签覆盖什么 |
| 媒体可用性 | 实际人脸分辨率、双方画面组织、独立音轨与串音程度 |
| 测试覆盖 | 各类 backchannel 数量与时长、无事件区间、自然分布与分层分析 |
| 新增工作 | 本项目具体补充了哪些筛选、标注、净化、划分与评价支持 |

传统 talking head generation 通常给定目标人物语音生成视频；听完对方后生成自己的回复属于对话回应生成，不混用两种定义。传统视觉 listening head generation 可作为输出范围的对照，但“所有倾听工作都不生成音频”不成立。ResponseNet 与 VideoFDB 已有相关覆盖，新颖性需依据具体任务条件与新增支持论证。[ResponseNet](https://omniresponse.github.io/index.html)、[VideoFDB 数据说明](https://huggingface.co/datasets/nvidia/video-full-duplex-benchmark/blob/main/README.md)

**5．模型 pipeline 的方法论证**

研究判断：**视听 backchannel 生成需要利用说话者语音线索，将其转化为反应相关的生成条件，并通过联合音视频生成表达。**

| 组成 | 预期职责 | 写作边界 |
|---|---|---|
| Speaker audio cross-attention | 为音频和视频生成器提供直接访问时序声学特征的路径 | 原 Qwen 路径已包含 speaker audio，新增 Whisper 是补充声学路径 |
| Event supervision | 对反应类别提供显式辅助监督 | 已评测旧版监督池化 U；新默认监督 LTX 最后 block 的生成 hidden，仍是片段级，不启用时序头。最终方法按实际训练与评测版本描述 |
| Feature supervision | 通过 listener teacher 特征重建补充细粒度信息 | 当前为特征解码器上的 flow-matching 监督，不是直接 H 与 teacher 的 MSE |
| 联合 AV 生成 | 学习声音与面部行为的共同表达 | 不要求所有视觉动作都伴随声音；收益需通过生成结果验证 |

用户提出联合生成有利于口型和自然度，作为方法假设保留。论文应解释同一次反应中声音、嘴部与表情的关联，并验证联合建模的效果。独立生成与级联生成不同：先生成音频再条件化生成视频仍有跨模态约束，不能笼统宣称所有级联方法必然更差。

pipeline 的贡献需要解释为何现有联合生成骨干仍需这些条件与监督设计，结合 AV-only、声学分支、Event、Feature 及完整模型对照说明。联合生成若沿用既有骨干，其基础能力与本项目新增设计分别交代。

结构依据：[旧联合实验交接](../related/P2_AV_Event_Feature_Whisper联合实验代码交接_20261105.md)、[新默认生成 hidden Event 说明](../related/P2_LTX主干整段与时序事件监督_20261106.md)。旧版训练状态更新见 [联合6000／8000步结果](../experiments/p2_combined_whisper_eval_20261106/RESULTS.md)。本文记录设计逻辑，不将旧结果转用于新结构。

**6．一对多反馈的评价原则与待定分歧**

用户明确提出：笑、点头等反应不必发生在唯一 GT 的精确时刻，评价应重视片段中是否出现了合适的反应类别。用户倾向类别优先，并认为部分场景的回应情绪比较明确。

据此保留的核心原则是：**精确复现单个参考不是判断自然反馈的唯一标准。** 一对多建模亦有相关研究基础。[Learning to Listen](https://evonneng.github.io/learning2listen/)

进一步的工作建议尚需定稿：类别本身也可能有多种合理选择；开心话语可对应微笑、点头或简短附和。输入未提供 listener 态度，不能从 speaker 内容唯一推断其是否同意。因此应区分“与参考类别一致”和“对输入语音适当”。

仅检查类别是否出现，无法区分自然轻笑与整段持续大笑，也可能奖励每段堆满所有行为的模型。建议形成两层评价：

- **参考一致性：** 片段级类别、声音活动等可复现统计，解释为对已观察参考的匹配。
- **反应适当性：** 结合当前 speaker audio，判断内容、强度、持续与粗粒度时机是否自然，允许与 GT 不同的合理反馈。

不将严格时刻匹配作为主成功标准；是否保留辅助时间一致性指标、如何定义可接受时机，尚未决定。仍需评价生成声音与生成视频自身的协调，这与复现 GT 时间轴是不同问题。

**7．短音频与互动评价的候选方案**

用户指出短促“嗯”“okay”等声音难用传统音频指标充分评价，具体指标尚未确定。UTMOSv2 的官方目标是合成语音自然度 MOS 预测，接口接收音频文件或波形；不能将其定义为只能评价完整一句话，也不能直接假定它对极短附和、笑声或静音有效。需要验证其分数与此类样本人工判断的关系。[UTMOSv2 官方实现](https://github.com/sarulab-speech/UTMOSv2)

| 评价对象 | 需要回答的问题 | 候选证据 |
|---|---|---|
| 声音行为 | 是否产生有效附和或笑声，是否有额外长回复或串音 | 人工核验事件集，后续验证自动检测 |
| 声音质量 | 是否自然，有无噪声、断裂和失真 | 短音频主观听评，自动分数与人工判断的一致性 |
| 回应作用 | 声音是否适合当前话语并体现参与 | 联合播放 speaker 与 listener 的上下文听评 |
| 视觉质量 | 人脸、身份与动作是否可信 | 常用视觉指标与人工观察，逐参考误差不独自决定反应正确性 |
| 视听协调 | 声音、嘴部、表情和动作是否自然配合 | 适用于短反馈的协调评价和人工判断 |
| 互动表现 | 是否贴切、适度且具有参与感 | 明确评价问题的人工比较，后续验证代理指标 |

静音片段的音质不直接计为高分或低分，应单独报告声音行为及音质指标有效覆盖率。只评价有声输出的质量，也不能掩盖大量漏声。

用户提出眼神运动作为互动评价候选。眼动量不等于互动性，参考首帧也未必提供真实注视对象方位；采用眼神指标前需明确测量含义并验证与人工感受的关系。已有研究关注同步、真实性和多样性，避免使用“没有任何互动指标”的绝对表述。

以上是评价设计方向，尚未确定新的正式指标、计算公式、权重或综合分数。自动反应检测器也需独立核验，不能只因与训练标签体系相同就视为可靠评价。
