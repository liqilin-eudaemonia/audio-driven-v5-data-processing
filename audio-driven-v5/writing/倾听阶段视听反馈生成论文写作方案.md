# 倾听阶段视听反馈生成论文写作方案

记录日期：2026-11-05。状态：初版方案，保留当时的引言、实验和摘要构思。2026-11-06 已明确短语音输入、数据／模型 pipeline／benchmark 三项核心贡献，并补充一对多和短音频评价讨论；当前以 [最新构思与评测原则](当前论文构思与评测原则.md) 为准。全部文档见 [论文写作总索引](README.md)。下文实验状态属于初版讨论背景，不作为最新运行结论。

核心主线：**倾听阶段包含持续的视听反馈。我们将这种反馈明确为一个生成任务，构建支持该任务的数据与评测协议，并提出面向反应的生成框架，研究如何从说话者语音中产生倾听者的视觉动作和短促声音反馈。**

文章围绕“当对方仍然持有话轮时，数字人如何通过面部行为与声音表现出合适的倾听反应”展开。整体组织采用 **任务定义 → 数据构建 → 专门评测 → 生成方法 → 实验分析**，将数据和 benchmark 提升为核心贡献候选。

**1．任务定位与叙事选择**

输入为 speaker audio 和 listener first frame；输出为倾听阶段的 listener 视频及自身音频，覆盖安静倾听、无声视觉反应和有声附和。目标人物的未来音频、视频和真实反应标签不作为推理输入。训练监督与推理条件必须在正文和结构图中区分。

倾听是一种对话角色，不能直接用是否发声定义。倾听者可以发出“嗯”、简短附和或笑声，同时让说话者继续持有话轮。沉默是任务需要覆盖的状态；不能把所有沉默或面部运动都标成 backchannel，也不能仅凭发声短就认定其属于 backchannel。

| 讨论过的方向 | 当前定位 | 主要理由 |
|---|---|---|
| 从视觉倾听扩展到视听反馈 | 用于开篇说明任务 | 直观，但已有工作涉及视听回应，不能仅靠增加音频输出建立贡献 |
| 面向反应的条件学习 | 用于组织方法 | 能解释声学分支、Event 和 Feature 的信息职责 |
| 稀疏反馈及发生时机 | 用于提出任务难点和评测问题 | 当前片段级 Event 不提供显式时间定位，不能将精确时机控制写成已有能力 |
| 任务、数据、benchmark 与方法共同推进 | 全文主线 | 数据明确学习对象，评测明确成功标准，方法回应建模困难 |

**2．引言的完整推进**

第一段从具体对话现象开始：说话者讲述时，倾听者通过点头、微笑、短促发声等表达注意、理解或情感回应。这些反馈可以不接管话轮。由此说明数字人的交互能力也取决于倾听期间的表现，并给出输入输出定义。

第二段定位相邻工作。视觉倾听生成提供动作建模基础，视听对话生成已经覆盖声音与画面，backchannel 检测和交互评价提供行为分析思路。本文聚焦说话者持有话轮期间的倾听反馈，在统一输入条件下研究其音视频生成。

第三段提出数据与评价需求。研究这一设定需要保留真实短促发声、区分反馈与话轮接管，并同时覆盖有反应与无事件区间。评价需要区分媒体质量和反馈行为，检查发生、类型、时间关系及视听协调。

第四段提出方法判断。生成器需要访问说话者的时序声学信息，中间条件表示也需要接受反应相关监督。直接声学条件与行为监督因此形成两个相互配合的设计方向；是否互补由实验检验。

第五段概括数据资源、评测协议和生成框架，并填写经过验证的主要发现。摘要与引言中的收益必须对应实际评测的模型配置。

**3．数据贡献的组织**

数据章节围绕“保留倾听阶段真实的行为选择”展开，规模统计放在任务定义、构建规则和质量证据之后。

| 数据设计 | 任务价值 | 所需证据 |
|---|---|---|
| 以对话角色和话轮组织片段 | 明确生成对象，减少完整说话回合混入 | 角色、边界和短发声的上下文抽检 |
| 保留 listener 短促发声 | 防止将 listening 系统性处理成全静音 | 发声保留率及 backchannel 类型核验 |
| 音轨净化和双方时间对齐 | 减少 speaker 串音污染目标，保留互动关系 | 串音、真实声音损伤和时间对齐检查 |
| 反应标签和自然语言描述 | 支持监督与行为分析 | 标签准确性、覆盖率和标注一致性 |
| 保留无事件区间 | 学习何时安静，避免只在事件片段上评价 | 自然分布统计与事件分层统计 |
| 独立的数据划分 | 支持可信比较 | 来源、身份或会话隔离规则及重复检查 |

基于现有语料构建时，准确说明原始来源，以及本项目新增的筛选、重组、标注、净化和验证工作。来源语料总量、处理后可用量、实际训练规模和标注覆盖分别报告。

待确认的关键问题是：J 切分中的 listener 短发声是否已经通过上下文核验，区分了 backchannel、回答、打断和接管话轮。VAD 或净化后存在声音，均不能单独完成这个判断。

**4．Benchmark 的论证与设计方向**

用三个具体失败引出评测：始终安静的模型可能有稳定画面却遗漏声音反馈；频繁回应的模型可能缺少与 speaker 的关联；分别自然的视频与声音也可能组合得不协调。

| 评价问题 | 观察内容 |
|---|---|
| 是否产生了反馈 | 反应覆盖、遗漏、额外反应，以及无事件区间的表现 |
| 产生了什么反馈 | 视觉行为、声音类型及其组合 |
| 反馈是否合适 | 时间关系、与 speaker 上下文的关联、视听协调 |
| 生成质量如何 | 视频真实性、身份保持、声音质量和连续性 |

参考事件匹配与人工适当性分开报告。同一上下文可能允许多种合理反应，偏离唯一 GT 不自动等于错误。时机评测需要可信的时间标注；片段级标签不足以提供事件起止真值。声音活动也不等同于有效 backchannel。

正式 benchmark 应明确输入限制、固定测试划分、评分定义、有效覆盖率及外部基线，提供可复现协议。自然分布测试与事件分层分析各有用途；目前的诊断子集不能仅因已有评分就自动视为完成的正式 benchmark。

简单对照可包含始终静音、错配反应等，用于检查指标能否识别明显失败。候选研究发现是“通用视觉指标与倾听反馈能力可能不一致”；需要跨模型、人工核验及评分口径检查后再写成结论。

**5．方法的叙述与机制边界**

方法的中心判断是：**直接声学条件提供输入信息，反应相关监督塑造条件表示，联合生成目标将其落实为音视频。**

| 设计 | 写作职责 | 机制与边界 |
|---|---|---|
| Speaker Whisper cross-attention | 为生成器提供直接的时序声学条件 | 原 Qwen 条件已接收 speaker audio；这是额外路径，不是首次加入说话者输入。音频与视频采用独立残差 cross-attention |
| Event loss | 鼓励条件表示保留反应类别 | 当前对 Connector 输出 U 的有效 token 均值池化，做 19 类片段级多标签监督；不提供显式事件时间定位 |
| Feature loss | 补充类别之外的目标特征信息 | 通过两路特征解码器进行 flow-matching 重建；不是直接对 Qwen H 与 teacher 特征做 MSE，也不自动证明语义解耦或同步能力 |
| AV loss | 学习最终音视频生成 | 生成质量与反应适当性分别验证 |

Event 与 Feature 监督作用于共享 Connector 及各自预测头；Whisper 分支通过 AV 目标学习。teacher 特征与真实 Event 标签仅用于训练。条件信息的作用属于待检验的设计解释，不能仅凭命名证明模型理解了语义、情感或反应时机。

当前结构详见 [联合实验交接](../related/P2_AV_Event_Feature_Whisper联合实验代码交接_20261105.md)。

**6．实验与图表的论证顺序**

1. **数据是否可信。** 报告构成、角色和标签核验、划分独立性及行为覆盖。
2. **现有方法表现如何。** 在统一输入协议下比较外部基线与简单对照，分开报告行为与媒体质量。
3. **完整方法改善了什么。** 使用相同数据和可比预算，比较 AV、AV＋Whisper、AV＋Event＋Feature 与完整方法；按实际问题补充单项监督消融。
4. **改善来自哪里。** 固定其他条件，去掉或扰动声学分支及辅助监督。仅扰动 Whisper 输入检查该分支；替换整个 speaker 输入时需重新计算所有相关条件，二者不混为一个实验。
5. **哪些问题仍未解决。** 展示漏声、额外发声、时间偏差、视听不协调和不同合理反应，结合人工判断解释。

首图建议用统一时间轴展示 speaker 语音、listener 连续画面和 listener 音频，使安静、无声动作和有声反馈可见。总体方法图区分推理条件与训练监督。数据与 benchmark 表强调新增支持，定性结果提供可听媒体，并交代选例规则。

本次讨论所依据的实验存在以下写作边界：完整 Whisper＋AV＋Event＋Feature 模型的记录是 18 步运行验收，不能作为收敛或生成收益证据；分项实验显示部分视觉收益，但组合监督未证明稳定叠加，声音遗漏仍是明显短板。SFT 收益随数据集与指标变化，暂作为分析方向，不提升为中心贡献。

后续结果以 [评测索引](../evaluation/README.md)、[Seamless 分析](../experiments/p2_seamless200_analysis_20261105/ANALYSIS.md)、[ResponseNet 结果](../experiments/p2_responsenet_random200_twelveway_20261105/RESULTS.md) 和具体实验记录为准。本方案不固定最佳模型或承诺最终收益。

**7．目标贡献表述**

以下是完成相应数据、评测和实验后可采用的表述方向：

- **数据资源：** 构建面向倾听阶段视听反馈的数据资源，在明确对话角色的基础上保留视觉反应与短促发声，并提供反应相关标注和质量分析。
- **评测协议：** 建立统一输入条件下的生成 benchmark，从反馈行为、时间关系、视听协调和媒体质量等方面评估模型，分析不同评价维度揭示的能力差异。
- **生成方法：** 提出结合直接声学条件与反应相关辅助监督的生成框架，通过控制实验研究各设计对倾听反馈生成的作用。

任务定义可与数据贡献合并，不为增加条目而单独宣称“全新任务”。全文应让读者记住：倾听阶段的视听反馈被组织为可学习、可比较、可诊断的问题，并有相应生成方法供研究。

**8．摘要工作草案**

下段保留拟投稿时的表达形式，列出的构建与评价工作需完成后才能成为正式摘要：

> 自然对话中的倾听者通过点头、表情和短促发声提供持续反馈，而这些行为可以在不接管话轮的情况下发生。本文聚焦于倾听阶段的视听反馈生成：根据说话者语音和倾听者参考图像，生成包含视觉反应与声音反馈的倾听者音视频。围绕这一设定，我们构建保留倾听角色与多模态反馈的数据资源，并建立分别评价反馈行为与媒体质量的评测协议。进一步，我们研究一种结合直接声学条件与反应相关监督的生成框架，通过反应类别和目标特征监督塑造中间条件表示，以支持最终音视频生成。

摘要后半部分待最终实验确定，优先填写一个 benchmark 揭示的现象和一个方法带来的明确收益，附相应量化或人工评价证据。

**9．相关工作与新颖性表述**

**10．后续写作需要落实的事项**

- 核验 backchannel 与话轮接管的区分，明确训练数据和测试标注的质量证据。
- 完成与现有资源的任务条件对照，确定数据和 benchmark 的实质新增支持。
- 固定测试协议、事件时间标注方案、人工评价规则与外部基线；不预先将待建设部分写成已完成。
- 完成完整模型及可比消融，将最终贡献和摘要结果收敛到实际证据。
- 明确资源交付范围，包括数据或索引、标注、处理脚本和评分实现；尚未确定公开范围时，不写“已公开”或具体发布承诺。
