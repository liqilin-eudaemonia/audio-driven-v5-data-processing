# Conclusion 写法借鉴：GLARE 与 OmniPersona

记录日期：2026-11-11。

本文分析作者在会话中提供的 [GLARE](00_GLARE_local.pdf) §7 Conclusion 与 [OmniPersona](OmniPerson.pdf) §5 Limitation and Conclusion，记录可用于本项目论文结尾的结构、表达与局限写法。这里提供写作框架和待填句式，不据参考论文预写本项目尚未确认的性能结论。

返回 [写作总索引](README.md)。配套阅读：[Method写作借鉴](Method写作借鉴_GLARE与OmniPersona_20261111.md)、[数据与评测构建写法借鉴](数据与评测构建写法借鉴.md)、[Experiments写法借鉴](experiments写法借鉴.md)。

## 1. 结论应完成什么

- 简洁重申本文解决的任务与核心思路。
- 归纳最重要的工作，交代它们之间的关系。
- 提炼实验已经支持的主要发现。
- 回到研究意义，让结尾回应引言的问题。
- 需要时补充真实的适用边界，并给出对应的后续方向。

结论可以概括已经证明的内容，但不新增模型机制、评价能力或性能主张。模块细节、公式、完整数据统计和逐项指标解释已经在前文承担相应职责。

## 2. GLARE：把数据、方法、评价收束到同一个研究观点

### 2.1 逐句承担什么作用

| 句子角色 | 原文的主要内容 | 写作作用 |
|---|---|---|
| 任务与总方案 | 提出以反应为中心的 listening-head 框架 | 用一句话提醒读者本文研究什么 |
| 数据支持 | 整理对齐的 speaker–listener pairs 和事件级反应标注 | 概括数据贡献及其用途 |
| 方法设计 | 韵律条件与时间反应损失 | 点出支撑任务的核心设计 |
| 评价支持 | 反应发生、时序和反应区域画质指标 | 说明评价如何对应任务目标 |
| 实验发现 | 视觉质量、动作及反应指标的改善 | 从“做了什么”转向“结果支持什么” |
| 研究意义 | 显式反应监督和针对性评价有助于自然倾听 | 把各项工作归纳为一个总体认识 |

它没有在结尾重新解释韵律特征的形状、分类头或每项指标公式。数据、方法和评价各用短句概括，最后把它们联系到倾听反应这一共同目标。

### 2.2 可以借鉴的三点

**贡献之间有联系。** 数据提供反应标注，方法利用反应监督，评价检查生成反应。结论呈现的是一套围绕任务组织的工作，而不是互不相关的模块清单。

**结果之后再谈意义。** 原文先概括实验发现，再说明这些发现对倾听生成有什么启发。对我们的稿件，结尾中的认识也应有前文证据支持。

**呼应引言的核心困难。** GLARE 开篇强调反应建模不足，结尾回到反应监督和评价的价值。本项目的引言强调 listener 的视听参与，结尾也应回到生成视觉与声音反馈的意义。

### 2.3 应根据自己的工作调整

当前会话中的贡献组织是：视听倾听框架；反应标注数据与 Feature／整段 Event 监督；实验表现。结论可以概括评价协议的作用，但不必机械照搬 GLARE 的“数据—方法—指标”三项并列，也不能自动将评价另立为新的独立贡献。

我们的 Event 不监督具体起止时间，因此不能照搬 GLARE 的“提高时间定位精度”作为主要结论。是否提高了画质、类别一致性、语境适当性或参与感，分别由对应实验决定。

## 3. OmniPersona：贡献总结与适用边界衔接

### 3.1 两段分别做什么

第一段概括整体框架、关键条件接口和生成设计，并回到多轮交互、身份保持与视听一致性这些目标。

第二段指出当前系统的流式使用与身体范围限制，再提出相对应的后续方向，最后回到交互数字人的总体意义。

其结构可以写成：

```text
本文提出什么框架
  → 关键设计服务于什么能力
  → 实验支持了哪些表现

当前适用范围或实际限制
  → 这些限制影响什么使用场景
  → 对应的后续研究方向
  → 与本文目标一致的研究意义
```

### 3.2 局限与未来方向一一对应

| 原文局限 | 原文对应的后续方向 | 可学习的写法 |
|---|---|---|
| 尚未形成面向低延迟流式交互的蒸馏／因果版本 | 流式交互与进一步降低延迟 | 说明现有能力与目标使用方式之间还差什么 |
| 当前主要生成人脸区域 | 全身数字人生成 | 说明系统覆盖范围及自然延伸方向 |

它给出的后续方向与前一句限制有关，因此不会像随意列举功能愿望。

参考论文关于四张 H200、生成速度和计算资源的说明属于其系统。我们不沿用它的性能数字，也不因同样采用联合生成就宣称已经实现实时或流式交互。

### 3.3 本项目可以学习什么

可以用一个短段落交代最相关的一至两个边界，让读者理解本文适用于什么设置。候选内容应从实际任务、方法或实验观察中选择，而不是从参考论文复制。

当前音频条件的短片段生成、多轮上下文、在线交互是不同研究范围。扩展到后两者可以作为未来方向，但不能写成本文当前已具备的能力，也不需要为了模仿 OmniPersona 而新增对应实验。

## 4. 与 Abstract、Introduction 和 Method 的分工

| 部分 | 主要职责 | 在结论中如何处理 |
|---|---|---|
| Abstract | 让读者快速了解问题、方法和结果 | 结论可保留核心信息，但不重新展开整套背景 |
| Introduction | 建立问题必要性与研究定位 | 结论直接回应这一问题，不再重述完整文献不足 |
| Method | 说明模块与监督如何实现 | 结论概括核心思路，不再列计算步骤和内部参数 |
| Experiments | 提供比较、消融及行为证据 | 结论提炼最重要的已验证发现，不逐列复述表格 |
| Conclusion | 回答本文最终带来了什么认识或能力 | 与前文证据保持同样的任务和比较范围 |

例如，Feature 的噪声构造、Event 的 pooling 和 BCE 都可以留在方法中；结论可概括为“适配生成条件与显式监督反馈类别”。Whisper 不需要在结尾单独拔高为一项主要贡献。

## 5. 本项目推荐的结尾组织

### 5.1 主结论：约四至五句

| 位置 | 要讲清的内容 | 表达重点 |
|---|---|---|
| 第一句 | 当前 speaker audio 与 listener reference image 到倾听阶段视听反馈 | 重申任务和总体框架 |
| 第二句 | Qwen 反应规划与 LTX 联合生成的连接 | 概括核心方法，不重复全部模型组件 |
| 第三句 | 配对视听数据、反应描述及 Feature／Event 监督 | 说明资源与训练目标如何支持该任务 |
| 第四句 | 正式实验已经确认的最重要发现 | 根据质量、类别行为及适用的人评结果填写 |
| 第五句（可选） | 对数字人视听倾听参与的启发 | 回应引言，控制在证据支持的范围 |

句子可以合并，尤其是第一、二句。结论不需要为了与贡献列表一一对应而机械编号。若评价协议是最终稿的重要组成，也可在数据与训练支持的概括中简要提及。

作为写作篇幅建议，可先控制主结论在约100–150个英文词，再按版面调整；这是编辑建议，不是会议格式要求。

### 5.2 局限段：从最相关的内容中选择

以下是可考虑的方向，不是已经确定的失败结论或新增实验要求：

| 候选边界 | 何时适合写 | 对应方向 |
|---|---|---|
| 当前条件只有当前话语和参考图像 | 需要说明本文任务范围时 | 研究上下文更丰富的连续交互 |
| 整段类别监督不直接规定精确事件时刻 | 解释行为控制粒度时 | 在保留多种合理回应的前提下研究更细的反馈控制 |
| 单一参考类别无法覆盖所有合理回应 | 解释评价结论范围时 | 更系统地研究多种合理反馈及与人类判断一致的评价 |
| 自动描述和外部检测存在可能误差 | 有对应核验或实际错误依据时 | 改善反应标注与检测可靠性 |
| 特定发声、动作或语境下表现不足 | 已有明确失败样例或分类结果时 | 针对已观察到的问题改进 |

任务范围可以客观说明；具体失败需要对应观察。不要把“尚未完成必要验证”包装为已经充分验证的方法只剩一个未来方向，也不把没有研究的所有功能逐项列为缺陷。

若保留局限段，可用两三句说明一个主要边界及其后续方向。主文中采用 `Conclusion` 后加 `Limitations` 段，或合并为一个结尾小节，均可按最终篇幅决定；无需因参考标题而新增复杂层级。

## 6. 语言与结论强度

### 6.1 先概括事实，再写结果与意义

完成的框架、数据组织和训练目标可以使用 `present`、`construct`、`combine` 等动词。性能句使用 `show`、`demonstrate` 或 `improve` 时，应能指向实际实验。

结尾的 `suggest` 可以表达谨慎的研究启发，但它仍然需要前文依据，不能替代验证。

### 6.2 不扩大比较范围

根据最终表格选择合适表述：

- 只在部分指标领先，就指出对应能力。
- 有总体优势但存在持平或退化，就使用准确限定，不写所有指标都最好。
- 视觉对照只支持共同视觉能力上的比较；不凭其音频 N/A 证明我方声音生成领先。
- 整段事件分数支持参考类别一致性，不能单独推出所有反馈都语境合理。
- 联合生成是框架形式，是否优于级联需要相应对照，不能在结论中新增加这一主张。

性能结论必须对应论文报告的模型版本、数据和协议。不要根据另一版历史模型的表现为最终模型写结论。

### 6.3 研究意义应具体

适合回到本项目的问题：数字人不仅需要画面逼真，也需要通过视觉和声音参与倾听；反应建模、学习资源和评价应围绕这一目标组织。

如果没有实际互动体验或人工评价证据，应把“改善用户体验”保留为研究目标或潜在价值，不写成已完成的实验结论。结尾可谈迈向更有参与感的数字人，但不扩展为通用对话智能已经解决。

## 7. 后续可填写的英文骨架

以下用于结果汇齐后的压缩写作；方括号仍是待填项，不是已经确认的实验结论。

```latex
\section{Conclusion}
\label{sec:conclusion}

We present a framework for generating audiovisual listening
feedback from the current speaker audio and a listener
reference image. The framework connects multimodal reaction
planning with joint audio--video generation, supported by
paired listening data and complementary feature and clip-level
event supervision. Experiments on [evaluated datasets]
show [the main verified findings and their comparison scope].
These findings [state the supported implication for
audiovisual listening generation].
```

如果最终内容需要更突出数据，可以将数据与反应标注拆成一句；如果后文已经解释评价，结论中一句提及即可，不必重新列所有指标。

**可选局限骨架：**

```latex
\paragraph{Limitations and future work.}
Our current [setting or design] is limited to [a supported
scope or observed limitation], which [explain the practical
consequence]. Exploring [a directly related extension] is
a promising direction for future work.
```

这里的 `limited to` 仅在确实表达范围时使用。若只是当前尚未研究某场景，直接描述当前设置也可以，不必人为加重缺陷语气。

## 8. 与现有草稿的关系

[当前LaTeX结论入口](CVPR2027-1109/draft_sections/08_conclusion.tex)仍以待补结论和局限为主。正式填写时，应依据当前确认的贡献组织、四组消融及最终实际结果，而不是直接复制占位备注中的早期五组安排。

本轮只记录分析和写作骨架，不改写正式 LaTeX 结论，也不预填 SOTA、人评收益、时序准确性或实时性能。

## 9. 结论的证据核对与自查

| 要写的内容 | 依据 | 当前处理方式 |
|---|---|---|
| GLARE 用数据、方法、评价和结果归纳反应建模意义 | 提供的 §7 文本 | 可借鉴组织方式 |
| OmniPersona 以局限对应后续方向 | 提供的 §5 文本 | 可借鉴叙述结构，不继承其性能或缺陷 |
| 本项目采用当前语音与参考图像条件下的视听反馈框架 | 任务定义及方法说明 | 按最终实现简洁归纳 |
| 数据与 Feature／整段 Event 支持生成学习 | 数据与方法说明 | 陈述设计与实现；实际增益另由消融支持 |
| 画质、反应、自然度或参与感提高 | 对应最终比较与适用的行为／人工结果 | 待实际证据决定措辞 |
| 局限与未来方向 | 任务范围、方法性质、核验和失败案例 | 选择相关且有依据的一至两项 |

定稿前检查：

1. **贡献：** 是否准确概括本文做过的工作，区分基座能力与本文设计？
2. **写作：** 是否比引言更集中，避免再次铺开背景、公式和模块细节？
3. **实验：** 每个效果结论是否有正式结果，比较范围是否一致？
4. **评价：** 是否把参考一致性、语境适当性和用户体验混为同一结论？
5. **方法边界：** 局限是否基于实际范围或观察，未来方向是否直接回应它？

适合本项目的整体做法是：借鉴 GLARE 的贡献收束与研究意义，再按需要借鉴 OmniPersona 的简短局限段。最终文字随着正式结果调整，不用在当前阶段固定尚未验证的效果结论。
