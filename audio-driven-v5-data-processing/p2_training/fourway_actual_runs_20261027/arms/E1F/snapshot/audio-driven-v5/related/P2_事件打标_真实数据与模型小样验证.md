## 3. 实模型小集与结果口径

在 Seamless 50 条中按时长选最短、中位、最长三个片段：

| 包内序号 | 样本 ID | 时长 |
|---|---|---|
| 003 | improvised_V00_S1432_I00000664_local_27882c5ec929 | 2.042 秒 |
| 032 | improvised_V00_S1485_I00001101_local_3bf4ca051198 | 6.804 秒 |
| 018 | naturalistic_V03_S1719_I00000264_local_a6d0888a719a | 11.127 秒 |

[小集清单](../experiments/listen_labeling_node8_models/smoke3_manifest.json)。这是接口与长度压力样本，没有按人工事件真值挑选，不保证覆盖正例。前面的模拟载荷测试使用原清单前 3 条，不能与这里的三条混淆。

每个分模态样本最多四次独立请求：视觉 discovery、音频 discovery、视觉 audit、音频 audit。audit 重读原媒体，不读取 discovery 文字；discovery 失败时保留其他分支的成功结果，不拼成完整草稿。Omni 模式是两次联合输入请求。

机器可读结果见 [model_smoke_report.json](../experiments/listen_labeling_node8_models/model_smoke_report.json)，包含全部轮次的 summary 路径、错误、合法阶段原文和服务器耗时。`succeeded` 仅表示完整草稿通过 schema；`inspected_minus_unknown_seconds` 是模型声称的支持区间扣除 unknown，**不是人工确认的监督时长**，也尚未计入训练格点/截边 mask。

### 已确认的问题

MiniCPM r4 最终为 **1/3 完整 schema 成功、2/3 失败**；唯一完整草稿的两类有效支持均为 0 秒。018 的视觉分支虽独立完成，音频失败使该条不能形成完整双路草稿。所有草稿仍待人工复核，当前没有可直接投入训练的完整样本。

- MiniCPM 初轮遗漏顶层字段、混淆容器；增加明确 JSON 骨架后仍出现 `[null]` 区间。最短片段在 r3 可形成完整草稿，但两个训练类的 coverage 都为空，不能贡献监督。r4 明确解释“检查后未见事件也应报告 reviewed”后，最短片段仍给出整段 unknown。032 的开放视觉输出把 owner 写为 uncertain 却不填写 uncertainty，音频含 `[null]`，均被严格拦截。不能把其自然语言“未发现事件”强制转成负标签。
- Qwen3-Omni 的纯音频分支完成最短片段的 discovery 与 audit：各约 25.3、36.6 秒，返回整段 reviewed、unknown 为空、events 为空。可作为待人工检查的候选负例；单个例子无法证明召回率或排除静音误判。
- Qwen3-Omni 的联合输入 r3 连续生成空白，约 182.6 秒达到时限，返回 `finish_reason=length`，已拒绝。需进一步查输入适配和推理配置，不能将这次失败解释成 Omni 模型天然不适合该任务。
- Joy 在 180 秒限制下输出被截断（约 261 token），已拒绝；对同一最短片段另做 600 秒限制的视觉重试，discovery 在约 235.9 秒、338 token 后完整返回，得到三个开放描述：口部运动、头部保持静止、眉部运动。其把静态状态列为事件，并从静音画面使用 speech-related 的措辞，三段边界都覆盖整条片段；这些需要人工检查，不能因 schema 合法就认定为三个真实 backchannel。独立 audit 在约 57.6 秒后通过 schema，报告全段已检查且未见点头。此轮视觉两阶段完成 1/1，总生成约 293.4 秒；仍未人工验证。

各轮 prompt 原文保存在对应 `branches/.../request.json`。提示词改动仅明确 JSON 结构、数字区间和检查覆盖含义，没有将开放发现改为封闭类别，也没有补造时间、将 null 转为空列表或修复失败结果后冒充原始合法标签。r1–r4 是小样上的接口调试轮次，不能当成独立测试集成绩。

## 4. 重现与阅读原始结果

基础准备命令、全 50 条输入清单见运行说明第 10 节。实模型客户端示例需在 node8 执行，且先启动对应本地服务：

```bash
cd /private/liqi_workspace/project_code/audio-driven-v5
/private/liqi_workspace/project_code/Omni-LTX-stage2/.venv/bin/python scripts/label_listen_events.py run --config experiments/listen_labeling_node8_models/minicpm_r3.json --manifest experiments/listen_labeling_node8_models/smoke3_manifest.json --mode split --output /path/to/new_smoke_run
```

`minicpm_r3.json` 的 r3 指部署配置；最新 r4 运行使用更新后的 prompt，原文和代码哈希独立记录。各模型启动命令、GPU 和本次 PID 保存在实验目录 `*.process.json`，**PID 是历史运行记录，不是永久可用服务**；只复制 command 复现，不直接照旧 PID 杀进程。模型 adapter 是小样验证工具，不是高吞吐生产服务。Qwen/Joy 有生成时限，MiniCPM 当前受最大生成 token 和客户端超时约束。

成功阶段的 `result.json` 保存解析结果、原始响应和输入媒体描述。`attempt-*.json` 保存所有尝试，包括截断/坏 JSON/连接失败；`runs/.../summary.json` 给出失败原因，`open_events` 保存开放发现，完整成功时生成 drafts 与 review_template。原始音视频、全量数据清单和已有训练代码未被这些测试改写。

## 5. 下一步判据

目前无需为了“能跑通接口”额外下载音频模型，已有 Qwen3-Omni 可先承担纯音频基线。先在明确有点头、短发声及静默的少量片段建立人工参考，确认听者身份和裁框，再比较开放发现的漏检/误报、边界误差、有效 reviewed 支持与人工修改时间。若 MiniCPM 持续不能稳定填写区间，应针对接口输出方式处理，而不是把它的 unknown 当 negative；Joy 先解决本次部署吞吐问题；Omni 联合输入先验证原生视听适配。

当前全部测试行维持 `training_admitted=false`。只有模型接口完成、标签复核和样本准入都通过，才进入既定 P2 S0；本轮没有用自动标签直接训练，也没有以模型自己的输出证明事件监督有效。
