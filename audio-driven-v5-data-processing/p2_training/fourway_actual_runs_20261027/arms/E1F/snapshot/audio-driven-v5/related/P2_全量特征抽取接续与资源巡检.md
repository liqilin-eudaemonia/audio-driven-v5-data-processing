## 范围与自动顺序

全量 **722,706 段，全部为原有 train split**；实测时长 2.0–11.95 秒，LTX 按原规则对齐后最多 305 帧。独立运行配置扩展旧 pilot 的 201 帧上限，不截断、不重新筛选样本。source 行哈希、split、角色、时长和预裁框均随数据保留。

1. 原始打标 → 七类语义归属 → 原文整合，由既有整合任务执行。
2. 每个整合分片落盘后，CPU 校验来源并分成每组 16 段的动态任务，提前准备媒体与标签。本轮先提高到原三机各 128、第四机 68 个媒体进程；媒体导出提速后改为四机各 96 个（当前作业完成后自然退出多余进程，可随巡检调整），单节点上限 128 个；已准备任务超过缓存水位时自动暂停预处理，避免无界堆积。
3. **全量整合写出 `COMPLETE.json` 后**，GPU 调度器等待上游进程释放显存，自动接手。它不终止原始打标、归类或其他程序。
4. 已在 node8 空闲卡提前完成新旧 VAE、input、teacher 逐元素一致性检查，共享 Gemma 文本缓存及最大 305 帧并发显存压力检查，`CANARY.json` 已通过。生产调度仍检查该门禁与上游完成状态。
5. 采用实测预设：每卡 2 个常驻抽取进程，上限也为 2；每进程 2 个 CPU 线程、预取 2 段。将原生模型 CPU 输入准备放入预取队列，并开启 expandable CUDA segments。实测峰值乘 1.05 后计算容量，另预留 16 GiB；OOM 时降并发。3／4 进程实验没有优于此方案，未启用。
6. CPU 与 GPU 并行核验完成的缓存。全部样本、文件哈希和清单通过后，生成总索引与 `COMPLETE.json`。

2026-10-25 后续巡检发现 CPU 校验池每轮只补充 8 个作业，原控制器每轮休眠 10 秒，导致校验吞吐约 10.9 段/秒、落后于抽取。已将现有配置 `poll_seconds` 从 10 调至 2，并由原 watchdog 仅重载 CPU 控制器及其校验池；56 个 GPU worker PID 不变，校验函数、哈希、总量及唯一性检查不变。运行中的节点监督器继续使用其启动时的 10 秒采样周期，后续重载时读取新值；20 分钟报告周期仍为 1,200 秒。变更与实测见 [本轮巡检记录](../experiments/p2_features_full_crop384_20261025/monitor/optimization-1792954265.json)。

## 抽取内容与复用边界

| 缓存 | 输入与用途 | 实现 |
| --- | --- | --- |
| `input` | speaker 音频＋listener 参考首帧，Qwen2.5-Omni-3B 多层 hidden H | 原运算语义；CPU 输入准备提前预取 |
| `teacher` | listener 目标视频及独立 listener 音频的 Omni 目标特征 | 原运算语义；CPU 输入准备提前预取 |
| `vae` | 512×512 listener 视频 latent、独立参考首帧 latent、listener 音频 latent | 原运算顺序及支持 mask，改为编码器常驻 |
| `text` | 固定正 prompt 与空负 prompt；所有样本共享一份 | 原 `cache_parts(..., ['text'])` |
| `events` | 七类事件区间、弱背景与 unknown 的时间栅格 | 原 `derive_sample()` 与 `rasterize()` |

输入与监督隔离保持不变，不把 listener 目标音视频放入 H，也不缓存可学习的 U。冻结模型、hidden 层、prompt、帧率和特征张量定义沿用交接文档；新代码主要负责常驻、预取和调度。

原 `features.py`、`runtime.py` 等基础实现没有改动，因此旧缓存身份仍可核验。新入口调用原生 `identity()`、`save_part()`、`load_part()`。依赖代码另存快照与 SHA-256，worker 启动前检查，源码变化不能静默混入同一运行。

## 媒体与标签

媒体复用此前 50 段已确认的导出方式：按同一个 listener 原始预裁框裁剪，再 bicubic resize 至 512×512，输出 25 FPS 视频与首帧；speaker、listener 各自从独立归一化音轨按样本点切出。保留完整真实时长；特征对齐所需尾部 padding 仍由支持 mask 排除。

建立只读来源行偏移索引，避免每个 worker 从头扫描十几 GB 的清单。每条实际使用的来源仍核对行 SHA-256。

2026-10-25 本轮巡检确认 4K 整帧 RGB/PIL 转换是供给瓶颈，已启用[独立版本媒体导出器及等价验证](../experiments/p2_features_full_crop384_20261025/media_export_v2/README.md)：只转换最终实际使用的源帧，对可验证的偶数尺寸逐行 YUV420P 先处理带对齐边界的局部区域，其余保留原转换；每段首个图像布局做逐像素核对，不一致退回原方法。96 组像素和 28 组取帧测试通过，真实整段四文件 SHA-256 一致，单段导出从 52.6 秒降至 12.7 秒。冻结特征代码与已有缓存哈希不变。

少数 speaker 音轨从 48 kHz 重采样到 16 kHz 时，`resample_poly` 向上取整比原接口要求的 `round(duration*16000)` 多 1 个样本。现有流水线的 [CPU 样本网格适配器](../scripts/repair_p2_audio_sample_grid.py) 只处理经哈希核实且严格多 1 个点的情况，原 WAV 保留；派生 FLOAT WAV 使用同一重采样结果的前 N 点。变更在作业锁内提交，已完成缓存不改，逐条事务记录在 `audio_grid/jobs/`；中断可恢复，3 项回归通过。listener 目标音轨、标签和时间不变。

事件缓存复用当前确认的弱背景规则：有效完整视图回执支持已覆盖时间；事件为弱正例，不确定与未定位证据遮罩。缺失／失败的完整回执不能生成背景负例；存在语义归类失败时，该样本事件监督保持 unknown。原文整合文件不覆盖，归类和描述不重新改写。

媒体校验通过后的 `target.admitted=true` 用于满足原生 P2 媒体／缓存接口，避免今后仅改变这个标志就导致冻结缓存失效；它不是正式训练数据集放行。派生记录仍保留 `formal_training_admitted=false`、来源状态和逐条审计；没有启动训练。事件标签的 `training_admitted` 表示是否具备本规则可栅格化的弱监督，正式数据接入仍须查看 provenance 与问题记录。
