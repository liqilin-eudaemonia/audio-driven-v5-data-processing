# P2 单卡/双卡数值一致性：根因修复与验证

日期：2026-10-25。状态：**已修复并通过本轮全部严格验收**。105 项 CPU 测试、CPU 双进程对照、真实 GPU 单/双卡 E0/E1、恢复重放和独立生成均通过；两组单/双卡最终参数最大差均为 **0**，原阈值 `2e-5` 未放宽。[最终汇总](../experiments/p2_listen_ddp_fix_v2_20261025/summary.json)。

## 1. 原问题与定位证据

此前 GPU 功能检查已通过，但同初始化、同样本/预算的 7 步单卡/双卡参数比较未通过 `2e-5` 阈值：E1 最大差 `5.76e-5`，E0 对照也达到 `8.64e-5`。历史记录保留于[上一轮报告](P2_弱背景监督GPU验证与数值修复.md)，不覆盖失败结果。

本轮不修改阈值，先固定真实样本、模型初始状态、噪声种子和目标，完全不执行优化器更新；在同一张 GPU 上比较重复反向、增加梯度审计、loss 乘 2 后将梯度除以 2。视觉/音频完整生成损失、feature 损失和事件损失均在场，事件使用 E0 模式，以隔离事件反馈到 U 的影响。

[backward_diagnosis.json](../experiments/p2_listen_ddp_fix_20261025/backward_diagnosis.json)记录：

| 对照 | 默认 GPU 反向的最大梯度差 | 默认相对 L2 差 | 开启确定性算法后的最大差 |
|---|---:|---:|---:|
| 同状态重复反向 | 3.05e-5 | 0.00577 | 0 |
| 同状态增加梯度审计 | 3.05e-5 | 0.00610 | 0 |
| loss 乘 2、梯度除 2 | 3.05e-5 | 0.00541 | 0 |

诊断两阶段均使用 `CUBLAS_WORKSPACE_CONFIG=:4096:8`，唯一切换项是 `torch.use_deterministic_algorithms(False/True)`。默认路径在同卡重复时已经不稳定，说明无需 DDP 也能复现问题；确定性算法使三组受控对照的梯度完全一致。这是 GPU 反向数值路径的直接证据，并非通过放宽最终参数阈值得出的判断。没有据此未经进一步分解就指认某个单独 CUDA kernel。

复现脚本：[diagnose_backward.py](../experiments/p2_listen_ddp_fix_20261025/diagnose_backward.py)。历史 FP32 事件头修复仍保留，本轮没有再修改事件结构、弱背景标签、BCE、类别权重或 E0/E1 定义。

确定性设置单独应用后的第一轮完整复测保存在 [ddp_comparison.json](../experiments/p2_listen_ddp_fix_20261025/ddp_comparison.json)：E1 最大参数差 `1.53e-6` 通过，但 E0 `3.65e-5` 仍失败。因此确定性算法是必要修复，但不足以消除单卡顺序累加与双卡局部累加/归约的差异。第二轮将每个 microbatch 的损失统一为全局归一化，并提高梯度累加/归约精度；最终证据见下节。

## 2. 代码修复

- [numerics.py](../src/p2_listen/numerics.py)：新增固定策略 `p2-deterministic-training-v2`。在 CUDA 初始化前设置受支持的 cuBLAS 工作区；启用确定性算法且不允许仅警告后继续；关闭 cuDNN benchmark，启用 cuDNN deterministic。无有效工作区且 CUDA 已初始化时直接报错，避免设置太晚却声称生效。
- [gradients.py](../src/p2_listen/gradients.py)：每个 microbatch 的反向梯度独立转为 FP64 累加；双卡关闭 DDP 自动梯度归约，统一在本步结束时执行 FP64 SUM，最后一次转回参数精度，再裁剪与更新。基础损失按全局 batch 归一化，事件损失按全局有效类别/bin 归一化；不额外乘 world size 或再取平均。保留未使用参数的 `None` 语义，先同步参数使用标记，避免部分 rank 无梯度时漏掉归约。
- [training.py](../src/p2_listen/training.py)：所有训练入口都先配置上述策略；将策略、工作区、精度标志、Torch/CUDA 版本写入 run、pair 和 checkpoint identity。各 rank 继续核对完整身份，断点恢复继续要求严格身份一致。数值身份额外记录 `gradient_accumulation=fp64`、`gradient_reduction=sum`、`loss_normalization=global_batch`。
- [check_p2_listen_gpu_replay.py](../scripts/check_p2_listen_gpu_replay.py)：恢复重放使用相同数值策略，缺失/不同策略拒绝重放。模型/优化器和 forward 容差保持原值，不改为更宽阈值。
- [check_p2_listen_gpu_pair.py](../scripts/check_p2_listen_gpu_pair.py)：可重复执行的单/多卡验收入口；核对配置、数值策略、源码/资产、初始化、标签、全局样本序号、监督计数、检查点身份和参数。参数阈值仍固定为 `2e-5`，失败会保存报告并返回非零退出码。
- [test_p2_listen_numerics.py](../tests/test_p2_listen_numerics.py)：新增设置时机、严格确定性、不初始化 CUDA、合法工作区保留、错误工作区及检查点策略不一致等回归测试。

BF16 主模型与 FP32 事件头的分工不变。旧数值路径的历史检查点不能冒充新策略的严格续训；本轮从相同随机初始化重新训练，保留全部旧结果。特征/媒体/标签缓存身份未变，在核验后复用，不重复打标或重提取 Omni H。

- [test_p2_listen_gradients.py](../tests/test_p2_listen_gradients.py)：验证大数相消时小梯度保留、零梯度与未使用参数区分、累加不修改参数及跨步重置、错误 world size 拒绝。105 项单元测试通过；[CPU 双进程对照](../experiments/p2_listen_ddp_fix_v2_20261025/cpu_ddp.json)覆盖某 rank 没有事件监督和类别计数不等的情况，E0/E1 连续 3 步最终参数差均为 0。

## 3. 本轮复测安排与产物

第二轮目录：[p2_listen_ddp_fix_v2_20261025](../experiments/p2_listen_ddp_fix_v2_20261025/)。机器仍为 `172.29.104.220`，只使用授权的后四卡中的 GPU 4/5/6，不停止其他任务；本轮按当时约 58–60 GiB 可用显存和既有约 50.5 GiB 单卡实测设置 56 GiB 启动门槛。

- 同一批 50 条真实弱标签样本，六类有效；摇头仍因无正例屏蔽。
- global batch 8，seed 20261027，单卡 E0/E1 各 7 步。
- E1 第 5 步停止，恢复至第 7 步；第 6→7 步重复重放。
- 双卡 E0/E1 各 7 步，同初始化、同有效 batch、同数据顺序，均与单卡对照。
- 新检查点独立生成一段 512×512 音视频，检查源输入隔离及实际解码/时长。
- `preflight.json`、`job_status.json`、训练日志、数值策略与源码指纹、原始输入保护哈希分开保存。

确定性计算和 FP64 累加/归约可能增加训练耗时；FP64 只用于可训练模块的梯度累加缓冲，不将冻结 LTX、前向激活或模型权重转为 FP64。本轮还叠加了共享机器上的其他任务，不能把本轮耗时变化全部归因于数值设置。这里验证的是工程和数值一致性，不能当作生成质量收益或正式效果实验。

这次通过来自数值路径修复：严格确定性反向消除同状态重复反向波动，统一全局损失缩放和 FP64 累加/求和消除本轮 rank 分组引入的最终更新差异。事件标签、BCE、有效类别归一化、事件权重、E0/E1 定义和验收阈值没有改变。

旧报告中的“首轮只能先使用单卡”是当时未通过跨卡验收的阶段性安排；当前实现已经通过同初始化、同全局 batch 的单/双卡对照。正式实验仍须保持两组配置、数据和预算匹配。这 50 条是 debug 数据，7 步仅检验代码和数值链路，不能据此断言事件监督改善生成效果，也不保证任意环境、GPU 或训练长度下位级一致。更换环境或数值策略需重新验证，旧策略检查点不能直接按新策略严格续训。
