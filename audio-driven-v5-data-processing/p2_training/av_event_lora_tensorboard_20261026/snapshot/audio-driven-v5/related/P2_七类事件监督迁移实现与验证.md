## 模型、标签和损失

固定类别顺序为 `head_nod, head_shake, smile, laugh, frown, surprise, listener_vocalization`。`contracts.py` 保存显式类别到模态表；`EventHeads` 是视觉 `Linear(6)` 和音频 `Linear(1)`，输入都是实际供给 LTX 的最终 U。上层仍返回七个按类别命名的张量，视觉 `[B,Tv]`、音频 `[B,Ta]`，允许 Tv 与 Ta 不同。所有原来的两元素类别 zip 已移除。

标签 schema 为 `listen-events-v2-visual6-audio1`，实验版本为 `p2-listen-event-v2-visual6-audio1`。必须提供七类 coverage/unknown、coverage 来源、准入记录、mapping/接受政策版本；事件保存唯一 ID、原文、来源、核验和边界状态。未准入标签不能导入或产生已知训练 bin。覆盖不完整、unknown、censored、结构 padding 和尾部部分有效 bin 均屏蔽；投影按秒计算事件并集的占用率，不改变原始事件次数。

配置 `events.K_train` 是请求监督的类别集合，必须遵守固定顺序，可为空。按 **train** 的已知支持统计正负占用，缺正例、缺负例或无覆盖的类别自动停用并记录原因；最终有效集合冻结在 `pair.json`、`run.json` 和 checkpoint identity 的 `K_train`，E0/E1 必须一致。后续评测的 `K_train` 应使用这个有效集合。此筛选不使用 dev/test，也不改变七个输出通道。

每类 BCE 先按整个 optimizer step（全部 rank 与累积 micro-batch）的有效 bin 数归一化，再对当步有支持的启用类求均值。七类均有效时每类权重为 1/7。`pos_weight=min(Nneg/max(Npos,1),cap)`，仅从 train 冻结。全 unknown 时事件项是可反向的零项，AV/feature 仍训练。

E0 的事件输入 detach，E1 回传 U；保留公共模块与事件头分别裁剪。S0 审计扩为七类逐类梯度和两种模态的 AV/feature/event 路径。

## 从现有候选导出

新命令只做 CPU 数据转换，使用当前原文整合的 `labels.candidate.jsonl`、对应 `review.json` 和 `observations.jsonl`。不重新推断类别、不去重第二次、不改词、不修边界、不加窗口偏移；输入时间已经是 clip-local 秒数。

```bash
cd /private/liqi_workspace/project_code/audio-driven-v5
CUDA_VISIBLE_DEVICES='' /private/liqi_workspace/project_code/Omni-LTX-stage2/.venv/bin/python scripts/p2_listen.py export-labels \
  --candidates experiments/listen_existing_fusion_verbatim_20261025/labels.candidate.jsonl \
  --review experiments/listen_existing_fusion_verbatim_20261025/review.json \
  --observations experiments/listen_existing_fusion_verbatim_20261025/observations.jsonl \
  --output /tmp/p2_v2_draft_new
```

输出目录须不存在或为空。不传 `--decisions` 时输出未准入草稿：coverage 全空、所有训练 bin 未知、0条 accepted event。候选没有被删除，完整输入逐字节保存在 `sources/`，全部候选的映射和未决原因保存在 `audit.json`。

有实际核验或已批准弱标签政策后，使用独立 decisions 文件，并以同一配置增加 `--decisions /path/to/decisions.json`，写入另一个新目录。每个 decisions 样本需要：

- `schema=listen-candidate-decisions-v2`、`sample_id`、`candidate_sha256`。该 hash 是 `p2_listen.contracts.digest(完整候选样本对象)`，不是文件 hash；候选改动后旧 decisions 会拒绝使用。
- 七类 `coverage` / `unknown`，以及 `coverage_sources`；非空 coverage 的来源包含 `reference` 和 `verification=human|weak_accepted`。必须实际检查覆盖，不能从稀疏候选自动生成全段负例。
- 两路目标媒体 SHA256、`admission_record.reference`、`source_review_reference` 和布尔 `human_verified`。
- `events` 内逐候选 `candidate_event_id`、`decision=accepted|rejected|unresolved`、`reason`。accepted 还需 `verification=human|weak_accepted`、`boundary_status=verified|weak_accepted|censored`、与候选相符的 `reviewed_flags`。

接受事件必须已有且仅有一个合法类别、模态匹配、有有效边界。复合描述不会被自动拆分成多类；修改文字或边界需要上游产生新的、可追溯的候选版本。一个未提供 decision 的候选保持未决，其区间在相关类别屏蔽；不因整体准入而成为负例。未定位词保留原记录并保守屏蔽该段音频类；上游待核验观测按可用模态/类别/时间屏蔽，无法定位时保守扩大 unknown。`out_of_scope` 观测继续保存在源数据，不强行分类。

`labels.json` 保存全部 canonical 标签/草稿，`labels.admitted.json` 单列已准入样本供 `import-labels` 使用，支持先核验少量样本。没有准入样本时后者为空，不能用于开训。`audit.json` 保存 `candidate_event_id → training_event_id` 和排除原因。接受事件的 `source` 保留完整原候选对象，含所有原描述、描述出处、时间证据和分歧标记。导出还保留对应 review 与全部原始观测的原文件及 hash。

**当前50段验证：** [`sample50_final/summary.json`](../experiments/p2_listen_v2_migration_validation/sample50_final/summary.json) 记录175条候选、682条原始观测、2个未定位词；50段均未准入，接受事件0。仅验证适配和完整性，没有编造弱标签政策或人工核验结论。

## 导入、缓存、恢复与推理

`import-labels --labels /path/to/labels.json` 验证已准入七类 schema、固定 taxonomy、mapping/政策与配置一致、真实目标媒体 hash；dev/test 还要求事件、边界和已知 coverage 的人工核验。一个批次先全部验证再写 canonical。包含未准入草稿的批次会拒绝，不能只把原候选的布尔值改成 true 后导入。

事件缓存签名包含新 schema、taxonomy 顺序、请求的 K_train、mapping/政策、完整标签与时间网格。标签或监督集合改变时事件缓存失效；同一代码/输入/布局条件下 H 缓存不受这些标签改动影响。输入媒体或布局改变仍正常失效。本次代码版本升级保留原有源码指纹检查，没有添加忽略旧缓存指纹的开关。

checkpoint 增加显式实验版本、label schema 和 taxonomy；旧二类头、optimizer、旧 taxonomy 或改变的 run identity 均拒绝严格恢复。没有实现隐式 warm start，也没有使用旧权重启动新实验。

推理仍只使用 speaker 音频、listener 首帧、固定文本和外部几何，读取七通道 probe，但不把标签、描述或 probe 输出作为生成控制输入。真实模型推理与梯度仍须在 GPU S0 验证。

早期 `listen_labeling` 的二类 schema/validator 已隔离到 `legacy_contract.py`，保持它的历史 prompt、类别和导出含义。旧工具输出的 `listen-events-v1` 不能直接导入七类训练；这是显式版本拒绝，不会自动补五类负例。当前全量开放打标和原文整合不使用该旧训练接口。

## 评测

评测协议新增 `schema=p2-listen-evaluation-v2-visual6-audio1`、固定 `taxonomy`、`K_train` 和预先冻结的非空 `K_primary`。报告全部七类的监督状态、参考数量、有效/未知时长、F1，以及视觉类别集合/分数、音频 F1 和失败率。K_primary 必须是 K_train 的子集。

未启用/未知类不以0混入主平均；预定主类缺参考正例时完整 macro 为 N/A，另列有参考正例的公共子集并明确类别。主集合只有一类时报告该类 `primary_f1`，`macro_f1` 为 null。配对差值与 bootstrap 使用冻结主集合；重复回应仍逐类一对一匹配，生成失败仍计 FN。

边界诊断与计划同步为起点0.2/0.5秒容差，新增 offset MAE 和起止均在0.2秒内的比例；onset 容差命中也一对一，不能用一个预测重复命中多次参考。评测不使用训练头作为裁判。
