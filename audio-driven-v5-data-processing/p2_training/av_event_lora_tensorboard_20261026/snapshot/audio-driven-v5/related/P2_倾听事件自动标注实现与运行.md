# P2 倾听事件自动标注：实现与运行

日期：2026-10-23。当前版本：`listen-labeling-v2-open`。状态：**开放发现 + 独立目标检查、媒体准备、分阶段续跑、人工修订导出及 P2 标签导入链路已实现；使用合成媒体和本地模拟 HTTP 服务验证，已完成 RealTalk/Seamless 真实媒体适配，node8 实模型小样联调进行中，标注质量尚未完成验收。**

总索引：[README](../README.md)。实验目的与训练入口见 [P2 实验计划](P2_倾听事件监督实验计划.md)、[P2 代码运行说明](P2_倾听事件监督实现与运行.md)。本实现独立于生产数据筛查，不扫描或占用已有 QC4 任务的媒体和 GPU。

## 1. 本轮选择与边界

按先把代码准备好、数据稍后提供的安排，实现以下默认路径：

1. **开放发现 discovery**：Joy 接收带时间戳的倾听者静音画面，音频模型接收倾听者独立完整波形。prompt 不列举行为类别，模型自由描述事件及直接证据，保留细微、复合、难以命名的动作或声音。
2. **独立目标检查 audit**：对每路再发一个新的请求，重新送入原始媒体，明确检查当前训练用的点头或倾听者发声；不向该请求提供 discovery 描述，避免其遗漏直接变成负例。
3. 将 audit 的两路结果按片段时间轴确定性合并，允许事件重叠、边界不同。P2 仍只训练 `head_nod`、`listener_vocalization`。
4. discovery 的自由文本、证据、不确定性及可选解释独立保留。它没有封闭行为枚举，也不经过关键词/类别强制归并；audit 失败时，已完成的开放发现仍可查看和复用。
5. 导出复核队列和可编辑 P2 标签 JSON。人工确认后导出 P2 标签；训练集也可显式选择导出未核验弱标签。

**每个样本默认 split 模式发 4 个请求（两路 discovery，再两路 audit）；Omni 模式发 2 个请求。** 均调用该分支配置的同一模型端点，第二阶段为新的单轮消息，不继承上一轮会话。增加的调用用于获取独立的目标检查；不声称消除了同一模型的系统性偏差。

同时实现 `--mode omni`，把同一组带时间戳的画面和真实波形送到一个多模态端点，用于联合标注对照。它是“时间戳图像序列 + 音频”的输入协议，**不是已经验证的原生视频音频同步编码路径**。两种方式的质量高低需要真实小集对照，不预设拆分一定更好。

这里的 Joy 是用户指定的 [JoyAI-VL-Interaction](../../JoyAI-VL-Interaction/)。其现有 [emotion labeling](../../JoyAI-VL-Interaction/caption/README_emotion_labeling.md) 是视觉和转写文本的片段级情绪代理，不能直接当作声学事件标注器。本实现复用其 HTTP 图像消息形式，独立编写事件提示词，不使用旧情绪标签、逐秒 speak/silent/delegate 决策或 300ms VAD 门槛。

## 3. 数据输入

清单支持 JSON 数组或 JSONL。每条必须有：

```json
{
  "sample_id": "example_0001",
  "experiment_split": "train",
  "target_video": "/path/to/listener.mp4",
  "target_audio": "/path/to/listener.wav",
  "duration_s": 6.4,
  "time_origin": "clip_start_seconds",
  "video_role": "listener",
  "audio_role": "listener",
  "audio_isolated": true
}
```

路径相对清单文件目录解析。程序计算两个媒体的 SHA256；若清单已给 `media_hashes`，必须完全匹配。视频时间从零开始；音频参与标注时，其时长也必须与声明一致。输入音轨必须已经是倾听者独立单声道，不自动把双人立体声音轨混成单声道。新增 `--mode visual` 可只检查视觉，允许保留 `audio_role=mixed, audio_isolated=false` 的源混音路径用于溯源，但绝不发送该音频；split/omni 仍要求独立 listener 音轨。角色字段是上游声明，**代码不能仅凭声明证明人物/声音归属正确**，仍需数据准入和复核。

标注可在 P2 数据准入之前开展，但之后导入训练必须使用相同 `sample_id`、时长和媒体哈希。若重新裁剪/降噪/归一化改变媒体，需要重新绑定标注，不能手工替换哈希复用。原画在线裁剪输入还必须绑定 `video_transform`，含原画尺寸、crop、512 输出尺寸和插值方法；它参与视觉缓存身份和标签 provenance。训练清单还需要 speaker 音轨、listener 首帧和分组身份等，见 P2 数据接口。

对带 `video_transform` 的原画输入，每个采样帧先按原坐标裁剪，再以 PIL bicubic resize 成精确 512×512，最后编码 JPEG；`max_edge` 不会把该路径缩小。没有 transform 的既有预裁剪输入继续使用 `max_edge` 上限。

默认按 8 FPS 目标网格选择后续实际解码帧，每帧文字注明真实 PTS。例：25 FPS 源的某个采样点实际是 0.16 秒，就传 0.16，而不是虚构为 0.125。最多 128 帧、最长音频 16 秒；超过预算报错，需明确切更短片段或调整预算，不悄悄稀疏抽帧，也不自动切窗后猜测事件跨窗合并。8 FPS 是待校准的起点，不能保证精确辨认更短的点头。

音频保留完整时长和源采样率，以 PCM16 WAV 传输；无 VAD 删段、无 ASR、无响度归一化、无自动重采样。浮点输入转 PCM16 会量化，原文件哈希与实际传输 WAV 哈希均保留。端点须接受这一采样率；若部署需要重采样，应显式增加可追踪的适配后再联调。

## 4. 配置端点

配置中的 `7060/7061/7062` 是本地服务地址模板，**未检测或启动这些服务**。Joy 的默认名称来自本地仓库；Qwen2-Audio 和 Qwen2.5-Omni 的名称只是可替换候选，不表示服务已部署或质量已验证。

每个端点使用 `/v1/chat/completions`：

- visual：必须接受 `image_url`，内容为 JPEG data URL。
- audio：必须接受 `input_audio`，内容为 base64 WAV。
- omni：必须在同一个 user message 中同时接受上述两类内容。

部署时核对 `base_url`、实际 served model name 和 `revision`（权重/部署版本）。同名服务替换权重或更改其服务端处理逻辑后，必须更新 `revision`，否则客户端无法知道服务改变。默认 `unverified-initial-deployment` 仅表示尚未联调。端点的 `capabilities` 是显式配置声明，离线校验不会证明服务真的支持它；真实联调由 HTTP 返回与小集人工核验确认。

密钥仅从 `api_key_env` 指定的环境变量读取，不写进 JSON；无密钥本地服务可留空。不允许 URL 内嵌凭据或任意密钥配置字段。当前客户端不是本地 Transformers 推理器，也不包含模型部署脚本；服务不支持上述输入协议时需适配，不能退化成只送转写文本。

固定 temperature=0。网络超时和部分临时 HTTP 错误有限重试；400/鉴权错误、JSON/字段错误、时间越界、`finish_reason != stop` 等保存证据并失败，不自动补造合法标签。

目录结构：

```text
labeling_run/
  latest.json                          # 最近一次调用的 summary 路径
  branches/<id>/<branch>/<discovery-or-audit>/<fingerprint>/
    request.json                       # 提示词、配置、请求哈希、帧时间/传输哈希
    attempt-<timestamp>.json            # 每次 HTTP 原始状态/响应或传输错误类型
    result.json                        # 只有完整响应通过验证才写入
  runs/<run_id>/
    inputs.json                        # 输入、配置、代码身份快照
    summary.json                       # 成功/失败、draft 路径、复核模板路径
    drafts/<id>.json                    # P2 canonical 弱标签
    open_events/<id>/<branch>.json      # 每路开放发现一完成就保存，包括 audit 失败样本
    rich/<id>.json                      # 完整样本的各路 discovery/audit 结果
    review_queue.json                  # 所有样本、媒体路径、错误及复核原因
    review_template-<hash>.json         # 可复制编辑的复核记录
```

任一必需阶段失败会保留其他已完成阶段和开放事件，但不发布该样本的合并 draft。summary/review_queue 中的 `open_events`、`stage_results` 指向实际产物，包括失败样本。批次有失败时 CLI 返回非零状态；summary 保留完整成功/失败计数，不把成功子集冒充全批完成。恢复后新增成功样本会产生新的复核模板，旧模板和人工副本不被覆盖。

## 6. 标签语义与人工复核

两阶段都要求顶层 `reviewed`、`unknown`、`events`、`notes`，但其语义不同，不能互换：

- **discovery** 的 `reviewed/unknown` 按证据模态 `visual/audio` 记录，表示哪些媒体区间被查看/存在不确定性，**不代表某种行为的负标签或穷尽检查**。事件没有必填类别，使用 `start/end/modality/owner/behavior/evidence/uncertainty/boundary_censored`。`behavior/evidence` 为非空自由文本；`owner` 可为 listener 或 uncertain，后者必须解释归属疑点。`confidence` 可选；其他描述细节允许保留。可选 `interpretation` 单列可能的沟通含义，prompt 明确要求它只是推测，不能冒充观察事实。代码验证结构，不声称能从文字自动判定证据是否真实。
- **audit** 的 `reviewed/unknown` 按当前训练目标 `head_nod/listener_vocalization` 记录，正例事件保持既有 P2 格式。它需要独立检查原媒体，明确正例、检查过的负例和不可判断区间。

开放事件示例见 [open_discovery.example.json](../examples/listen_labeling/open_discovery.example.json)。这里可以保存“嘴唇轻抿后身体稍前倾”等未命名的复合行为，无须归入 `other_visual` 或任何固定类。Omni 模式也按证据模态分别记录可重叠的事件，不能只靠画面宣称有声音。

**只有 audit 的 `reviewed` 映射成 P2 `coverage`。** discovery 的空列表、自由描述中出现的类别词、甚至声明检查了全片，都不能自动变成点头/发声正负监督。audit 未报告事件也不自动产生全片负标签；只有明确检查过、无 unknown 的区间才参与监督。模型声明的 inspected negatives 仍然是弱证据。

自动 P2 输出 `provenance.human_verified=false`，分别绑定两阶段 fingerprint。自报 confidence<0.7 仅提示复核，不作为已校准概率或训练权重。开放事件的不确定性另列复核原因；它不覆盖独立 audit 的类别判断。P2 仍依据 audit 的 unknown 和边界截断标记屏蔽监督。

开放发现可能漏检，也可能把普通运动当候选；自由描述并不保证收集到全部 backchannel。后续可对描述归并、复核形成数据驱动类别，或研究文本表示监督；本次不自动聚类、不新增训练类别头、不改变 E0/E1 实验。

复核方式：打开 summary 中指向的 `review_template`，复制为自己的 review JSON。模板还附带 `open_events` 路径供同时查看；当前 human_verified 只确认 P2 两类标签，不宣称所有开放描述均经人工确认。结合原媒体修订每条 `label.events`、`label.coverage`、`label.unknown`；可部分留 unknown，不要求把不可判定区间硬标负例。逐条填写外层：

```json
{
  "sample_id": "example_0001",
  "draft_sha256": "保留模板内原值",
  "human_verified": true,
  "reviewer": "实际复核者",
  "reviewed_at": "2026-10-23T12:00:00Z",
  "label": {"此处为模板里完整的标签对象": "编辑事件及覆盖，不修改 provenance"}
}
```

上例仅解释复核记录结构，不是可直接导入的标签；实际使用生成的完整模板。外层 true 表示已由所填复核者检查；代码检查记录/媒体身份，不声称能验证人是否真的看过视频。内层 provenance 保留，导出时由程序写入复核信息、draft/review 哈希并把事件标为 human。

导出已复核标签：

```bash
/private/liqi_workspace/project_code/Omni-LTX-stage2/.venv/bin/python scripts/label_listen_events.py export --summary /path/to/summary.json --reviews /path/to/my_reviews.json --output /path/to/reviewed_labels.json
```

如果明确选择将自动弱标签用于训练集：

```bash

```

该选项只放行 manifest 中的 train，dev/test 始终需要人工复核；`unassigned` 或 `training_admitted=false` 的兼容性样本不导出训练标签；输出报告列出跳过和失败样本。它不自动导入训练目录。首轮 S0 建议仍逐条人工核验。已准入 P2 数据后导入：

## 7. 数据到位后的第一轮

先取既定 S0 小集（8–16 train + 约 8 dev），覆盖静默、短发声、点头、双事件重叠和难例。进行端点单样本联调，再运行两路标注并逐条复核，记录漏检/误检、边界偏差、声源归属和修订耗时。可在相同小集跑 Omni 对照；疑难样本也可单独整理子清单跑 `--mode omni`，人工对比两份结果。本轮没有自动让 Omni 覆写两路标签的机制。

确定标签可用后再进入既定 P2 S0，不直接开展 RL 或扩大类别头。模型质量仍需用独立人工结果衡量；不使用正在训练的事件头给自身打分。当前未实现浏览器复核 UI、模型内置定位器、自动长片切窗和超大批并发；首轮使用媒体播放器加 JSON 修订。

## 9. RealTalk 随机 50 条：原画坐标裁剪与 512 输入核验

用户提供包：[annotation_test_random50_20261023](../../../realtalk_processing/annotation_test_random50_20261023/README.md)。本次检查使用包内原画 MP4 和 samples.json，没有运行包内 export.py、访问原始 tar 或改写全量切分结果。

实际结构：50 个原画片段，25 个固定提议框、25 个 `crop=null`；已有 25 个 listener MP4 是按框裁出的原生尺寸，个别奇数边长为编码右/下补 1 像素，仍未 resize 到 512。WAV 是源双人混合音频；单声道不代表 listener 已分离。p0/p1 是视频内角色，`start_frame/end_frame` 为原视频帧号，导出片段自身的 PTS 已从 0 开始。

处理约定：

- 一律使用 `original_video` 解码，按 `crop.x/y/width/height` 裁剪，再 bicubic resize 为 512×512。无需先导出整条物理裁剪视频，也不使用已有 `listener_video` 再套原坐标。
- 不补猜 `crop=null` 的框、不降级到全图、不静默截断越界框。不修改原来的 crop、flags 或训练准入状态。
- 角色、片段起止、完整提议框及 flags、metadata/frame_annotations 的路径和哈希写入 `source_reference`；source frame = clip frame + start_frame。逐帧 bbox 仍是原画坐标，不替换固定 crop，不把 current_speaker/score 作为行为 GT。
- 对应 bbox 若需可视化到 512：`x'=(x-crop.x)*512/crop.width`、`y'=(y-crop.y)*512/crop.height`；越界和无效 bbox 必须保持标记。本次模型只接收裁剪画面，不发送 bbox 或说话分数提示。
- 所有导入行保持 `experiment_split=unassigned, training_admitted=false`；兼容性检查不等于合格训练样本。视觉模式的 P2 draft 中音频 coverage 为空，整段音频 unknown，不把未听音当作静默。
