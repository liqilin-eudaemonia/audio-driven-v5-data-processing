## 自动流程与资源接续

1. **CPU 提前准备。** 一个分片的视觉、音频、ASR 三支原始任务都写入完成标记后，16 个 CPU 进程并行读取（初始为4，本轮巡检因GPU提速后有待整合分片而提高）、核对来源与窗口，保存完整原文观测和语义请求。原始打标仍在运行时即可准备。
2. **已释放 GPU 补七类语义元数据。** node17、node12、node4 及新增 node8（172.29.104.220，仅 GPU 4–7）均部署守护进程，每 10 秒检查一次。原始 worker 正常结束、显存释放且没有上游重新分配时，对应卡自动启动 Qwen3-VL-8B 的纯文本语义归类。最多 28 卡，原三机24卡 batch 512，新增 node8 四卡 batch 128（大批次出现间歇延迟后回退；运行配置中逐卡覆盖），vLLM 显存预算 0.85；需要模型加载时间。原始视觉队列仍多时，原始调度器优先把音频／ASR 完成的卡转给视觉。
3. **CPU 逐分片原文整合。** 归类完成即执行已确认的 `listen-existing-result-fusion-verbatim-v2`。不等全量 GPU 任务一起结束；全局原文完全相同、模态相同、prompt／模型签名相同的语义请求共享缓存，大小写等差异不会模糊复用。
4. **全量审计。** 1,024 个分片输出完后检查文件 SHA-256、722,706 个 sample_id 全局唯一及总数，最后写 `index.json` 和 `COMPLETE.json`。语义队列完成后 GPU 正常释放，最终文件校验由 CPU 执行。

GPU 仅用于尚未具备的“六类视觉＋一类音频”语义归属，不重新观看视频或听音，不用 GPU 改写描述。描述原文和 ASR 原词保留。纯去重、时间区间整理和证据关联仍由 CPU 完成。

## 内容与质量契约

- 开放原始事件全部保存在 `evidence/`，主候选在 `labels/`。七类是附加元数据，不是替换自然语言的硬映射。
- 沿用原文整合版本，不把“嘿”改成笑声、不把 Ed 换成 Yeah、不添加 Says 模板；来源冲突和未定位词仍可追溯。
- 按既有原文整合规则处理跨窗重复与独立发声；不把上层回应组的整个包络当作持续发声区间。没有重新验证 ±0.2 秒精度，结构校验不能代替准确率评估。
- 每个输入样本都有输出记录。原始请求缺失、格式失败、超出预期窗口等问题写入 `issues/`，成功的证据仍可整合。失败不是“无事件”，不能直接当作负例。
- 语义结果先验证 JSON、类别与来源。格式／截断失败最多三次，输出预算依次 768／1536／2048；同一分片的失败请求按轮集中成批重试，仍失败则单列问题。引擎异常由进程恢复机制重试，不伪造正常类别。
- ASR 已有的 73 条独立修复仅在转写来源匹配时作为附加证据读取，原始文件不覆盖。
- 原始时长按音频样本点计算后的预期窗口数与旧索引名义窗口数同时记录，差异留作审计。
- `training_admitted=false` 是派生候选的准入状态。本任务不修改训练代码、生成弱背景或启动训练。

## 守护与恢复

控制器和四台节点主管分别有独立 watchdog，10 秒检查子进程；控制器每分钟检查远端 watchdog，心跳超过 90 秒尝试重新拉起。主管采用文件锁防止重复实例，重启可以接管仍在运行的本任务 worker。

GPU worker 异常退出采用有上限的退避重启；心跳超过 30 分钟，先终止经 PID、命令与进程组确认的本整合 worker，60 秒后仍未退出才强制清理。主管自身心跳超过 20 分钟也会恢复。恢复只针对本整合任务，不终止原始打标或其他程序。

分片通过 `flock` 认领，写入先临时文件再原子替换；缓存使用首次成功写入，重启复用已有有效缓存。CPU 分片异常会留下诊断并退避重试，不将其记为成功。完成标记是文件落盘之后写入。

不能承诺基础设施永不故障；当前措施覆盖进程退出、可恢复卡死和节点主管丢失。若整台控制节点及其 watchdog 同时停止，需要在恢复后执行下方启动命令，已有检查点继续有效。
