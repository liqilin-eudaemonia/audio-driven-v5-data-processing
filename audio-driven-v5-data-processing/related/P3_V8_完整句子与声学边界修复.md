## 为什么修改

V7 在话轮内部按时长和词间隙组合窗口，不能保证句首完整；旧话轮判定也可能将组合附和误判为接管发言。仅保证切点不穿过转写词，仍会从半句话开始。V8 借鉴 listen-response 的句首回溯和声学切口逻辑，但保持纯 listen 任务，不延伸进 listener 正式回应。

## 当前规则

1. 在原始 speaker 全局逐词时间线上先组成完整语句，再与话轮匹配，允许补回旧话轮之前缺失的句首。句末标点、时间戳异常及推断出的分句边界分别记录证据；标点并不等于语义可靠。
2. 通常 2–10 秒。为完整保留一句话及声学余量，允许到 11.95 秒。不为满足上限删掉几个开头/结尾词；过长或无法可靠分割的单位进入 unresolved 记录。
3. 保留 listener 笑声、附和及组合反馈，例如 “Yeah, makes sense.”。明确接管话轮的正式发言不能混入；短句但角色不确定的情况保留复查。异常拉长的 “Yeah” 时间戳不能自动当作已修复。
4. 使用原始双方音轨的 10ms RMS 寻找至少 60ms 的共同安静区间。开头目标提前约 0.2 秒、局部搜索约 0.35 秒；结尾目标余量约 0.3 秒、搜索最多 1.5 秒，并避让下一次发声，目标间隔约 0.08 秒。实际切口受完整词、反馈、源长度和总时长约束。
5. listener 局部没有发声时，不把局部背景声当作语音强度参考；优先使用全轨已标注语音能量，无任何语音时使用噪声底参考。这只用于找切口，不是音质通过判据。
6. 找不到可信安静切口、余量不足、跨入未确认声音时保留边界复查标记。文本补齐不代表声音已经确认完整，不以淡出、静音或降噪遮盖问题。
7. 两路音视频共用连续时间区间，不删中间停顿，不做 8k+1 硬截短。重新计算裁框，原像素最短边至少 448；保留原方向检查、归一化音轨和人工排除记录。
8. 新时间边界重新运行 AST/PANNs 音频质检，不能继承旧片段的通过结论。

## 从原始数据到片段的顺序

| 步骤 | 输入与操作 | 产物 / 处理方式 |
|---|---|---|
| 来源读取 | `/public/0_DATA/2_Avatar/seamless_interaction` 内原始 TAR；读取双方转写、逐词时间戳、VAD、关键点和音视频 | 保留 pair、split、人物及原始路径；当前验证使用已有配对 catalog |
| 方向与角色 | 检查旋转元数据和关键点方向；按双方发言识别当前 speaker/listener | 原视频方向错误拒绝；双方角色随话轮变化，不固定一个人永远是 listener |
| 语句与反馈 | 全局 speaker 词时间线组成语句，识别组合 backchannel、正式接话及不确定短语 | 完整语句候选与语义证据，避免旧话轮边界丢掉句首 |
| 时间组合 | 在纯 listen 约束下组合完整语句，通常 2–10s、完整性例外最多 11.95s | 不按任意词间隙硬切；无法可靠形成片段的单位进入 unresolved |
| 声学边界 | 双方原始 PCM 的 10ms 能量、前后已知发声、反馈区间和源长度共同约束 | 连续统一起止时间；不足的余量、可疑切口保留标记 |
| 画面裁框 | 对最终时间区间重新计算 listener 固定裁框 | 原像素边长 ≥448、拒绝不合适的过宽裁框；预览输出 512×512 |
| 音量处理 | 使用原始独立 WAV 的整轨固定增益归一化，沿用原 -18 LUFS 策略及峰值保护 | 当前样本复用 `normalized_audio[role].path` 与 SHA256 指定的整轨，随后按最终区间裁剪；不新增降噪 |
| 新区间音质筛查 | AST/PANNs、串音/噪声特征、既有人工标注 | 音质结论独立记录，不因切分被认可就自动改成通过 |
| 人工记录与导出 | 应用本次 7 条暂不采用记录；双方共用同一区间导出与校验 | 审计文件保留，训练准入另行判断；连续上下文只供试听 |

原始能量用于定位切口；归一化音轨用于当前试听及音频质检，两者用途不同。整轨归一化并不意味着每个短片段自身都恰好达到 -18 LUFS。

## 本轮自动结果与人工结论

- 24 组覆盖 V7 的六个类别，每类 4 组；包括 3 个已知边界问题及 21 个对照。不是全库随机样本，不能据此估计全量保留率。
- 17 组得到新候选，7 组没有强行生成新的不完整片段。用户确认这 7 组暂不采用；仍保留原因及旧片段/上下文供追溯。
- 2 个新候选超过 10 秒。已知例补回 “So it's because my body's…”、“But while I can, I should to…” 和 “The concept…”；原 ASR 文本不擅自改写。第三例为推断分句，保留相应机器证据，用户已认可整体切分效果。
- 自动结果中，17 个新候选都存在至少一个边界复查标记；综合结论为 15 个待复核、2 个建议排除。人工认可切分逻辑单独记录，不重写这些原始自动结果，也不将 17 个全计入合格训练时长。
- 16 项边界/反馈回归测试通过。最终页面另做浏览器播放、拖动、声道切换、笔记导出、HTTP Range 和移动端宽度验证，结果保存在预览目录的 `browser_validation.json`。

## 并发与执行

本轮质检已使用 GPU 0–7，每卡一个进程、模型 batch size 16；8 份 `logs/qc_*.log` 均有成功结果。17 条新片段每卡仅分到 2–3 条，任务结束后 GPU 空闲是正常现象。其他服务占用显存不能算作本任务 GPU 利用率。

调度已将 CPU 规划并发由 8 提高到最多 32（24 组时实际最多 24），视频导出由 12 组提高到最多 32 个独立媒体任务，新候选与上下文可并行导出。FFmpeg 保持少量线程，避免进程和线程同时膨胀；支持 `LISTEN_V8_CPU_WORKERS` 调整。已完成媒体按边界、裁框、来源及 SHA 校验复用。此调度修改尚无全量吞吐基准，不承诺具体加速倍数。

从项目父目录执行：

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=2 LISTEN_V8_CPU_WORKERS=32 \
  /private/liqi_workspace/project_code/Omni-LTX-stage2/.venv/bin/python \
  audio-driven-v5/scripts/preview_listen_v8.py all
```

`all` 会重新执行音频质检；已有最终结果无需重复执行。也可单独执行 `plan`、`render`、`qc`、`publish`。V7 冻结的科学处理代码未修改。V8 尚未进行全量重处理，当前不能报告新的全库合格小时数。
