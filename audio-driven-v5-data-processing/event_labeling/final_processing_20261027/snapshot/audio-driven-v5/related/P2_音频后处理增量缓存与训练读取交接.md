## 5. 全量仍沿用的处理与读取语义

生成阶段：

```text
原始listener WAV + 官方词/句/VAD + 已有ASR事件
  → 生成配方、新canonical标签
  → read_listener_audio：原采样率、float32，在内存中依次应用两级静音
  → 波形变化：NativeAudioEncoder → 独立音频payload
    波形未变：保存 reuse_base_audio=true
  → 新事件标签栅格化 → cache/events
```

两级静音按已复核顺序执行：官方词/句/VAD并集，两侧0.1秒保护、内部边缘10毫秒淡变；再对多字中文ASR事件区间静音并在外侧作10毫秒淡变。单个汉字保留。缺少metadata或必需字段会报错，不会冒充合法空并集。

`NativeAudioEncoder`使用原生FP32音频VAE；按原几何时长补齐、使用原生音频处理器，保存BF16 latent及原有时序元数据。只加载音频编码器，保持原音频支持范围与尾部token处理。

训练阶段：

```text
training.train
  → training_data.load_training_sample
    → overlay.load_training_sample
      读取原input/layout
      读取原VAE包，保留视频部分
      读取新音频payload，替换音频部分
      读取新events
      返回 (input, layout, None, combined_av, events)
```

返回的 `None` 是未使用的teacher；普通训练无需实时运行音频VAE。训练前的逐条加载检查和每一步实际加载都经过该入口。

注意两个不同概念：

- **静音区间**已经反映在编码前的波形和新音频latent里。
- **`support.audio`**用于有效时长和尾部支持范围，不是“只在有回应时才计算音频损失”的掩码。不要用官方VAD将静音目标区间全部从AV损失中删掉。

事件的弱覆盖与unknown策略保留原契约，没有因音轨被静音就自动补人工确认负标签。不连续支持片段保留原事件关联，不能把片段数直接当成真实发声次数。

## 6. 缓存内容与身份校验

有更新的音频 `payload.pt` 包含：`audio_latents`、`audio_support`、`geometry`、`audio_support_margin_s`、`audio_endpoint_tokens_removed`、`reuse_base_audio=false` 和 `waveform`摘要。没有视频tensor。

波形未变时payload只保存 `reuse_base_audio=true` 与波形摘要；训练直接使用原AV包。`waveform`中有配方摘要、源波形摘要、处理波形摘要和是否变化。

加载时校验配方与样本、原音轨路径/哈希、标签绑定、原VAE身份和载荷哈希。新音频身份还包含处理代码、编码器、组合代码及原运行时文件哈希。来源波形在实际读取/编码时核对文件SHA256；最终审计逐条核对。每个缓存完成标记与payload哈希关联，文件写入采用原子替换。

遇到缺缓存、身份不同或payload损坏会报错，不自动回退到旧未处理音频。源码路径也属于部分缓存身份的一部分，复制到新路径后不能假定旧缓存或旧checkpoint仍能直接复用。

## 7. 全量缓存的重建与复用边界

| 数据/缓存 | 全量处理要求 |
| --- | --- |
| 原listener WAV、speaker音频、视频、参考图 | 保留原文件和哈希；不生成全量处理后WAV |
| input与text特征 | 输入、模型和配置身份兼容时复用 |
| 原VAE中的视频latent | 几何和模型兼容时复用，不重编码或复制 |
| listener音频latent | 波形变化则从处理波形重编码；没变化时明确复用旧音频 |
| 开放整合记录、canonical及events | 对所有样本应用后处理；保留视觉标签和原文，更新音频支持区间及审计 |
| teacher特征 | 不能直接拿旧listener音频teacher监督新音轨；当前适配入口不支持teacher损失 |

**本交接的缓存范围是新音频latent＋事件缓存，并不是宣称所有依赖listener目标音频的特征都仍然有效。** 若下一步训练使用AV＋Feature或E1＋Feature，必须另外实现、验证与处理后音轨一致的teacher重建/读取；如原teacher是视听联合编码，还需检查视觉输出是否也依赖变化的音频，不能仅凭视频未变就宣称该teacher视觉部分可复用。当前音频overlay会拒绝 `feature_loss_enabled=true`。

50h已有结果只可作为回归证据与有条件复用候选：需比对sample_id、原音轨SHA256、规则/代码、配方、原VAE身份、目标几何和标签绑定。全量base根、来源记录、准入属性或配方来源摘要不同都可能导致身份不同；不能硬链接或复制50h的 `complete.json` 绕过检查，也不能直接从722,706中减去30,415后宣布只需处理692,291段。

复用数量应单列：`原音频波形未变复用`、`同版本已完成结果复用`、`本轮新编码`；三者与失败/待处理合计必须覆盖全部ID。修改静音规则或源数据时建立新输出版本，保留旧结果。

`targets.json`中的 `target_audio` 始终是原始来源。后续训练须经过 `training_data.load_training_sample`，使用最终全量新配置，不能直接播放原WAV并认为已经静音，也不能继续使用50h配置期待全量样本自动加入。

5. 统计七类覆盖、保留音频事件数、有/无音频标签样本数、保留声音区间为空样本数、中文移除数及磁盘用量；这些数字不能套用50h结果。
6. 固定100条波形/编码对照及代表性全量样本训练读取通过；训练读取需验证从新缓存取音频，缺失时不回退旧音频。
7. 所有错误已明确处理；只在整批验收通过后生成新全量 `COMPLETE.json`。缓存准备完成不等于启动训练或获得训练准入。

**执行时间尚无全量实测。** 按50h外推，三机24卡独占时该音频/事件后处理链预计约4–6小时，不含入口改造、资源等待和新增teacher重建。它不是已经开始计时的任务，也不是完成时限承诺。
