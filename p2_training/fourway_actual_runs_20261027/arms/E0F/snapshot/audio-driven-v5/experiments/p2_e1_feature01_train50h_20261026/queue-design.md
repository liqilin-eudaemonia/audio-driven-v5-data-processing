# E0＋Feature → E1＋Feature durable queue

User explicitly authorizes automatic succession and recovery, keeping all 24 GPUs in use after the existing job completes. Preserve frozen training code/config and paired initialization; no unrelated process termination. Existing one-shot controller is insufficient after transient SSH/launch failure. Add a standalone, three-host redundant watchdog instead of modifying active trainer/controller sources. All watchdogs share a nonblocking flock leader lease; followers heartbeat and take over if leader dies. State is persisted on shared storage; leader can live on any host, launches job controllers on node0 over SSH when necessary.

Each stage E0/E1 has an allowlisted management path, config and run path. Remote CPU helper validates process argv, birth and hostname before signaling owned torchrun process groups/controllers/supervisors. Completion requires budget1268, not stopped, completed nodes, no live owned workers, and final checkpoint SHA. E0 may be recovered if it unexpectedly fails; it is not interrupted while healthy. E1 starts fresh from the shared pretrained initialization, never from E0 weights. On failure stop owned controller then torchrun and supervisors, wait until all owned processes are gone, archive stale supervisor state, choose latest SHA-verified checkpoint. If no usable checkpoint exists preserve the failed run by renaming it into an attempt archive before fresh deterministic restart; do not delete it. Native resume truncates uncommitted rank/TensorBoard logs. A stale final status ahead of fallback checkpoint is archived before rollback. All source and paired identities remain strict.

Transient errors retry without a total attempt cap, backoff ≤60 seconds. Startup timeout30min, no-progress timeout15min; partial multinode launch grace120sec. STOP at queue/job/run explicitly pauses and is never cleared automatically. Resource admission checks all24 GPUs; unrelated workloads are never killed. Missing controller while all workers healthy does not trigger disruption; queue itself supervises their completion. Monitor metrics progress independently from controller state. Tests exercise false completion, checkpoint fallback, wrong-job safety, retry/restart, and CPU-only SSH helpers. After deployment perform a real leader failover while E0 continues; validate standby takeover and restore three live watchdogs. Do not claim external machine/storage/network failures can be made impossible.
