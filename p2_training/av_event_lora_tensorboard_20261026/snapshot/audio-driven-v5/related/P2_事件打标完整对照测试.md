## 1. 测试范围

配置含 9 个主配置、3 个辅助配置和 4 个输入控制配置。一次 `run` 只运行明确指定的一个配置，模型加载一次；可以在确认空闲的不同 GPU 上分别运行。脚本不自动占用全部 GPU，不停止已有服务。

| 配置名 | 用途 |
|---|---|
| `joy_visual` | Joy 纯视觉 |
| `qwen3_visual` | Qwen3-Omni 纯视觉 |
| `qwen3_audio` | Qwen3-Omni 纯音频 |
| `qwen3_omni_native` | Qwen3-Omni 原生视频音频时序处理 |
| `minicpm_visual` | MiniCPM-o-4.5 纯视觉 |
| `minicpm_audio` | MiniCPM-o-4.5 纯音频 |
| `minicpm_omni_native` | MiniCPM-o-4.5 原生高帧率联合输入 |
| `qwen2_audio` | Qwen2-Audio 纯音频 |
| `qwen3_vl_visual` | Qwen3-VL-8B 纯视觉 |
| `captioner_audio` | 音频描述，辅助结果，不输出事件标签 |
| `qwen3_asr` | listener 转写，辅助结果，不以转写为空判负例 |
| `face_landmarker` | 关键点和面部变换矩阵，辅助结果，不自动转成点头标签 |
| `qwen3_omni_separate` | Qwen 同一请求中图像列表 + 整段音频，用于输入方式消融 |
| `minicpm_omni_separate` | MiniCPM 同一请求中图像列表 + 整段音频 |
| `minicpm_omni_native_1fps` | MiniCPM 每秒一帧 + 对应音频，官方基础联合形式 |
| `minicpm_visual_1fps` | 与上项配套的视觉采样控制 |

主配置沿用 listener 原框裁剪、bicubic 512×512、8 fps 及独立 WAV；不送 speaker 媒体、转写或 context。所有音频分支接收同一完整波形，必要时统一用 `scipy.resample_poly` 重采样到 16 kHz，并记录原始和编码采样数。

两个阶段仍独立调用原媒体；discovery 失败也会继续 audit。默认 4096 输出 token、greedy、一次请求、JSON schema 约束（LM Format Enforcer），不自动语义重检。最终仍按原 schema 做语义校验。可复制配置关闭 `guided_json` 做输出约束消融，必须用新输出目录。

这不是历史 vLLM 1536-token 对照的原样复现。后端、预算、时序表示和解码约束都有明确记录；本轮各主配置应在新测试集上重新比较。

## 2. 原生输入的具体差异

**Qwen**：已裁剪图像直接形成视频张量，独立 WAV 直接传给 processor 的 audio 参数；同时启用 `use_audio_in_video=True`，显式传递 fps，并关闭再次抽帧。没有从 MP4 内提取 AAC，也没有把全部图片当成无时序的图像列表。真实 PTS 与 native 均匀时间网格之间的偏差、尾部差异、processor 张量形状均保存。原视频 PTS 不被改写；native 模型本身的均匀网格近似不能冒充精确 PTS。

**MiniCPM**：按照官方高帧率排列，每秒为“首帧、对应 1 秒音频、其余帧的时间顺序拼图”；调用已安装 `minicpmo.utils.concat_images`，保留独立音频最后不足 1 秒的尾段，不补零、不丢弃。输入帧原先均为 512×512，但拼图不是 512×512，后续编码也与纯视觉不同；拼图尺寸、每秒帧索引和音频采样区间都会记录。主联合配置 `max_slice_nums=9`，单模态为 1，这些是明确的模型原生配置差异，不能仅凭联合结果推断融合收益。另备 1 fps 成对控制及普通拼接控制。

MiniCPM 的 `chat` 会筛选生成参数，新适配器在底层 `generate` 注入 JSON 约束并采集实际生成 token，而不是根据答案重新编码估计截断。禁止 processor 静默截断，输入和输出总长度同时受模型配置的实际 context 上限约束。

JSON 约束通过 LM Format Enforcer 的公共 TokenEnforcer API 接入，兼容本机 Transformers 4.x/5.x 的不同导入布局，不修改共享库文件。CPU 检查会逐 token 验证合法 schema 示例能完成并允许 EOS，而不仅检查模块可导入。

Qwen2-Audio 在不同 Transformers 版本中分别使用 `audios` / `audio`，代码检查实际签名；所有 HF 分支都强制确认相应图像/音频特征已生成，避免只输入文本却误报处理成功。

## 3. 权重与环境

只读检查会核对 safetensors 索引、文件头、张量末端与文件长度，并记录配置/处理器文件 hash、分片大小、mtime 和 header hash。**这不等于完整权重 payload 校验或上游 commit 验证。**

本地已有 Joy、Qwen3-Omni-Instruct、MiniCPM-o-4.5、Qwen2-Audio、Qwen3-VL-8B 和 Qwen3-ASR-1.7B 权重。2026-10-24 用户已将 [Qwen3-Omni-30B-A3B-Captioner](https://huggingface.co/Qwen/Qwen3-Omni-30B-A3B-Captioner) 下载到 `/public/2_CKPT/3_PreTRAINED` 根目录；已核对 16 个权重分片并成功执行 GPU 推理。配置直接引用该目录，不需要再次下载，也不移动同目录其他资产。下载命令留作复现：

```bash
hf download Qwen/Qwen3-Omni-30B-A3B-Captioner \
  --local-dir /public/2_CKPT/3_PreTRAINED
```

Captioner 只接收音频，不添加任务 prompt，不强制输出 audit JSON。ASR 当前不加载 ForcedAligner，因此不输出词时间戳；若未来需要词级定位，再单独接入 aligner。Face Landmarker 仅保存运动证据，点头规则及其阈值需要人工真值调试，尚未作为自动决策方案。

Captioner 必须使用默认 chat template，不传 `enable_thinking=False`，避免插入它未要求的 `<think>` 标记；空描述明确记为失败。MiniCPM 的片尾若仅剩真实 WAV 尾音频，保留为最后一个 audio-only 段，不复制视频帧；中间缺帧仍报错。对应旧版结果保留并由独立新版全样本复跑替代。vLLM 0.19 的 Qwen 原生视听只使用单请求、关闭 chunked prefill 的独立引擎；禁止与普通图像/音频请求混批。该路径先通过冒烟，再执行 `native_vllm_v5` 全 50 条对照；Transformers 的已完成结果和长尾请求另行保留，最终是否完成以汇总中的 `completed_samples` 为准。

各模型使用配置指定的独立 Python；缺失的小型依赖装在项目专用 `experiments/listen_benchmark_deps/py310/`，仅相关 Python 3.10 子进程加入 `sys.path`，不覆盖共享 Torch/Transformers。依赖清单见 [`requirements-listen-benchmark-overlay.txt`](../configs/requirements-listen-benchmark-overlay.txt)。不能把此二进制 overlay 加入 Python 3.13 客户端。

人脸模型来源：`https://storage.googleapis.com/mediapipe-models/face_landmarker/face_landmarker/float16/1/face_landmarker.task`，保存为 `/private/ckpts/mediapipe/face_landmarker.task`；大小 3,758,596 字节，SHA256 `64184e229b263107bc2b804c6625db1341ff2bb731874b0bcc2fe6544e0bc9ff`。

## 5. 后续显式运行

先确认 node8 的空闲显存和 GPU；历史 8 个服务可能仍占用设备，本文不自动停止它们。以下 `run` 会真正加载模型并发出本地推理。

```bash
BENCH_RUN="experiments/listen_benchmark_$(date -u +%Y%m%dT%H%M%SZ)"
# 在确认物理 GPU 2 空闲后使用；不是对当前 GPU 状态的声明。
"$BENCH_PY" scripts/benchmark_listen_labeling.py run \
  --manifest "$BENCH_MANIFEST" --output "$BENCH_RUN" \
  --system minicpm_omni_native --gpu 2 --limit 3

"$BENCH_PY" scripts/benchmark_listen_labeling.py summarize \
  --root "$BENCH_RUN" --output "$BENCH_RUN/structure_summary.json"
```

更换 `--system` 运行其他配置。扩大到 50 条时使用新的输出目录；同一目录、同一配置和样本集合重复执行是续跑。默认跳过已有成功和失败；显式加 `--retry-failed` 才对失败追加新 attempt。首轮结果与后续结果分别统计，旧失败不覆盖。

每个 system 有独立进程锁，`inputs.json` 绑定配置、代码、权重文件身份、依赖版本、样本及媒体 hash；身份变化拒绝复用目录。单 worker 默认总超时 6 小时，`--timeout-seconds` 可改。超时只停止本次 worker，已保存阶段保留。

```text
<run>/<system>/inputs.json
<run>/<system>/summary.json
<run>/<system>/requests/<sample>/<stage>/request.json
<run>/<system>/requests/<sample>/<stage>/raw-0001.json
<run>/<system>/requests/<sample>/<stage>/attempt-0001.json
```

raw 在解析前保存。结构化失败、截断、缺媒体都保留原因；结果始终 `human_verified=false`、`training_admitted=false`。这里没有生产游标、全量源队列或 P2 训练导出功能。

## 6. 人工真值与质量评估

旧 50 条只用于开发与诊断。正式选型应另抽新样本，按人物/session 隔离调试与留出集合，分别统计自然随机样本和困难样本；不要用模型结果筛选唯一的测试集。

```bash
"$BENCH_PY" scripts/benchmark_listen_labeling.py review-template \
  --manifest "$BENCH_MANIFEST" --limit 50 --output experiments/benchmark_blind_review.json
```

模板不含模型答案，也不把空事件当负例。人工填写 reviewer、reviewed_at、evaluation_partition（`tuning` 或 `heldout`）、stratum、完整 reviewed/unknown/events，并仅在复核完成后置 `human_verified=true`。原媒体 hash、crop 和 duration 必须与被评测运行一致。模板没有实现双人仲裁工作流，需实际组织独立标注和争议复核。

```bash
"$BENCH_PY" scripts/benchmark_listen_labeling.py evaluate \
  --system-dir "$BENCH_RUN/minicpm_omni_native" \
  --ground-truth experiments/benchmark_blind_review.json \
  --partition tuning --output "$BENCH_RUN/minicpm_quality.json"

"$BENCH_PY" scripts/benchmark_listen_labeling.py evaluate-pair \
  --visual-system-dir "$BENCH_RUN/joy_visual" \
  --audio-system-dir "$BENCH_RUN/qwen3_audio" \
  --ground-truth experiments/benchmark_blind_review.json \
  --partition tuning --output "$BENCH_RUN/joy_omni_split_quality.json"
```

评估以事件为单位，按类别和 stratum 输出 IoU 0.1/0.3/0.5 下的 precision、recall、F1，以及匹配事件起止绝对误差中位数/P90。使用最大匹配数优先的一对一匹配，重复预测不重复计真阳性。失败或模型 unknown 不从 GT 阳性分母剔除；另报有效监督时长比例。仅人工明确检查且扣除人工 unknown 的范围可评估负例；GT 边界截断事件区域不进入主要定位指标。模型自报边界截断不能用来逃避误报计数。

开放发现的语义质量、发声归属、人工修订成本仍需人工审阅；Captioner/ASR/关键点输出不允许冒充同格式事件标签参与指标排名。未来跨模型复核或头姿规则属于新的组合方案，需要在 tuning 上确定规则后再评 heldout。
