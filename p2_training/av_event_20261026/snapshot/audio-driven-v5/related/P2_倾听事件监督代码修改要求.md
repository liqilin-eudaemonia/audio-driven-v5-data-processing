## 3. 数据与标注 schema

### 3.1 输入和训练目标物理分离

建议生成两份 JSONL/索引：

```json
{
  "schema": "p2-listen-observation-v1",
  "sample_id": "example_0001",
  "experiment_split": "train",
  "official_split": "train",
  "group_id": "connected_group_001",
  "speaker_audio": "media/example_0001/speaker.wav",
  "listener_image": "media/example_0001/reference.png",
  "requested_duration_s": 6.4,
  "geometry": {"fps": 25, "height": 512, "width": 512},
  "media_hashes": {"speaker_audio": "<sha256>", "listener_image": "<sha256>"}
}
```

这里的 ID、时长和哈希是说明用占位值，不是现有样本。目标索引单独保存 `sample_id`、listener 视频/音频、事件文件、真实支持、来源裁剪起止、teacher/VAE 签名。推理 API 只接受 observation，不接受带 targets 的合并行；group/split/身份字段仅用于路由审计，不拼进模型文本。

准入清单还需保存：原来源 pair/session/双方身份、QC4 revision/pool、人工反馈命中、内容与媒体验收、实时时长/帧率、裁框、渲染对齐时长、padding、split 连通组签名、admission 状态。`training_admitted` 只能由该实验的准入步骤生成，不能修改生产 pool 以绕过规则。

```json
{
  "schema": "listen-events-v1",
  "sample_id": "example_0001",
  "time_origin": "clip_start_seconds",
```

## 4. 时间布局、缓存和特征提取

### 4.1 布局合同

实现一个纯输入函数：

```python
make_output_layout(observation, processor_geometry, config) -> OutputLayout
# 仅由 requested_duration / fps / size / teacher sampling 计算
# 包含 Nv/Na、坐标、每 token 所属时间组、支持区间、结构性 padding mask
```

区分三种 mask：

1. `layout_valid`：外部布局和 batch padding，决定 U/attention 的有效 token；不由目标事件或 GT 是否有声决定。
2. `target_valid`：教师/VAE 有效真实支持，只用于目标损失。
3. `event_known`：该类别已审阅且非 unknown 的时间 bin，只用于事件 loss/指标。

坐标使用真实秒数；视频同时间不同空间位置拥有相同时间组 ID。`vision_fps=8` 与 temporal patch=2 的中心/支持使用实际 processor 规则，不能简单把数组索引除以 25。音频 8 Hz 聚合必须基于原生教师 token 的实际时间支持；不得对含大量 padding 的序列整体 adaptive-pool 后假定时间均匀。

首帧生成由 `reference_latents` 或等价 source-only 实现构建；尺寸、时长不从 GT latent shape 反推。尾部 VAE mask 若当前 runtime 无法正确应用，必须实现 masked reduction 并验证后才能宣布支持该长度；不能隐藏截断或把补帧当真值。首轮可先只用已验证对齐几何，记录因此排除的候选及事件分布。

### 4.2 分离缓存

拟定结构：

```text
experiments/p2_listen_event_v1/
  protocol.json                    # 展开配置、配对、源码/模型/提示词身份
  manifests/{observations,targets,admission,splits}.jsonl
  labels/{raw,canonical,audit}/
  cache/input/<sample_id>/{hidden.pt,layout.pt,complete.json}
  cache/teacher/<sample_id>/{features.pt,complete.json}
  cache/vae/<sample_id>/{targets.pt,complete.json}
  cache/text/{fixed.pt,negative.pt,complete.json}
  cache/events/<sample_id>/{labels.pt,complete.json}
  runs/<train_seed>/{E0,E1}/
  generated/<train_seed>/<arm>/<step>/<split>/<sample_id>/<sample_seed>/
  evaluation/{protocol.json,per_sample.jsonl,summary.json,report.md}
```

每个阶段独立原子落盘，complete marker 只在文件校验完成后写入。允许中断后恢复，不覆盖身份不匹配的旧缓存；禁止“忽略哈希继续训练”开关。

H 缓存签名只绑定输入音频/首帧/固定文本、Omni 权重/processor/选层/代码；teacher/VAE 签名绑定相应目标和布局；事件缓存签名绑定标签/覆盖/mapping/网格。修改事件标签只重建事件缓存，不应强迫重提 H。修改 speaker 音频必须使 H 失效。

推理服务不需要打开 GT 文件验证其哈希。输入缓存合格即可 source-only 推理；训练时另外核验目标缓存。禁止在 `generation` 中调用 `read_sample` 这样的全目标加载器。

## 5. 模型、梯度与损失实现

### 5.1 接口草案

```python
class ListeningExtractor(nn.Module):
    def forward(self, condition_inputs, time_groups, targets=None,
                event_targets=None, event_mode="probe_only", generators=None):
        u = self.extractor.connector(condition_inputs)
        # LTX 和 feature decoder 消费同一 u，无重新计算或替代支路
        pooled = pool_by_time(u, time_groups)
        event_input = detach_tree(pooled) if event_mode == "probe_only" else pooled
        logits = self.event_heads(event_input)
        # 返回 U、logits、loss sums/counts；可训练模块调用在 DDP forward 中
        return ...
```

实际函数签名由实现者决定，但不能把 loss 依赖埋进全局配置或隐式 stage。`event_mode` 只允许 `probe_only/joint_event`；标签缺失不能改变 U 的长度或条件值。

事件头读取最终 `u.video/u.audio`；训练反向不 detach E1 的 U。H 可以 detach，因为 Omni 冻结。禁止把 U 先保存/转 CPU 再读回当作训练条件；缓存 U 只允许评测/导出，不作为训练融合器的正常路径。

### 5.2 稳定性与公平性细节

- BCE 在 float32 下按已知 bin 求 numerator/count；class pos_weight 由 train 样本预计算并冻结，两个 arm 共用。
- E0 的事件头参数需要正常优化，但其梯度不能进入 U。E0 的公共参数更新应与关闭 probe 的 baseline 在固定噪声下数值一致。
- 为事件头和公共模块分别执行 gradient clipping，避免 probe 的梯度范数影响 E0 公共参数。事件头不要 dropout，避免无必要的 RNG 分歧。
- base loss、feature noise、AV noise、数据顺序、事件头初始化使用独立 RNG 流。两个 arm 从同一公共/头初始化文件加载；不能依赖“同一个 seed 大概一样”。
- DDP/梯度累积按有效 global batch 归一化。每类的全局有效 bin 分母须涵盖本次 optimizer step 的所有 micro-batches/ranks；可预取该步标签统计。DDP 默认平均梯度时补偿 world-size，不能简单平均各 rank 的局部比值。
- 同理保留原特征/AV 损失的明确归一化规则并记录，不能因为新增 event 改变它们的权重。不同长度样本的 base loss 首轮按样本均值，event 每类按有效 bin 均值；两组严格一致。
- 某类 global count=0 时返回与 graph 兼容的零项；使 DDP 知道参数使用情况，不死锁、不 NaN。日志报告跳过类别和监督覆盖。
- 冻结 DiT 可能需要 train 模式启用 checkpointing，但参数仍 `requires_grad=False`；不得把整个 AV forward 放进 `torch.no_grad()`。
- 保留零初始化末层。第 1 步上游没有梯度可属预期；第 3–5 步分别检查 `L_AV→U→各层融合`、`L_feature→U`、`L_event→U`。E0 最后一条必须为零，E1 在有标签时必须非零。
- 两个事件头均保存，但标准推理不把 logits 填进 Gemma 或额外控制 LTX；这会引入不同实验。

### 5.3 Checkpoint 与恢复

保存：Extractor/辅助 decoder/事件头、优化器、各 RNG 流及各 rank RNG、global step、数据 epoch/ordinal、有效 batch、arm/seed/pair id、全部 loss 配置、分类权重、schema/split/媒体/标签/源码/基座签名、采样协议。

严格恢复必须拒绝 changed arm、标签版本、公共初始化、world-size/累积等未支持变更。阶段迁移与严格 resume 是两种操作；新实验不得伪装原 run 续训。S0/过拟合模型带明确标记，不自动进入正式 pair。

## 6. 推理与评价接口

`generate` 只接受锁定 checkpoint、observation manifest、固定 prompt cache、模型配置、seed；可实时提 H 或读 input-only H 缓存。支持 `normal/text_only/remove_u/audio_swap`，oracle 若实现必须独立命名并禁止进入主结果聚合。

CFG 契约需在 S0 固定并写入报告：首轮默认将 U 保留在正、负分支，只对 Gemma 文本执行既定 CFG；若 v5 现有 guided sampler 的实际语义不同，先核实并明确实现该默认，不能把仅正分支 U 的结果混入同组。`remove_u` 同时移除两分支的 U。保持首帧条件、噪声 seeds、调度、steps、音视频 CFG 与解码方式一致。

每个输出写 observation/checkpoint/protocol 哈希、训练 seed、生成 seed、实际帧数/音频时长/末尾补齐、模型耗时、失败状态。生成裁剪到请求的真实支持；视频显示可有一帧量化误差，音频样本数与时间轴精确记录。无法生成也写失败记录，不能静默跳过。

评测分三份：`probe_metrics`、`generated_event_metrics`、`quality_metrics`。事件匹配一对一、unknown/边界截断过滤、tIoU/onset/误触发、per-class 和 macro、按组 bootstrap 全部有确定实现。生成 detector 的版本、人工修订与原始预测一并存档。

主 F1 严格按配套计划第 8.2 节实现：clip/生成 seed 分别匹配 → 同 clip 的 TP/FP/FN 在 seeds 上平均 → 跨 clip 累加 → per-class F1 → 类别 macro。生成失败视为空预测并计参考事件 FN，单列失败率；不是丢弃失败后计算，也不是平均逐 clip F1。训练 seeds 分开报告；bootstrap 按连通组重采样、保留所有组内配对结果后重算公式。unknown/censored 完整事件排除及支持区间扣除须与计划一致；跨边界预测落入已知负区间的时长仍计误触发。评测工具失败优先人工补齐，未补齐时报告未判定覆盖，不伪造事件标签。

盲评素材需同时提供 speaker 语音上下文、listener 生成视频/独立音轨和可选参考；隐藏 E0/E1 名称，随机左右顺序。汇总报告必须指出人工覆盖、自动检测覆盖、失败和未判定；不能仅导出漂亮案例。

## 9. 必须具备的验证

### 9.1 CPU/小张量测试

1. **输入隔离：** 给推理 loader 设置 target/label 文件读取陷阱，正常推理布局与条件准备仍成功；修改 GT 文本/目标/标签不改变 H/U，修改 speaker 输入会使 H cache 失效。
2. **时间轴：** 非零源起点、2 秒/8 秒/11.95 秒、首尾事件、短于 bin 的事件、同时点头发声、unknown、padding、不同 FPS/采样率；不丢尾部、不误把 padding 当负例。长片段即便 pilot 排除，布局单测仍覆盖。
3. **布局：** 相同输入几何下，沉默和有声目标得到相同 query 数与 layout mask；目标缺失只改 loss mask。
4. **梯度路径：** E0 event 到 U/Connector 梯度为零，head 非零；E1 对有标签类的对应 U/Connector 非零；两组 AV/feature 路径均非零。零初始化在多步后再检查上游。
5. **公平性：** E0 probe 开/关时公共模块更新一致，含分别裁剪的验证；增加日志/head 不改变 AV 噪声或样本顺序。
6. **稀疏标签：** 全 unknown、单类空、某 rank 无标签、全负例时 loss 有限且分母正确；变长/累积的全局梯度与拼接 batch 参考一致。
7. **缓存契约：** 提示、层号、source audio、时间布局、标签修改分别只允许命中正确的缓存；不兼容版本明确拒绝，原子写入失败可恢复。
8. **评测：** 一对一匹配、重复预测惩罚、无正例、unknown 遮挡、时间偏移、padding、生成失败、组级 seed 汇总与 bootstrap 不重复计算样本。

### 9.2 真实模型 S0

完成至少一次正常声音/沉默视频生成；检查 listener 音轨与 speaker 角色没有混用，输出支持与标注坐标吻合。验证 native CFG 的 U 分支语义，不仅验证 shape。记录显存/耗时/输入 token/U token 数，确认提高到 8 FPS/8 Hz 后可承受。

冻结参数逐项检查 requires_grad/grad/更新签名；检查 AV 梯度能穿过冻结 DiT。将 target/labels 目录从推理环境隐藏后重新生成。严格 checkpoint 恢复后下一步 loss/参数在约定数值误差内一致，说明差异来自 bf16 非确定性还是逻辑错误。

单卡通过后只扩展必要的多卡验证；不为了文档检查启动 GPU 或全量训练。实现时运行与变更有关的测试，不机械重跑所有历史数据工程任务。
